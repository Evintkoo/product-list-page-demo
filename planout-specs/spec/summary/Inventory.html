1.  Data
1.1Overview

The Inventory feature for the Lumi ERP project provides a reliable way to track stock levels and movements between warehouses and stores. It ensures that whenever stock is moved or adjusted, the system automatically updates the current inventory counts and maintains a detailed audit trail of these changes. This system is designed to be "atomic," meaning that all related updates—such as changing a stock level and recording the history—happen together as a single, inseparable action. If any part of the process fails, the entire operation is cancelled to prevent data errors.

1.2Step-by-Step Flow

The system handles inventory changes through two primary processes:

1.Stock Order Movements:

* When sending stock: The system decreases the quantity in the source warehouse and creates a history record to document the departure.

* When receiving stock: The system increases the quantity in the destination store and creates a history record to document the arrival.

* Consistency: These updates are bundled with the workflow status change (e.g., moving from "sent" to "received") to ensure the inventory always matches the order status.

2.Stock Adjustments (Stock Opname):

* When a physical count is performed, the system calculates the difference (variance) between the counted quantity and the system's recorded quantity.

* If a difference exists, the system updates the store's stock level to match the physical count.

* A history record is created to explain the adjustment, ensuring there is a clear audit trail for why the stock level changed.

1.3Key Concepts
–Atomic Transaction: A safety feature that ensures a group of database changes either all succeed together or all fail together, preventing partial or corrupted data.
–Stock History: A permanent, append-only log that tracks every movement or adjustment of inventory, providing a clear audit trail for accountability.
–Variance: The difference between the expected stock (what the system thinks is there) and the actual stock (what was physically counted).
–Workflow State: The current status of an order or adjustment (e.g., "draft," "sent," "received," or "completed"), which triggers the corresponding inventory updates.
1.4Business Value
–Data Accuracy: By automating inventory updates, the system eliminates manual calculation errors and ensures that stock levels are always up-to-date.
–Auditability: Every change to inventory is logged with a reference code, making it easy to trace stock movements and investigate discrepancies.
–Operational Reliability: The use of atomic transactions prevents "ghost" inventory or mismatched records, ensuring that the business can trust the data when making purchasing or sales decisions.
–Process Integrity: By linking inventory movements directly to workflow states, the system ensures that stock is only deducted or added when the business process (like shipping or receiving) is officially confirmed.
