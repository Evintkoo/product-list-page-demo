1.  Logic
1.1Overview

The Payment Type Mappings feature provides a structured way for the Lumi ERP system to retrieve and display how different payment methods are configured across various store locations. This functionality allows users to query specific payment settings for a company and receive a clean, organized list of active mappings, including the human-readable names of stores and payment types.

1.2Step-by-Step Flow
1.Request Submission: The system receives a request containing filters such as the company ID, specific store ID, payment type ID, and status (active/inactive). It also accepts pagination settings (limit and offset) to manage the amount of data returned.
2.Data Retrieval: The system queries the database to find all relevant payment mappings. It automatically links the internal mapping records with the actual names of the stores and payment types to ensure the output is easy to read.
3.Filtering: The system applies the requested filters to narrow down the results, ensuring only the relevant mappings are returned.
4.Metadata Calculation: The system calculates the total number of available records for the given company to assist with navigation and pagination.
5.Response Delivery: The system returns the final list of mappings along with metadata, which includes the total count of records and the current pagination settings.
1.3Key Concepts
–Payment Type Mapping: A configuration that links a specific payment method to a store location within the ERP.
–Filtering: The ability to narrow down results by specific criteria, such as viewing only active mappings or mappings for a single store.
–Pagination: A method of breaking large lists of data into smaller, manageable chunks using "limit" (how many items to show) and "offset" (where to start in the list).
–Metadata: Supplemental information provided with the data, such as the total number of records found, which helps the user interface display information correctly.
1.4Business Value

This feature ensures that administrators and system users have clear visibility into how payments are configured across their organization. By providing a standardized way to fetch this data, the system enables:

–Operational Transparency: Easily verify which payment methods are active at specific store locations.
–Efficient Data Management: The use of pagination and filtering allows users to quickly find specific configurations without being overwhelmed by large datasets.
–Consistency: By resolving internal IDs into human-readable names (e.g., showing "Downtown Store" instead of a code), the system ensures that reports and management screens are intuitive and easy to interpret.
2.  Data
2.1Overview

The Payment Type Mappings feature allows the Lumi ERP system to organize and track how different payment methods (such as credit cards, cash, or digital wallets) are assigned to specific store locations. This feature provides a structured way to view and filter these assignments, ensuring that the system correctly identifies which payment types are active and available at each store within a company.

2.2Step-by-Step Flow
1.Request Initiation: The system receives a request to view payment mappings, which includes the specific company ID and optional filters (such as a specific store, a specific payment type, or the active status of the mapping).
2.Data Retrieval: The system searches the database for all records that match the provided company and filter criteria.
3.Information Consolidation: As the system retrieves the records, it automatically links the internal ID codes to their human-readable names (e.g., linking a store ID to the actual store name and a payment type ID to the payment type name).
4.Result Delivery: The system returns a clean, organized list of mappings, sorted by the date they were created, ready to be displayed in the user interface.
2.3Key Concepts
–Payment Type Mapping: A record that links a specific payment method to a specific store location.
–Filtering: The ability to narrow down the list of mappings by store, payment type, or whether the mapping is currently active.
–Display Names: The human-readable labels (like "Downtown Store" or "Visa") that replace complex internal ID codes to make the data easy for users to understand.
–Pagination: A method of returning results in smaller, manageable chunks (using limits and offsets) to ensure the system remains fast and responsive.
2.4Business Value

This feature provides transparency and control over financial configurations across a business. By allowing users to easily view and filter payment mappings, the business can:

–Improve Accuracy: Quickly verify that the correct payment methods are enabled for the right store locations.
–Enhance Reporting: Ensure that financial data is correctly categorized by store and payment type.
–Streamline Operations: Reduce manual effort in managing store-level configurations, allowing administrators to quickly identify and update active payment methods as business needs change.
