1.  Logic
1.1Overview

The Customer Search feature provides a flexible way to retrieve a list of customers from the Lumi ERP system. By using specific search criteria, you can quickly narrow down your customer database to find exactly who you are looking for. The system is designed to handle large amounts of data efficiently by breaking results into manageable pages and allowing you to sort the information in a way that best suits your workflow.

1.2Step-by-Step Flow
1.Authentication Check: The system first verifies that you have the necessary permissions to access customer data. If you are not logged in or your session is invalid, the request will be denied.
2.Parameter Validation: The system checks your search request to ensure it includes the required "type" category. If the request is missing this or contains invalid information, the system will notify you of the error.
3.Applying Filters: The system applies your specific search criteria (such as name, status, phone, or email) to narrow down the list of customers.
4.Sorting and Organization: The system organizes the results based on your preferred field (e.g., by name or date created) and order (ascending or descending). If no preference is provided, it defaults to sorting by the date the customer was added.
5.Pagination: To keep the data easy to read, the system divides the results into pages. You can specify which page you want to view and how many customers should appear on each page.
6.Data Retrieval: The system gathers the matching records and presents them to you. If no customers match your search criteria, the system will inform you that no results were found.
1.3Key Concepts
–Filters: Specific criteria used to narrow down search results, such as searching for a customer by their email address or account status.
–Pagination: A method of splitting a large list of results into smaller, manageable chunks (pages) to improve performance and readability.
–Sorting: The ability to arrange the final list of customers in a specific order, such as alphabetically by name or chronologically by creation date.
–Mandatory Field: A required piece of information (in this case, "type") that must be included in your search request for the system to process it.
1.4Business Value

This feature significantly improves operational efficiency by allowing staff to locate customer records instantly without manually scrolling through long lists. By providing robust filtering and sorting capabilities, the system ensures that users can access the exact data they need for reporting, communication, or account management. Furthermore, the pagination logic ensures that the application remains fast and responsive, even as the customer database grows over time.

2.  Data
2.1Overview

The Customer Search feature provides a flexible way to retrieve lists of customers from the system. It allows users to narrow down results using specific criteria (such as name, status, phone, or email), organize the data in a preferred order, and view the results in manageable chunks (pagination). This ensures that even with a large database, users can quickly find the specific information they need without overwhelming the system.

2.2Step-by-Step Flow
1.Request Validation: The system receives the search request and first checks that a "customer type" is provided, as this is a mandatory requirement for the search.
2.Base Filtering: The system identifies the core group of customers based on the required "type."
3.Applying Search Criteria: The system applies any additional filters provided (e.g., searching for a specific name or email). It only processes filters for approved fields to ensure data security and accuracy.
4.Counting Results: Before returning the data, the system calculates the total number of customers that match the search criteria. This helps the user understand the full scope of their search results.
5.Sorting: The system organizes the list based on the user's preferred field (e.g., by name or creation date) and direction (ascending or descending).
6.Pagination: The system slices the list into smaller pages based on the requested page number and the number of items per page, then returns the final list along with the total count metadata.
2.3Key Concepts
–Filters: Specific criteria used to narrow down the list, such as searching by name, status, phone number, or email address.
–Pagination: A method of breaking a large list of results into smaller, manageable pages (e.g., 20 items per page) to improve performance and readability.
–Sorting: The ability to arrange the results in a specific order, such as alphabetical order or by the date the customer was added.
–Metadata: Additional information returned with the search results, such as the total number of matching records, which helps the user navigate through the pages.
2.4Business Value
–Improved Efficiency: Users can quickly locate specific customer records without manually scanning through long lists.
–System Performance: By using pagination, the application only loads a small portion of data at a time, keeping the interface fast and responsive.
–Data Accuracy: The system enforces strict rules on which fields can be searched, preventing errors and ensuring that search queries are always handled securely and consistently.
–Better User Experience: The combination of sorting and filtering gives users full control over how they view and interact with customer data.
