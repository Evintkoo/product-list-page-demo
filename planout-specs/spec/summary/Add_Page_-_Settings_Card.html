1.1Overview

The Service Settings Card is a configuration component within the "Add Service Product" page. It allows users to define key operational behaviors for a new service, such as its availability status, pricing flexibility, and duration expectations. This ensures that each service is correctly categorized and behaves as expected when used in future transactions.

1.2Step-by-Step Flow
1.Set Active Status: By default, the service is marked as "Active." You can toggle this off if you wish to create the service in the system without making it immediately available for use.
2.Configure Pricing: You can enable the "Open Price" option. When active, this allows staff to manually set or change the price of the service at the moment of a transaction, rather than relying on a fixed price.
3.Define Duration: You can enter an "Estimated Time" (in minutes) to indicate how long the service typically takes. The system will validate this input to ensure only positive numbers are entered.
4.Configure Duration Flexibility: You can enable "Open Estimated Time." Similar to open pricing, this allows the duration of the service to be adjusted freely during a transaction, providing flexibility for services that vary in length.
1.3Key Concepts
–Active Status: A toggle that determines if a service is currently available for selection in the system.
–Open Price: A setting that permits the final price of a service to be determined at the time of sale rather than being pre-set.
–Estimated Time: A numeric field used to set the standard duration of a service, helping with scheduling and planning.
–Open Estimated Time: A setting that allows the duration of a service to be modified at the time of sale to accommodate variable work requirements.
1.4Business Value

This feature provides the necessary flexibility to manage diverse service offerings within the ERP. By allowing users to define whether prices and durations are fixed or "open," the system can support both standardized services (like a flat-rate haircut) and variable services (like custom consulting or repair work). This reduces manual workarounds and ensures that service data remains accurate and consistent across the platform.
