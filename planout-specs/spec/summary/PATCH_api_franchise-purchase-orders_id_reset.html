1.  Logic
1.1Overview

This feature allows authorized users to "reset" a franchise purchase order that has been previously cancelled. By triggering this action, the system moves the order back into a "draft" status, allowing it to be edited or processed again without needing to create an entirely new order from scratch.

1.2Step-by-Step Flow
1.Validation: The system checks that the provided order identifier is formatted correctly.
2.Authorization: The system verifies that the person making the request has the necessary administrative or managerial permissions.
3.Verification: The system searches for the specific purchase order to ensure it exists and belongs to the user's company.
4.Status Check: The system confirms the order is currently in a "cancelled" state. If the order is in any other state, the reset request is rejected.
5.Update: The system updates the order status to "draft" and records the current time as the last update.
6.Confirmation: The system returns the updated order details to confirm the process was successful.
1.3Key Concepts
–Franchise Purchase Order: A formal request for goods or services within the franchise network.
–Workflow State: The current stage of an order in its lifecycle (e.g., "cancelled" or "draft").
–Reset: A corrective action that reverts a cancelled order to a draft state so it can be modified or resubmitted.
–Authorization: A security check to ensure only designated staff (Admins or Managers) can modify order statuses.
1.4Business Value

This feature improves operational efficiency by reducing manual rework. Instead of forcing staff to discard a cancelled order and manually re-enter all the data for a new one, they can simply reset the existing order. This saves time, reduces the risk of data entry errors, and maintains a clean audit trail for franchise procurement activities.

2.  Data
2.1Overview

This feature allows authorized users to "reopen" a franchise purchase order that has been previously cancelled. By resetting the order status back to "draft," users can make necessary adjustments or corrections to an order that was previously discarded, rather than having to create a new order from scratch.

2.2Step-by-Step Flow
1.Verification: The system confirms the user has the appropriate permissions (Admin or Manager) and that the requested purchase order exists within their company.
2.Status Check: The system checks the current status of the purchase order.
3.Validation: If the order is currently marked as "cancelled," the system proceeds to update the status. If the order is in any other state, the request is rejected to prevent accidental changes to active or completed orders.
4.Update: The system updates the order status to "draft" and records the current time as the last update.
5.Confirmation: The system returns the updated order details to the user.
2.3Key Concepts
–Draft State: A status indicating that an order is currently being prepared or edited and is not yet finalized or submitted.
–Cancelled State: A terminal status for an order that has been voided; this is the only state from which an order can be "reset."
–Atomic Update: A safety mechanism that ensures the status change only happens if the order is currently in the expected "cancelled" state, preventing conflicts if the order status changed while the request was being processed.
–Company Context: A security boundary that ensures users can only modify purchase orders that belong to their specific organization.
2.4Business Value

This feature improves operational efficiency by providing a "recovery" path for cancelled orders. It reduces administrative overhead by eliminating the need to manually recreate purchase orders that were cancelled in error or require minor modifications, ensuring that data remains accurate and workflows remain flexible.
