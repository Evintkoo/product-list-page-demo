1.  Logic
1.1Overview

The login feature provides a secure way for users to access the Lumi ERP system. It verifies user credentials and establishes a temporary session. To protect the system and user data, the feature includes built-in safeguards against unauthorized access, automated attacks, and malicious attempts to guess user information.

1.2Step-by-Step Flow
1.Security Screening: The system first checks if the request is coming from a trusted source. If the request originates from an unauthorized external location, it is blocked immediately.
2.Traffic Control: The system checks if there have been too many login attempts from the user's current location. If the limit is exceeded, the request is paused to prevent automated brute-force attacks.
3.Data Validation: The system ensures the login information provided is formatted correctly (e.g., a valid email structure). If the information is incomplete or malformed, the request is rejected.
4.Credential Verification: The system checks the provided email and password against our secure records. It also confirms that the account is active and not locked.
5.Session Creation: If the credentials are correct, the system creates a secure session that remains valid for 24 hours.
6.Response: Upon success, the system provides a session ID and an expiration timestamp. If any part of the authentication fails, the system returns a generic error message to protect account privacy.
1.3Key Concepts
–CSRF (Cross-Site Request Forgery) Protection: A security measure that ensures login requests are only accepted from our own application, preventing malicious websites from performing actions on behalf of a user.
–Rate Limiting: A defensive mechanism that limits the number of login attempts allowed from a single location within a specific timeframe to stop automated "guessing" attacks.
–User Enumeration Prevention: A security practice where the system provides the same generic error message regardless of whether the email was wrong or the password was incorrect. This prevents attackers from discovering which email addresses are registered in our system.
–Constant-Time Verification: A technique used during password checking to ensure that the time taken to process a login attempt does not reveal information about whether the password was partially correct.
1.4Business Value

This feature balances user convenience with high-level security. By implementing robust protections like rate limiting and generic error messaging, we significantly reduce the risk of account takeovers and data breaches. This ensures that the Lumi ERP remains a trusted environment for our users while maintaining compliance with modern security standards.

2.  Data
2.1Overview

The login feature provides a secure way for users to access the Lumi ERP system. It validates user credentials and establishes a temporary session upon a successful match. The system is designed with high security standards to protect against common cyber threats, ensuring that login attempts remain private and resistant to unauthorized access.

2.2Step-by-Step Flow
1.Request Submission: The user submits their email and password to the login endpoint.
2.Input Normalization: The system automatically cleans the email address (removing extra spaces and converting it to lowercase) to ensure consistency.
3.Credential Verification: The system checks the provided credentials against the database.
4.Security Validation: The system verifies the password and checks if the account is active and not locked.
5.Session Creation: If all checks pass, the system generates a unique session ID that remains valid for 24 hours.
6.Response: The system returns the user's details and the new session ID. If any part of the process fails (e.g., wrong password, inactive account, or unknown email), the system returns a generic error message to prevent attackers from guessing valid account information.
2.3Key Concepts
–Generic Error Handling: Regardless of why a login fails, the system provides the same "Invalid email or password" message. This prevents malicious actors from determining if an email address exists in our system.
–Constant-Time Verification: A security technique that ensures the system takes the same amount of time to process a login attempt, whether the password is correct or incorrect, preventing timing-based attacks.
–CSRF Protection: A security measure that ensures login requests are coming from our legitimate application, preventing unauthorized third-party sites from hijacking user sessions.
–Session Expiry: For security, every login creates a session that automatically expires after 24 hours, requiring the user to re-authenticate.
2.4Business Value
–Enhanced Security: By using generic error messages and constant-time verification, we significantly reduce the risk of "user enumeration" attacks, where hackers try to identify valid user accounts.
–Data Integrity: Normalizing email inputs ensures that users can log in regardless of how they type their email (e.g., capitalization), reducing support tickets related to login issues.
–Compliance and Safety: The inclusion of CSRF checks and account status verification (checking for locked or inactive accounts) ensures that only authorized, active users can access the ERP, protecting sensitive business data.
