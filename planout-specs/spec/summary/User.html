1.  Data
1.1Overview

The User Management feature provides a secure foundation for handling staff access within the Lumi ERP. It is designed to manage user identities, control active login sessions, track security-related events, and protect the system against unauthorized access attempts. By separating user data from session and security logs, the system ensures that account information remains protected while providing a clear trail of activity for administrative oversight.

1.2Step-by-Step Flow
1.Registration & Identity: When a user is created, their profile is stored with a secure password hash and a specific role (e.g., Admin, Staff). The system ensures email addresses are unique and case-insensitive.
2.Login Attempt: Every time someone tries to sign in, the system records the attempt in a dedicated log. This allows the system to detect suspicious patterns, such as repeated failed logins from a single IP address or against a specific account.
3.Authentication & Session: Upon a successful login, the system creates a secure session. This session acts as a "digital key" that allows the user to stay logged in for a set period without re-entering their credentials.
4.Security Monitoring: Throughout the user's lifecycle, the system records significant actions (like password changes or role updates) in an audit log. This creates an immutable history of who did what and when, which is essential for security compliance.
5.Access Control: If a user is deactivated or a security event occurs, the system can immediately revoke all active sessions, ensuring that the user can no longer access the ERP.
1.3Key Concepts
–User Profile: The core record containing identity information, account status (active/inactive), and security flags (such as a requirement to change a password upon next login).
–Session Management: A secure mechanism that tracks active users. It includes "sliding expiration," meaning sessions stay active while the user is working but expire automatically after a period of inactivity.
–Audit Trail: A permanent, read-only record of security-sensitive actions. It provides accountability by linking actions to specific users and recording the context of those changes.
–Login Throttling: A security measure that monitors login attempts to prevent "brute force" attacks, where an unauthorized party tries to guess a password by repeatedly attempting to sign in.
–Role-Based Access: The system assigns roles to users, which determines their level of authority and what they can do within the ERP.
1.4Business Value
–Enhanced Security: By tracking login attempts and maintaining an audit log, the system proactively defends against unauthorized access and provides clear visibility into system activity.
–Operational Control: Administrators can easily manage staff access, including the ability to lock accounts or force password resets, ensuring that only authorized personnel have access to sensitive business data.
–Compliance & Accountability: The audit trail ensures that all critical changes are documented, which is vital for internal oversight and meeting business compliance standards.
–Reliability: The session management system ensures that users have a smooth, uninterrupted experience while maintaining strict security standards for how long a user remains logged in.
