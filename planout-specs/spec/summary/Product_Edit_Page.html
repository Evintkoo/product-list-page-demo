1.  Frontend
1.1Overview

The Product Edit Page allows users to update the details of an existing product within the Lumi ERP system. When a user navigates to this page, the system automatically retrieves the current product information and populates a comprehensive form. Users can modify various attributes—such as pricing, tax settings, stock tracking, and categorization—and save their changes directly. The page also includes convenient "quick-add" features for brands and tags, allowing users to create new entries without leaving the edit screen.

1.2Step-by-Step Flow
1.Page Load: The system fetches the existing product data using the product's unique identifier and pre-fills all form fields with the current information.
2.Data Modification: The user updates the desired fields. This includes:

* Core Details: SKU, Name, Description, Type, Brand, and Tags.

* Pricing & Tax: Supply prices, wholesale/retail pricing, tax settings, and Maximum Retail Price (MRP).

* Operational Settings: Toggles for active status, internal product status, open pricing, ordering permissions, product freezing, and stock tracking.

* Logistics & Metadata: Warranty periods, return limits, physical dimensions (weight/volume), validity dates, and custom attributes.

3.Inline Creation: If a required brand or tag is missing, the user can click the "New Brand" or "New Tag" buttons to open a quick-add overlay, create the new item, and immediately select it in the form.
4.Saving Changes: Once the user is satisfied with the updates, they click the "Save" button. The system sends the updated information to the server to finalize the changes.
5.Navigation: After saving, the system automatically redirects the user back to the product list or details page. If the user decides not to proceed, they can click "Cancel" to discard all changes and return to the previous screen.
1.3Key Concepts
–SKU (Stock Keeping Unit): A unique identifier used to track individual products in the inventory.
–MRP (Maximum Retail Price): The highest price at which a product can be sold to consumers.
–Inline Quick-Add: A feature that allows users to create new supporting data (like a new brand or tag) in a pop-up window without navigating away from the current page.
–Bundle Settings: Configuration options for grouping products; note that these are locked if a product has already been sold to ensure data integrity.
–Tax/UOM (Unit of Measure): Settings that define how a product is taxed and how its quantity is measured (e.g., kilograms or liters).
1.4Business Value

This feature provides a centralized, efficient way to maintain accurate product data. By allowing users to edit all relevant product attributes in one place—including pricing, tax, and operational flags—the system reduces administrative overhead and minimizes the risk of errors. The inclusion of inline "quick-add" buttons for brands and tags further streamlines the workflow, ensuring that users can manage their product catalog without unnecessary interruptions or navigation steps.

2.  Logic
2.1Overview

The Product Edit page allows authorized users to modify existing product information within the Lumi ERP system. When a user navigates to the edit page for a specific product, the system automatically retrieves the current details and populates a form. Once the user makes their desired changes and clicks "Save," the system updates the product record with the new information.

2.2Step-by-Step Flow
1.Authentication Check: When the page loads, the system verifies the user's identity. If the user is not logged in, they are automatically redirected to the login page.
2.Data Retrieval: The system identifies the specific product from the page address and fetches its current details (such as pricing, stock settings, and descriptions) from the database.
3.Form Population: The retrieved product data is automatically mapped into the corresponding fields on the screen, allowing the user to see the current values immediately.
4.User Modification: The user updates the necessary fields in the form.
5.Submission: Upon clicking the "Save" button, the system collects all the current form values, maps them back to the product record format, and sends an update request to the server.
6.Confirmation: The system processes the update and displays a success notification if the changes were saved correctly, or an error message if the update could not be completed.
2.3Key Concepts
–Authentication: A security check that ensures only logged-in users can access or modify product data.
–Data Mapping: The process of matching specific pieces of information (like "SKU" or "Wholesale Price") between the database and the visual form fields to ensure data is displayed and saved in the correct location.
–Payload: The collection of all product information fields that are sent to the server when the user saves their changes.
–404 Not Found: A standard system response indicating that the requested product does not exist in the database.
2.4Business Value

This feature provides a reliable and efficient way for staff to maintain accurate product catalogs. By automating the pre-filling of forms and providing clear feedback upon saving, the system reduces manual data entry errors and ensures that pricing, stock tracking, and product attributes remain up-to-date across the business.

3.  Data
3.1Overview

The Product Edit Page feature allows users to manage and update existing product information within the Lumi ERP system. This feature ensures that all product details—ranging from basic identification and pricing to logistics and inventory settings—can be accurately maintained and synchronized with the central database.

3.2Step-by-Step Flow
1.Page Loading: When a user opens the edit page for a specific product, the system retrieves the current data from the database and automatically populates the form fields with the existing information.
2.Data Modification: The user updates the necessary fields in the form. This includes general details (name, description, brand), financial settings (pricing, tax, trade-in values), and operational settings (stock tracking, warranty, bundle status, and POS quick-button configurations).
3.Saving Changes: Once the user clicks the "Save" button, the system maps the updated form information into a structured format.
4.Database Update: The system performs an atomic update, ensuring all modified fields are saved to the database simultaneously to maintain data integrity.
3.3Key Concepts
–Atomic Update: A process that ensures all changes to a product record are saved as a single, complete operation, preventing partial or inconsistent data updates.
–Product Metadata: The comprehensive set of attributes defining a product, including its identity (SKU, name), financial rules (tax, pricing, MRP), and operational constraints (stock tracking, warranty, and bundle flexibility).
–Form Mapping: The bridge between the user interface and the database, ensuring that every field visible to the user is correctly linked to the corresponding data point in the system.
–POS Quick-Button Configuration: Settings that allow specific products to be prioritized or organized for faster access at the Point of Sale.
3.4Business Value
–Operational Accuracy: By providing a centralized and structured way to edit product details, the system reduces the risk of manual entry errors in pricing, tax, or inventory settings.
–Efficiency: The pre-filled form functionality saves time for staff by allowing them to quickly identify and update only the specific information that has changed.
–Flexibility: The inclusion of diverse attributes—such as bundle settings, warranty periods, and business unit categorization—enables the business to adapt to complex inventory needs and evolving market requirements without needing custom software changes.
