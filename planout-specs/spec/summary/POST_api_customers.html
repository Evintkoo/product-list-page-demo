1.  Logic
1.1Overview

The `POST /api/customers` feature allows the system to create a new customer record along with their associated addresses in a single operation. This process ensures that customer data is captured accurately, categorized by business type (such as wholesale or franchise), and linked to specific locations. The system automatically handles the assignment of unique identifiers and tracks which user created the record, ensuring data integrity and auditability.

1.2Step-by-Step Flow
1.Authentication Check: The system verifies that the user is logged in. If not, the request is rejected.
2.Request Validation: The system checks that the provided customer information (name, type, and address details) is formatted correctly.
3.Transaction Initiation: The system opens a secure "all-or-nothing" transaction. This ensures that if any part of the creation process fails, no partial or incomplete data is saved to the database.
4.Customer Creation: A new customer record is generated with a unique ID, the provided name, and the appropriate business type flags.
5.Address Processing: If addresses are provided, the system creates them and links them to the new customer. If an address is marked as the "main" address, the system updates the customer record to reflect this as the primary contact location.
6.Finalization: Once all data is successfully saved, the transaction is finalized (committed), and the system returns the newly created customer details to the user. If any error occurs during this process, the system cancels the entire operation (rollback) to keep the database clean.
1.3Key Concepts
–Transaction: A safety mechanism that ensures multiple related database actions (like creating a customer and their addresses) either all succeed together or all fail together, preventing data inconsistencies.
–Customer Type Mapping: A logic layer that translates a simple customer category (e.g., "wholesale") into specific internal settings that the system uses to manage business rules for that customer.
–Primary Address: A designated location for a customer that the system highlights for primary contact or shipping purposes.
–Audit Tracking: The automatic recording of the user who created the record, which is essential for maintaining a history of system activity.
1.4Business Value

This feature streamlines the onboarding of new clients by allowing users to submit comprehensive customer profiles in one go. By automating the linking of addresses and the assignment of business types, the system reduces manual data entry errors. Furthermore, the "all-or-nothing" transaction logic provides peace of mind, ensuring that the database remains accurate and reliable even if a network interruption or validation error occurs during the creation process.

2.  Data
2.1Overview

The "Create Customer" feature allows the system to register a new customer profile along with their associated addresses in a single, reliable operation. This process ensures that customer data is correctly categorized (e.g., wholesale, franchise, or consignment) and that primary contact information is linked accurately to the customer's profile.

2.2Step-by-Step Flow
1.Initiation: The system receives a request to create a new customer, including their name, business type, and any provided addresses.
2.Customer Creation: A new customer record is generated in the database, capturing the user who initiated the request and the current timestamp.
3.Address Processing: The system iterates through the provided list of addresses, saving each one and linking it to the newly created customer.
4.Primary Address Assignment: If an address is flagged as the "main" address, the system automatically updates the customer profile to designate that specific address as the primary point of contact.
5.Finalization: If all steps succeed, the transaction is finalized (committed). If any part of the process fails, the system cancels the entire operation (rolls back) to prevent incomplete or "orphaned" data.
2.3Key Concepts
–Atomic Transaction: A "all-or-nothing" approach where the customer and their addresses are saved together; if one part fails, nothing is saved, ensuring data consistency.
–Customer Type: A classification system that tags customers as retail, wholesale, franchise, or consignment to support specific business logic.
–Primary Address: A specific designation for a customer's main location, which is automatically linked to the customer profile for easy retrieval.
–Audit Tracking: The system automatically records the identity of the user who created the record, providing accountability for all new entries.
2.4Business Value

This feature streamlines the onboarding of new clients by allowing users to input comprehensive customer details—including multiple addresses—in one go. By using an atomic transaction, the business avoids data errors or partial records, ensuring that every customer profile is complete and reliable from the moment it is created. This reduces manual data entry and improves the accuracy of customer records across the ERP system.
