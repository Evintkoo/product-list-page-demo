1.  Frontend
1.1Overview

The Sales Details page provides a comprehensive view of an individual retail transaction within the Lumi ERP system. It allows staff to review transaction data, monitor the current workflow status, and perform necessary actions such as finalizing or canceling a sale. The page is designed to be dynamic, showing relevant information based on the sale's current state.

1.2Step-by-Step Flow
1.Loading Data: When you open a specific sales record, the system automatically retrieves all relevant transaction details, including customer information, product line items, payment summaries, and timestamps.
2.Viewing Details: The page displays a structured summary of the sale, including the reference code, store location, salesperson, and specific product details.
3.Monitoring Status: A status bar at the top indicates whether the sale is currently a "Draft" or "Completed."
4.Taking Action:

* If the sale is in "Draft" status, you have the option to "Complete" the sale or "Cancel" it.

* If you choose to change the status, a confirmation window will appear to prevent accidental updates.

* You can also use the "Print and Send" button at any time to generate a PDF of the transaction for email distribution.

1.3Key Concepts
–Draft Status: The initial state of a sale after it has been created but before it is finalized.
–Completed Status: The final state of a sale, indicating the transaction has been fully processed and executed.
–Workflow Status Bar: A visual indicator that shows the current progress of the sale and provides access to status-changing actions.
–Confirmation Modal: A safety pop-up that requires you to verify your intent before the system permanently updates the status of a sale.
–Line Items Table: A detailed breakdown of the products included in the sale, showing quantities, pricing, and any applied discounts.
1.4Business Value
–Operational Efficiency: By centralizing all transaction data and status controls in one view, staff can quickly manage sales without navigating between multiple screens.
–Data Integrity: The use of confirmation modals for status changes reduces the risk of human error, ensuring that sales are only finalized or canceled intentionally.
–Improved Customer Service: The ability to instantly print or email transaction details allows for faster communication with customers regarding their purchases.
–Transparency: Clear tracking of timestamps (created, updated, and completed) and user attribution provides a reliable audit trail for every transaction.
2.  Logic
2.1Overview

The Sales Details feature provides a centralized view for managing individual retail transactions within the Lumi ERP system. It allows staff to view comprehensive transaction data—such as store location, total amounts, and current status—and manage the lifecycle of a sale from its initial draft phase through to completion.

2.2Step-by-Step Flow
1.Data Retrieval: When a user opens a sales record, the system automatically fetches the transaction details, including the specific store location and financial totals.
2.Information Display: The system maps internal database records to the screen, ensuring fields like the reference code, date, customer information, and salesperson are clearly visible to the user.
3.Payment Summary: The system calculates the final total (including tax) and determines the change due by comparing the total amount against the payments provided by the customer.
4.Status Management: Users can monitor the sale via the Workflow Status Bar. If a change is requested (e.g., moving from "Draft" to "Completed"), the system prompts for confirmation.
5.Validation: Before finalizing a status change, the system verifies that the sale is not already marked as "Completed." If the sale is already finished, the system prevents further modifications to ensure data integrity.
2.3Key Concepts
–Sales Transaction: The core record containing all details of a retail sale, including financial data, store context, and current progress.
–Workflow Status: A tracking mechanism that identifies whether a sale is currently a "Draft" (in progress) or "Completed" (finalized).
–Payment Summary: An automated calculation that ensures the amount paid by the customer matches the transaction total and accurately reflects any change owed.
–Data Mapping: The process of translating raw system data into a user-friendly format displayed on the screen.
2.4Business Value
–Operational Efficiency: By automating the calculation of totals and change, the system reduces manual errors and speeds up the checkout process.
–Data Integrity: The built-in validation prevents accidental changes to finalized sales, ensuring that financial records remain accurate and reliable.
–Improved Visibility: Providing a clear, mapped view of transaction details allows staff to quickly access necessary information about customers, products, and store performance, leading to better customer service.
3.  Data
3.1Overview

The "Sales Details - Store" feature provides a centralized view for monitoring the performance of individual retail locations within the Lumi ERP system. It allows users to pull specific sales records for a chosen store over a defined timeframe, while also providing high-level performance metrics to help managers quickly assess how a specific location is performing.

3.2Step-by-Step Flow
1.Identify the Store: The system retrieves the specific profile and metadata for the selected store to ensure the user is viewing the correct location.
2.Define the Timeframe: The user selects a start and end date to narrow down the sales activity they wish to review.
3.Retrieve Transaction Records: The system gathers all individual sales transactions that occurred at that specific store within the chosen date range.
4.Calculate Performance Metrics: The system automatically aggregates the data to provide a summary, including the total revenue generated and the total number of transactions processed for that store.
3.3Key Concepts
–Store Metadata: The descriptive information about a store, such as its name, location code, and region, which provides context for the sales data.
–Sales Transactions: Individual records of sales events, including the date, the total amount paid, and the current status of the sale.
–Aggregated Metrics: A summary calculation that combines individual transaction data into meaningful totals, such as total revenue and transaction volume, to give a quick snapshot of store health.
3.4Business Value

This feature empowers store managers and regional leads to make data-driven decisions by providing clear visibility into store performance. By combining detailed transaction logs with summarized revenue metrics, users can easily identify sales trends, track daily performance, and compare results across different time periods without needing to manually calculate totals.
