1.  Logic
1.1Overview

This feature provides a secure and reliable way for users to create "Discrepancy Stock" reports. These reports allow staff to record the actual quantities of products counted at a specific store location. The system is designed to ensure data integrity by validating all entries before saving and preventing duplicate reports if a user accidentally submits the same form twice.

1.2Step-by-Step Flow
1.Duplicate Check: The system checks if the report has already been submitted using a unique request identifier. If it has, the system returns the existing report instead of creating a new one.
2.Security & Data Validation: The system verifies that the store belongs to the user's company. It also ensures the report contains at least one item, all products are valid, no product is listed twice, and all quantities are greater than zero.
3.Report Creation: Once validated, the system generates a unique reference code for the report and saves the header information along with all product lines.
4.Atomic Saving: The report and its items are saved as a single "all-or-nothing" transaction. This ensures that if any part of the save fails, the entire report is discarded, preventing incomplete or corrupted data.
5.Confirmation: Upon success, the system returns the finalized report details, including the generated reference code, so the user can immediately view or track the new document.
1.3Key Concepts
–Idempotency: A safety mechanism that ensures submitting the same request multiple times does not result in duplicate reports; it simply returns the original result.
–Atomic Transaction: A "save all or nothing" approach that ensures a report is only created if every single line item is successfully processed.
–Reference Code: A unique, system-generated identifier (formatted as DISC/StoreCode/Sequence) used to track and display the report in the system.
–Draft State: All new reports are automatically set to a "draft" status, allowing for further review or action before they are finalized.
1.4Business Value
–Data Accuracy: By validating product IDs, quantities, and store ownership at the point of entry, the system prevents human error and unauthorized reporting.
–Operational Reliability: The "all-or-nothing" saving process prevents partial data entries, ensuring that inventory records remain consistent and trustworthy.
–User Experience: The idempotency feature protects users from accidental double-submissions (e.g., clicking "Submit" twice due to a slow connection), providing a smoother and more predictable workflow.
–Security: By automatically assigning company and user information based on the active session, the system prevents users from accidentally or intentionally filing reports for the wrong location or organization.
2.  Data
2.1Overview

This feature provides a secure and reliable way for users to submit "Discrepancy Stock" reports. These reports allow staff to record differences between expected and actual inventory counts at a specific store. The system is designed to ensure data integrity by validating all inputs, preventing duplicate submissions, and ensuring that reports are saved completely or not at all.

2.2Step-by-Step Flow
1.Validation: The system checks that the store mentioned in the report belongs to the user's company. It also verifies that the report contains at least one item, that all products are valid, that no product is listed twice, and that all quantities are greater than zero.
2.Duplicate Prevention: The system checks if a report with the same unique request ID has already been submitted. If it has, the system returns the existing report instead of creating a duplicate.
3.Report Preparation: The system automatically assigns a unique reference code to the report (formatted as `DISC/store-code/sequence`), sets the status to "draft," and records the user who created it and the time of creation.
4.Atomic Saving: The system saves the report header and all individual product lines together in a single operation. This ensures that if any part of the process fails, the entire report is rolled back, preventing incomplete or "half-saved" data.
5.Confirmation: Once successfully saved, the system returns the full details of the new report, including the generated reference code, so the user can immediately view or manage the document.
2.3Key Concepts
–Idempotency: A safety mechanism that ensures if a user accidentally submits the same form twice (e.g., by clicking "submit" multiple times), the system recognizes it as the same request and does not create duplicate reports.
–Atomic Transaction: A "all-or-nothing" approach to saving data. It guarantees that the report header and its associated product lines are saved as a single unit, preventing data corruption.
–Server-Side Ownership: To maintain security and consistency, the system ignores certain data sent by the user (like the status or company ID) and instead uses verified information from the user's active session.
–Draft State: All new reports are automatically initialized as "drafts," allowing for further review or adjustments before they are finalized or processed.
2.4Business Value

This feature streamlines inventory management by providing a standardized, error-proof method for recording stock discrepancies. By automating the reference numbering and enforcing strict validation, it reduces manual data entry errors and ensures that inventory records remain accurate and auditable. The built-in duplicate protection and atomic saving provide a robust experience for store operators, ensuring that their work is reliably captured without the risk of system-side data inconsistencies.
