1.  Frontend
1.1Overview

The Stock Order Details page provides a centralized view for managing inventory requests within the Lumi ERP system. This page allows users to view specific order information, track the progress of an order through its lifecycle, and perform necessary actions—such as confirming, reviewing, or receiving stock—based on the order's current status.

1.2Step-by-Step Flow
1.Page Initialization: When the page loads, the system automatically retrieves the order’s core details and the list of items associated with that order.
2.Displaying Information: The page displays the order metadata (such as reference numbers and warehouse details) in a dedicated panel, while individual products are listed in a sortable table.
3.Sorting Data: Users can click on column headers (such as SKU, Product, or Order Quantity) to sort the list of items in ascending or descending order to help locate specific information quickly.
4.Workflow Progression: Depending on the current status of the order (e.g., Draft, Store Confirmed, or Warehouse Sent), the system displays relevant action buttons.
5.Action Execution: When a user clicks an action button (like "Confirm"), a confirmation window appears to prevent accidental changes. Once confirmed, the system updates the order status and moves it to the next stage of the workflow.
1.3Key Concepts
–Workflow Status Bar: A visual tracker that shows the current stage of the order (e.g., Draft, Store Confirmed, Warehouse Sent, or Store Received) to ensure users know exactly where the order stands in the process.
–Details Panel: A summary section that provides essential context about the order, including source information, dates, and administrative notes.
–Sortable Table: A data grid that allows users to organize product information by clicking on headers, making it easier to manage large lists of items.
–Action Buttons: Context-aware controls that only appear when they are relevant to the current order status, ensuring users only perform valid operations at the right time.
1.4Business Value

This feature streamlines inventory management by providing a clear, guided process for handling stock orders. By automating the status tracking and providing a consistent interface for reviewing and confirming orders, the system reduces manual errors, improves communication between the store and the warehouse, and ensures that inventory records remain accurate throughout the entire fulfillment lifecycle.

2.  Logic
2.1Overview

The Stock Order Details page provides a centralized view for managing inventory requests. It allows users to view specific order information, review the list of requested products, and perform final actions such as confirming or cancelling an order.

2.2Step-by-Step Flow
1.Page Initialization: When a user opens a specific stock order, the system simultaneously retrieves the order’s header information (such as the warehouse location and status) and the list of individual items included in that order.
2.Data Display: The system populates the page header with the order details and fills the product table with the retrieved items, ensuring that information like product codes, quantities, and costs are clearly mapped to their respective columns.
3.Order Confirmation: If the user chooses to confirm the order, the system updates the order status to "Confirmed" to reflect that the request is finalized.
4.Order Cancellation: If the user chooses to cancel, the system prompts for a final confirmation to prevent accidental clicks. Once confirmed, the order status is updated to "Cancelled."
2.3Key Concepts
–Stock Order Header: The top-level information for an order, including the unique order ID, current status, creation date, and the associated warehouse.
–Line Items: The specific products requested within an order, displayed in a table format that includes details like SKU, product name, quantity, and average cost.
–Status Transition: The process of changing an order's state (e.g., from "Pending" to "Confirmed" or "Cancelled") to ensure the system accurately reflects the current progress of the inventory request.
–Data Mapping: The process of taking raw system information and organizing it into the user-friendly table columns (such as "Order Qty" or "Store Remark") for easier reading.
2.4Business Value

This feature streamlines inventory management by providing a clear, organized interface for staff to verify and process stock requests. By separating the order header from the item list, users can quickly assess the scope of an order, while the built-in confirmation steps for status changes help reduce errors and ensure that inventory records remain accurate and reliable.

3.  Data
3.1Overview

The Stock Order Details page provides a centralized view for managing individual stock orders within the Lumi ERP system. This feature allows users to view comprehensive order information, including specific product line items, and provides the necessary controls to finalize or cancel an order directly from the interface.

3.2Step-by-Step Flow
1.Page Initialization: When a user opens a specific stock order, the system verifies their access permissions.
2.Data Retrieval: The system simultaneously fetches the main order details (such as the warehouse location and status) and the list of products associated with that order.
3.Display: The product list is organized into a clear table format, showing details like product codes, quantities, average costs, and any specific remarks added by the store.
4.Workflow Management:

* Confirming: If the user chooses to confirm the order, the system updates the order status to "Confirmed."

* Canceling: If the user chooses to cancel, the system reverts the order to a "Cancelled" state and refreshes the page to reflect the updated status.

3.3Key Concepts
–Stock Order: The primary document representing a request for inventory, containing header information like the warehouse destination and current status.
–Line Items: The individual rows within a stock order that detail specific products, including their quantities, costs, and any store-specific notes.
–Workflow Status: The current stage of an order (e.g., Pending, Confirmed, or Cancelled), which dictates what actions a user can take.
–Pagination: A method used to display large lists of products in manageable chunks, ensuring the page remains fast and easy to read.
3.4Business Value
–Operational Efficiency: By consolidating order headers and line items into a single view, staff can quickly verify order accuracy without navigating between multiple screens.
–Improved Accuracy: Standardized mapping of product data ensures that store staff see consistent information, such as product codes and average costs, reducing the risk of manual entry errors.
–Streamlined Decision Making: Providing clear "Confirm" and "Cancel" actions directly on the details page allows for faster processing of inventory requests, helping to keep warehouse operations moving smoothly.
