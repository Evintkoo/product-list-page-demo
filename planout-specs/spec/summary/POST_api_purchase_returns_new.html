1.  Logic
1.1Overview

The "Create Purchase Return" feature allows the system to officially record items being returned by the company. This process ensures that both the main return document (the header) and the specific list of items being returned are saved together as a single, reliable transaction. The system automatically generates tracking information, such as unique reference codes and timestamps, to keep inventory records accurate and organized.

1.2Step-by-Step Flow
1.Validation: The system checks that the incoming request is formatted correctly.
2.Duplicate Check: The system looks for a unique request identifier to ensure the same return isn't processed twice by mistake. If it has already been processed, it simply returns the existing record.
3.Transaction Start: The system begins a secure "all-or-nothing" process to ensure data integrity.
4.Header Creation: A new return document is created, and the system automatically assigns it a unique ID, a reference code, and the current date/time.
5.Item Processing: The system reviews each item in the request. It verifies that every product exists in the inventory database before adding it to the return.
6.Finalization: If all items are valid, the system saves the entire return (header and items) permanently. If any part of the process fails, the system cancels the entire operation to prevent incomplete or incorrect data from being saved.
1.3Key Concepts
–Transaction: A safety mechanism that ensures either the entire return is saved successfully or nothing is saved at all, preventing partial or corrupted data.
–Idempotency Token: A unique identifier used to prevent the same request from being submitted multiple times, which protects against accidental duplicate entries.
–Header: The main record for the purchase return that contains high-level information, such as the type of return and the date it was created.
–Validation: The process of checking that all provided information (like product IDs) is accurate and exists within the system before finalizing the record.
1.4Business Value

This feature provides a reliable and automated way to manage inventory returns. By using a transaction-based approach, the business avoids "ghost" records or mismatched inventory data. The inclusion of duplicate protection and automated reference generation reduces manual administrative work and minimizes the risk of human error, ensuring that the company’s inventory levels remain accurate and auditable.

2.  Data
2.1Overview

This feature allows the system to record a new "Company Purchase Return." It captures the high-level details of the return (the header) and the specific list of items being returned. The system is designed to be robust, ensuring that either the entire return is saved successfully or nothing is saved at all, preventing incomplete or corrupted data.

2.2Step-by-Step Flow
1.Duplicate Check: The system first checks if a return with the same unique request identifier has already been processed. If it has, the system returns the existing record instead of creating a new one.
2.Transaction Start: The system begins a secure database operation to ensure all data is saved together.
3.Header Creation: The system creates the main return record, automatically generating a unique reference code and timestamps for the entry.
4.Item Processing: The system adds each individual item from the request to the return, linking them to the main header record created in the previous step.
5.Finalization: If all steps succeed, the transaction is finalized, and the system confirms the creation. If any part of the process fails, the system cancels the entire operation to ensure no partial data is saved.
6.Response: The system returns the newly created record details or provides an appropriate error message if the request was invalid or an unexpected issue occurred.
2.3Key Concepts
–Idempotency: A safety mechanism that uses a unique request identifier to ensure that if the same request is sent multiple times (e.g., due to a network retry), the system does not create duplicate records.
–Transaction: A "all-or-nothing" approach to saving data. It ensures that the return header and its associated items are treated as a single unit of work.
–Header: The primary record that classifies the return and holds general information, such as the return type and creation date.
–Items: The specific products and quantities associated with a return, which are linked back to the main header record.
2.4Business Value

This feature provides a reliable and consistent way to track inventory returns within the Lumi ERP. By using an idempotency check, it prevents accidental duplicate entries, which protects inventory accuracy. Furthermore, the "all-or-nothing" transaction logic ensures that the system never ends up with "orphaned" items or incomplete return records, maintaining high data integrity for financial and inventory reporting.
