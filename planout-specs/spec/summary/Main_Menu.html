1.  Frontend
1.1Overview

This feature describes the Main Menu — the header bar that appears at the top of every page in the ERP system. It gives users a consistent way to navigate between sections, search for information, check notifications, and manage their account, no matter which page they're on.

1.2Step-by-Step Flow
1.Viewing the header: Every page displays the same top bar, containing the company logo, navigation links, a search box, a notification bell, and an account avatar.
2.Clicking "Products": When a user clicks the Products navigation item, a menu panel opens beneath it showing related options. Clicking it again closes the panel.
3.Clicking a navigation item: When a user clicks any other top navigation item (like a section link), the system marks that item as "active" (highlighted), closes any open panels, and takes the user to the corresponding page.
4.Using the search box: As a user types into the search field, the system trims extra spaces and limits entry to 200 characters. It waits briefly after the user stops typing (to avoid reacting to every keystroke) before treating the typed text as a search request. If the box is cleared, any search results are cleared too.
5.Opening notifications: Clicking the bell icon opens a dropdown meant to show unread alerts, and closes any other open panels. Clicking again closes it.
6.Opening the account menu: Clicking the avatar opens a dropdown with "Settings" and "Sign Out" options, closing any other open panels. Clicking again closes it.
7.Only one panel open at a time: Whenever the user opens a Products menu, notification panel, or account menu, any other currently open panel automatically closes — keeping the header uncluttered.
1.3Key Concepts
–Active navigation state: The system remembers which navigation item was last clicked so it can visually highlight it, helping users know where they are.
–Debounced search: Instead of searching on every keystroke, the system waits for a short pause in typing before acting — this prevents unnecessary or premature searches while typing.
–Mutually exclusive dropdowns: Only one dropdown (Products, Notifications, or Account) can be open at a time; opening one automatically closes the others.
–Placeholder features: The notification list and account profile details (like name and photo) are designed to appear in the header, but the actual data connections for these are not yet defined — they will be completed once that information becomes available.
–Input safeguards: The search box automatically trims stray spaces and caps entries at 200 characters to keep input clean and manageable.
1.4Business Value

This header creates a consistent, predictable navigation experience across the entire ERP system, so employees always know where key actions (search, notifications, account, navigation) are located, regardless of which module they're using. The debounced search reduces unnecessary system load, keeping the interface responsive. Auto-closing of dropdown menus keeps the interface clean and prevents visual clutter or user confusion. Although notifications and account details aren't fully wired to live data yet, the structure is ready to support these once the underlying data becomes available — minimizing future rework.
