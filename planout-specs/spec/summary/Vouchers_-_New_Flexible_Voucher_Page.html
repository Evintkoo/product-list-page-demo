1.  Frontend
1.1Overview

The "New Flexible Voucher" page is a dedicated interface within the Lumi ERP system that allows staff to create and configure new flexible voucher products. This page provides a structured form to define the voucher's identity, validity rules, and usage locations, ensuring that all necessary business data is captured before the voucher is made available in the system.

1.2Step-by-Step Flow
1.Initialization: When the page loads, the system automatically fetches necessary configuration data (such as available product conditions and external publisher options) to populate the dropdown menus.
2.Data Entry: The user fills out the form, providing essential details such as the unique SKU, the voucher name, and an optional description.
3.Configuration: The user defines the voucher's behavior, including:

* Setting the validity period (in days or months) and specific start/end dates.

* Selecting where the voucher can be sold, issued, or redeemed.

* Assigning the voucher to specific members or keeping it open to all customers.

* Choosing a product condition (e.g., by product list or by type/brand).

4.Validation: Upon clicking "Save," the system checks that the mandatory fields (SKU and Name) have been completed.
5.Submission: If valid, the system saves the new flexible voucher to the database.
6.Completion: The user is redirected to the main voucher list page. If the user decides not to proceed, they can click "Cancel" to discard all changes and return to the list page.
1.3Key Concepts
–SKU: A unique identifier used to track and manage the voucher product within the ERP system.
–Flexible Voucher: A versatile voucher type that allows for customizable pricing, validity, and redemption rules.
–Open Price: A setting that, when enabled, allows the voucher price to be flexible rather than fixed.
–Product Condition: A rule set that determines which specific products or categories the voucher applies to.
–Redemption/Issue Locations: Specific store locations authorized to sell or accept the voucher.
–External Publisher: A third-party entity or partner associated with the issuance or promotion of the voucher.
1.4Business Value

This feature streamlines the product management process by providing a centralized, user-friendly way to create flexible vouchers. By enforcing mandatory fields and providing clear configuration options for validity and location, the system reduces manual entry errors and ensures that all vouchers are correctly categorized and restricted according to business policy. This ultimately improves operational efficiency and provides better control over promotional and financial voucher programs.

2.  Logic
2.1Overview

The "New Flexible Voucher" feature allows administrators to create and configure new voucher products within the Lumi ERP system. This page provides a structured way to define voucher details—such as pricing, validity periods, and usage locations—ensuring that all necessary information is captured accurately before the voucher is made available for use.

2.2Step-by-Step Flow
1.Data Entry: The user fills out the voucher form, providing details such as the unique SKU, name, description, pricing rules, and validity dates.
2.Validation: Upon clicking "Save," the system automatically checks the input for errors. It ensures the SKU is unique, prevents conflicting expiration settings (e.g., setting both months and days), and confirms that a price is provided if the voucher does not have an "open price."
3.Mapping: If the data is valid, the system organizes the form information into the required format for the database.
4.Persistence: The system saves the new voucher record to the database.
5.Confirmation: Once successfully saved, the system returns a confirmation containing the new voucher's unique ID, SKU, and creation timestamp.
2.3Key Concepts
–SKU (Stock Keeping Unit): A unique identifier for the voucher product, used to distinguish it from other items in the system.
–Open Price: A setting that allows the voucher price to be determined at the time of sale rather than being fixed in advance.
–Validation Rules: Automated checks that prevent the creation of vouchers with missing or logically conflicting information.
–Flexible Expiration: The ability to define how long a voucher remains valid, either by a specific date range or a duration (months/days).
–Location Mapping: The ability to specify exactly where a voucher can be sold/issued and where it can be redeemed.
2.4Business Value

This feature streamlines the product management process by providing a standardized, error-proof method for creating vouchers. By enforcing data consistency at the point of entry, the system reduces administrative errors and ensures that vouchers are correctly configured for sales and redemption, ultimately supporting more reliable financial tracking and customer experience.

3.  Data
3.1Overview

The new Flexible Voucher feature allows your team to create and manage versatile voucher products within the Lumi ERP system. This feature is designed to be highly configurable, enabling you to define specific pricing, validity periods, and location-based rules for each voucher. By centralizing this process, the system ensures that every voucher is uniquely identified and correctly tracked from the moment it is created.

3.2Step-by-Step Flow
1.Data Entry: You input the voucher details into the system, including its unique identifier (SKU), name, pricing structure, and validity rules.
2.Validation: The system automatically checks that the SKU is unique to prevent duplicate records. If a duplicate is found, the system will alert you to correct it.
3.Configuration: The system captures specific business rules, such as whether the price is fixed or open, where the voucher can be sold or redeemed, and any specific membership requirements.
4.Persistence: Once validated, the system saves the voucher details into the database, assigning it a unique internal ID and a timestamp for audit purposes.
5.Confirmation: Upon successful creation, the system confirms that the voucher is active and ready for use.
3.3Key Concepts
–SKU (Stock Keeping Unit): A unique code used to identify a specific product, ensuring no two vouchers are confused in the system.
–Open Price: A setting that allows the voucher price to be flexible or determined at the time of sale, rather than being fixed.
–Validity Rules: Configurable timeframes (days or months) or specific calendar dates that dictate when a voucher can be used.
–Location Mapping: The ability to define specific branches or locations where a voucher can be issued (sold) and where it can be redeemed.
–External Publisher: A field to track if the voucher is being managed or issued by a third-party partner.
3.4Business Value
–Operational Efficiency: By automating the creation and validation process, staff can quickly launch new promotional vouchers without manual oversight.
–Flexibility: The ability to set custom redemption locations and variable pricing allows the business to run targeted marketing campaigns tailored to specific regions or customer segments.
–Data Integrity: Automated SKU validation prevents errors in inventory and financial reporting, ensuring that every voucher sold is accurately accounted for in the ERP.
–Scalability: The structured approach to defining voucher rules makes it easy to manage a large catalog of diverse products as the business grows.
