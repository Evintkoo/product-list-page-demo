1.  Logic
1.1Overview

This feature provides a way to retrieve a list of all service products that have been deactivated within the Lumi ERP system. By accessing this list, users can view services that are no longer active, helping with record-keeping, auditing, or potential reactivation. The system also allows users to narrow down this list by applying specific filters, such as service type or category tags.

1.2Step-by-Step Flow
1.Authentication Check: The system verifies that the user is logged in and authorized to view this information. If not, access is denied.
2.Filter Extraction: The system checks if the user has requested to filter the results by a specific service type or a specific tag.
3.Validation: If filters are provided, the system confirms that the requested type or tag actually exists in the database. If a requested filter does not exist, the system reports an error.
4.Data Retrieval: The system searches the database for all service products marked as "inactive." If filters were provided, it further narrows the search to only include items matching those specific criteria.
5.Display: The system returns the final list of inactive service products to the user.
1.3Key Concepts
–Inactive Service Products: Items that have been "soft-deleted" or deactivated in the system, meaning they are hidden from standard views but still stored for historical reference.
–Filtering: The ability to refine the list of inactive items by selecting a specific "Type" or "Tag," making it easier to find relevant records.
–Validation: A safety check performed by the system to ensure that any filters requested by the user are valid and exist in the database before attempting to search.
–Unauthorized Access: A security measure that ensures only authenticated users can view sensitive service product data.
1.4Business Value

This feature improves data management by providing a dedicated view for deactivated services. Instead of losing track of items that are no longer in use, administrators can easily audit or review these records. The addition of filtering capabilities ensures that users can quickly locate specific inactive services without having to manually sort through a large, unfiltered list, thereby saving time and improving operational efficiency.

2.  Data
2.1Overview

The "Inactive Service Products" feature provides a way to retrieve a list of service products that have been deactivated within the Lumi ERP system. This endpoint is designed to support the "Inactive" tab in the user interface, allowing users to view, manage, or potentially restore services that are no longer in active use.

2.2Step-by-Step Flow
1.Request Initiation: The system receives a request to fetch inactive service products.
2.Validation: The system checks if any optional filters (such as specific service types or tags) are provided. If a filter is provided but does not exist in the system, the request is rejected with a "Not Found" error.
3.Data Retrieval: The system queries the database for all service products marked as "inactive."
4.Filtering: If filters were provided, the system narrows the list to only include items matching those specific criteria.
5.Pagination: The results are organized into pages (based on the requested page number and limit) to ensure the system remains performant even with a large number of inactive items.
6.Sorting: The results are returned in order of creation, with the most recently deactivated or created items appearing first.
7.Response: The system returns the requested page of data along with metadata (such as the total count of inactive items) to the user.
2.3Key Concepts
–Inactive Status: A "soft-deleted" state for service products, meaning the data is hidden from active workflows but remains in the system for record-keeping or potential reactivation.
–Pagination: A method of breaking a large list of data into smaller, manageable chunks (pages) to improve loading speeds and user experience.
–Filtering: The ability to narrow down the list of inactive products by specific categories (Service Type) or labels (Service Tag).
–Metadata: Supplemental information returned with the list, such as the total number of inactive products, which helps the user interface display accurate page numbers and navigation.
2.4Business Value

This feature improves data management by providing clear visibility into discontinued or deactivated services. By allowing users to filter and browse these items, the business can:

* Maintain Data Integrity: Keep a historical record of services without cluttering the active product catalog.

* Improve Operational Efficiency: Enable staff to quickly locate and potentially reactivate services that were previously retired.

* Enhance Reporting: Provide better insights into the lifecycle of service offerings by tracking what has been deactivated and why.
