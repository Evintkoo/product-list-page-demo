1.  Frontend
1.1Overview

The Payment Types List feature provides a centralized dashboard for managing how different payment methods are configured within the Lumi ERP system. Users can view, search, and filter through all active or inactive payment types, such as cash, credit cards, or debit cards. The interface is designed to help finance teams quickly verify payment provider details, fee rates, and specific processing rules (like refund capabilities or invoice receivable settings) in a clear, tabular format.

1.2Step-by-Step Flow
1.Initial Load: When the page opens, the system automatically displays a list of all "Active" payment types, showing 20 items per page.
2.Navigation: Users can toggle between "Active" and "Inactive" tabs to switch the view of payment types.
3.Filtering: Users can narrow down the list by entering a name or selecting specific criteria from dropdown menus (Type, Refund status, or Invoice Receivable status).
4.Search: Clicking the "Search" button applies the selected filters, resets the view to the first page, and updates the table with the relevant results.
5.Reviewing Details: The table displays key information for each payment type, including the provider, fee rates, and operational settings.
6.Taking Action:

* Clicking a payment provider name navigates the user to the relevant Customer Details page.

* Clicking the "Show" button in the Stores column opens the mapping list for that payment type.

* Clicking the "Edit" button allows the user to modify the configuration of a specific payment type.

1.3Key Concepts
–Payment Type: A specific method of payment (e.g., Cash, Credit Card) configured in the system.
–Active/Inactive Status: A toggle that filters the list to show only currently used payment methods or those that have been archived/deactivated.
–Pagination: A system that breaks the list into smaller, manageable pages (20 items per page) to ensure the interface remains fast and easy to read.
–Filter Bar: A set of controls that allows users to refine the list based on specific attributes like name, type, or processing rules.
–Mapping: A feature that links a payment type to specific store locations or business rules.
1.4Business Value

This feature streamlines financial administration by providing a single source of truth for payment configurations. By allowing users to easily search and filter payment types, the system reduces the time spent looking up provider details or fee structures. Furthermore, the ability to quickly navigate to customer details or mapping configurations ensures that finance teams can maintain accurate records and respond to payment-related inquiries with minimal effort.

2.  Logic
2.1Overview

The Payment Types List feature provides a centralized view for managing how payments are processed within the Lumi ERP system. Users can browse, search, and filter through all configured payment types—such as credit cards or cash—to quickly locate specific payment methods and view their associated settings, such as provider fees and refund capabilities.

2.2Step-by-Step Flow
1.Initial Load: When the page first opens, the system automatically displays a list of all "Active" payment types, showing 20 items per page.
2.Applying Filters: Users can refine the list using the filter bar. Available filters include the payment name, type, refund status, invoice receivable settings, and an active/inactive status toggle.
3.Search Execution: Upon clicking the "Search" button, the system clears the current view, resets to the first page of results, and fetches the updated list based on the selected criteria.
4.Data Display: The system retrieves the relevant payment data and organizes it into a table. This includes details like the payment provider, fee rates, and specific operational flags (e.g., whether refunds are enabled).
5.Pagination: If the results exceed the page size, the system provides navigation controls to move between pages, ensuring the interface remains clean and easy to navigate.
2.3Key Concepts
–Payment Type: A specific method of payment (e.g., Cash, Credit Card, Debit Card) configured within the system.
–Filters: Search criteria that allow users to narrow down the list by specific attributes, such as whether a payment type is currently active or if it allows refunds.
–Pagination: A method of breaking the list into smaller, manageable chunks (pages) to improve performance and readability.
–Provider Details: Information regarding the external service or bank handling the transaction, including any associated fee rates.
–Operational Flags: Settings that dictate how the system handles specific payment types, such as whether to skip invoice receivables or allow refunds.
2.4Business Value

This feature improves operational efficiency by allowing finance teams to quickly audit and manage payment configurations. By providing robust search and filtering capabilities, users can easily verify provider fee rates and payment settings, ensuring that financial data remains accurate and that payment processing rules are correctly applied across the organization.

3.  Data
3.1Overview

The Payment Types List feature provides a centralized view for managing how your business processes incoming payments. It allows finance team members to browse all configured payment methods—such as credit cards or digital payment services—in a clear, organized table. The feature includes search capabilities to quickly locate specific methods and pagination to keep the interface clean and easy to navigate when managing a large number of payment options.

3.2Step-by-Step Flow
1.Requesting Data: When you open the Payment Types screen, the system retrieves the full list of available payment methods from the database.
2.Applying Filters: If you enter a name into the search bar, the system narrows down the list to show only the payment types that match your search term.
3.Organizing Results: The system divides the list into manageable pages based on your preferred number of rows per page.
4.Calculating Totals: The system calculates the total number of pages and items available, ensuring the navigation controls (like "Next" or "Previous" buttons) are accurate.
5.Displaying Information: The system formats the raw data into a user-friendly list, showing key details like the provider name, associated fees, and specific settings (such as whether refunds are enabled or if invoice receivables should be skipped).
3.3Key Concepts
–Payment Type: A specific method used to receive funds, such as a credit card, bank transfer, or digital wallet.
–Search Filter: A tool that allows you to find a specific payment method by typing part of its name.
–Pagination: A navigation feature that breaks a long list of items into smaller, separate pages to improve performance and readability.
–Provider Fee Rate: The percentage or cost charged by the payment service provider for processing a transaction.
–Refund Capability: A setting that indicates whether a specific payment method supports the processing of customer refunds.
3.4Business Value

This feature streamlines financial operations by providing a single source of truth for all payment methods. By allowing users to quickly search and filter through these options, the finance team can reduce administrative time spent looking up payment configurations. Furthermore, the clear display of provider fees and processing rules ensures that staff can easily verify payment settings, leading to more accurate financial reporting and better control over payment processing workflows.
