1.  Frontend
1.1Overview

The "Add Sales" feature provides a streamlined interface for retail staff to process customer transactions. It allows users to build a sale by selecting a customer, assigning a salesperson, and choosing a register. The system supports adding multiple products and vouchers to a single transaction, automatically calculating totals, taxes, and payment balances to ensure accuracy at the point of sale.

1.2Step-by-Step Flow
1.Initialization: When the page loads, the system automatically populates dropdown menus for Salespeople, Registers, and Payment Types by fetching the latest data.
2.Sale Header Setup: The user selects the required Customer (searchable by name, phone, birthdate, or ID), the Salesperson, and the Register. If a customer is not in the system, the user can quickly add them via a pop-up window. Optionally, a vehicle can be linked to the sale.
3.Adding Items: The user adds products to the sale. For each item, the system automatically fills in the price and discount information. The user only needs to input the quantity.
4.Adding Vouchers: If applicable, the user can switch to the Voucher tab to add vouchers to the transaction.
5.Billing & Summary: The system automatically calculates the subtotal, tax, and final total. If shipping is required, a dedicated form allows the user to add shipping costs to the final amount.
6.Payment: The user enters payment details. The system tracks the balance owed and calculates any change due.
7.Finalization: Once all details are confirmed, the user clicks "Save." The system validates that the required fields (Customer, Salesperson, and Register) are present before submitting the transaction.
1.3Key Concepts
–Searchable Dropdowns: Fields that allow users to type a few characters to quickly find and select specific items, customers, or vouchers from the database.
–Auto-Calculation: A feature where the system performs math (like multiplying quantity by price or summing totals) in real-time, reducing manual entry errors.
–Required Fields: Essential information (Customer, Salesperson, Register) that must be provided before a sale can be finalized.
–Modal: A pop-up window that allows the user to perform a secondary task (like creating a new customer) without leaving the main sales screen.
–Read-Only Fields: Information displayed on the screen that is automatically filled by the system and cannot be manually edited by the user.
1.4Business Value
–Efficiency: By automating price lookups and total calculations, staff can process transactions faster, reducing wait times for customers.
–Data Accuracy: Centralizing the entry of sales, customer, and inventory data ensures that records are consistent and reliable for reporting.
–Flexibility: The ability to handle both standard product sales and voucher redemptions in one transaction simplifies the workflow for retail staff.
–Operational Control: Requiring specific fields like "Salesperson" and "Register" ensures that every transaction is properly attributed, which is critical for performance tracking and cash management.
2.  Logic
2.1Overview

The "Add Sales" feature provides a streamlined interface for retail staff to record transactions within the Lumi ERP system. It allows users to capture essential sale details—such as the customer, the salesperson, the register used, and the specific items sold—and save them directly to the system. The feature is designed to be intuitive, using searchable dropdowns to quickly find and link relevant information like customers, vehicles, and payment methods.

2.2Step-by-Step Flow
1.Initialization: When the sales page loads, the system automatically retrieves and populates dropdown lists for Salespeople, Registers, and Payment Types so that staff can select the correct options immediately.
2.Data Entry: The user fills out the sale details. This includes searching for and selecting a customer, assigning a salesperson, choosing a register, and adding items to the sale. Optional information, such as vehicle details, promo codes, or sales notes, can also be added.
3.Validation: When the user clicks "Save," the system performs a mandatory check to ensure that a Customer, Salesperson, and Register have been selected. If any of these are missing, the system will prevent the sale from being saved.
4.Submission: Once validated, the system bundles all the entered information—including itemized products, discounts, taxes, and payment details—into a single record and sends it to the system database.
5.Confirmation: Upon a successful save, the system confirms the transaction by generating a unique sale ID and timestamp.
2.3Key Concepts
–Searchable Dropdowns: Interactive fields that allow users to type a few characters to quickly filter and select specific records (like customers or vehicles) from the database.
–Mandatory Fields: Essential information required to complete a transaction; the system will not allow a sale to be finalized without a Customer, Salesperson, and Register.
–Payment Mapping: The process of linking a specific payment method (e.g., cash, card, or voucher) to the amount paid, ensuring the financial record of the sale is accurate.
–Itemized Sales: The ability to list multiple products within a single transaction, with the system automatically calculating subtotals, discounts, and taxes for each line item.
2.4Business Value

This feature centralizes retail sales operations, ensuring that every transaction is accurately recorded with the necessary accountability (who sold it and where). By automating the lookup of users, stores, and payment types, it reduces manual data entry errors and speeds up the checkout process. Furthermore, by capturing detailed information like vehicle associations and ecommerce references, the business gains better visibility into sales trends and customer history, supporting more informed decision-making.

3.  Data
3.1Overview

The "Add Sales" feature allows retail staff to record new transactions within the Lumi ERP system. This functionality captures the essential details of a sale—such as who made the purchase, which staff member processed it, and which cash register was used—ensuring that every transaction is accurately logged and linked to the specific items sold.

3.2Step-by-Step Flow
1.Validation: The system checks that the essential information is provided, specifically the customer, the salesperson, and the cash register. If any of these are missing, the system will prevent the sale from being saved.
2.Transaction Initiation: Once the data is validated, the system begins a secure recording process to ensure all parts of the sale are saved together as a single unit.
3.Recording the Sale Header: The system creates a primary record for the transaction, which includes the total amount and the exact time the sale occurred.
4.Recording Sale Items: The system then logs each individual product included in the transaction, linking them to the primary sale record created in the previous step.
5.Finalization: Once all items are successfully recorded, the system confirms the transaction is complete and provides a unique reference ID for the sale.
3.3Key Concepts
–Sale Header: The main record of a transaction that captures the "who, where, and when" of the purchase.
–Sale Items: The individual line items within a transaction, detailing which specific products were bought, in what quantity, and at what price.
–Transactional Integrity: A safety mechanism that ensures that if any part of the sale fails to save, the entire transaction is rolled back to prevent incomplete or corrupted data.
–Validation: A mandatory check performed by the system to ensure that critical information is present before allowing the record to be created.
3.4Business Value

This feature provides a reliable foundation for retail operations by ensuring that all store sales are captured consistently. By linking sales to specific staff members and registers, the business gains better visibility into store performance and accountability. Furthermore, the structured data collection allows for accurate reporting and tracking of product movement, which is essential for maintaining healthy inventory levels and understanding customer purchasing habits.
