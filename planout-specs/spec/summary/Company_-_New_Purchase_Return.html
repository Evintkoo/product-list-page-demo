1.  Frontend
1.1Overview

The "New Purchase Return" feature provides a streamlined way for users to process returns for items previously purchased by the company. By selecting an existing invoice, the system automatically pulls in the relevant order details, allowing users to specify the quantity to be returned and the reason for the return. The system handles all financial calculations—such as subtotals, taxes, and discounts—automatically to ensure accuracy before the return is finalized.

1.2Step-by-Step Flow
1.Initiate Return: The user selects the "Return" type from the required dropdown menu.
2.Select Supplier and Invoice: The user chooses a supplier, then searches for the specific invoice (requiring at least 3 characters).
3.Auto-fill Details: Once the invoice is selected, the system automatically populates the associated Purchase Order, Purchase Delivery reference, and the list of items included in that original purchase.
4.Adjust Quantities and Reasons: For each item in the list, the user enters the quantity to be returned (which cannot exceed the original amount purchased) and provides a reason for the return.
5.Review Financials: The system calculates the subtotal, applies any entered discounts (automatically formatted for consistency), and adds the applicable tax to display a final total.
6.Save and Finalize: Upon clicking "Save," the system validates all entries and submits the data. If successful, the user is redirected to the Purchase Return list page.
1.3Key Concepts
–Invoice Search: A security and efficiency measure that requires a minimum of 3 characters to find an invoice, ensuring the user selects the correct document linked to a specific supplier.
–Auto-fill Logic: The system automatically retrieves and displays related data (like Purchase Orders and Delivery references) based on the invoice selection to reduce manual data entry and errors.
–Validation Rules: Built-in checks that prevent invalid data, such as ensuring return quantities do not exceed the original invoice amounts.
–Dynamic Calculations: The system continuously updates the financial summary (subtotal, tax, and total) as items are added, removed, or quantities are adjusted.
–Data Formatting: Automatic adjustment of discount entries to ensure financial records remain consistent and professional.
1.4Business Value

This feature reduces manual administrative work and minimizes human error by automating the retrieval of purchase history and financial calculations. By enforcing strict validation on return quantities and requiring specific reasons for returns, the company maintains better inventory accuracy and clearer audit trails for all returned goods. This leads to faster processing times and more reliable reporting for the inventory management team.

2.  Logic
2.1Overview

The "New Purchase Return" feature allows users to formally record the return of items to a supplier. This process ensures that inventory records are updated accurately and financial adjustments—such as subtotals, discounts, and taxes—are calculated automatically based on the items being returned.

2.2Step-by-Step Flow
1.Form Initialization: The user begins by selecting the supplier and the specific invoice associated with the return. The system automatically populates related details like the Purchase Order and delivery information.
2.Item Selection: The system displays the products from the selected invoice. The user specifies the quantity to be returned for each item and provides a reason for the return.
3.Automatic Calculation: As the user enters quantities and applies any discounts, the system instantly calculates the subtotal, tax, and final total for the return document.
4.Validation: Before submission, the system ensures all mandatory information (such as the return type, supplier, and invoice) is present.
5.Submission: Once the user clicks the save button, the system processes the return, saves the data, and redirects the user to the main list of purchase returns.
2.3Key Concepts
–Purchase Return: A formal document used to track goods sent back to a supplier, ensuring the company’s inventory and financial records remain in sync.
–Invoice Linking: By selecting an existing invoice, the system pulls in pre-verified product data and pricing, reducing manual entry errors.
–Automated Financials: The system handles the math for subtotals, tax applications, and discounts, ensuring the final return value is always accurate.
–Return Reason: A required field for each item that provides auditability and insight into why goods are being returned (e.g., damaged, incorrect item).
2.4Business Value
–Accuracy: Automating the calculation of totals and taxes eliminates manual math errors.
–Efficiency: Linking returns to existing invoices saves time by auto-filling product details and purchase order information.
–Audit Readiness: By requiring reasons for returns and maintaining a clear link to original invoices, the business maintains a transparent and reliable audit trail for all inventory adjustments.
3.  Data
3.1Overview

The "New Purchase Return" feature allows your team to formally record the return of goods to a supplier. This process is integrated with your existing invoice system, ensuring that return records are accurate, linked to original purchase documents, and validated against previous transactions to prevent errors.

3.2Step-by-Step Flow
1.Initiation: You select an existing invoice to start the return process. The system automatically pulls in relevant details, such as the associated purchase order, delivery information, and the list of products from that invoice.
2.Data Entry: You fill out the return form, including the supplier, the warehouse where the goods are being returned from, and any optional reference numbers or notes.
3.Item Selection & Validation: You specify the quantity of each product being returned and provide a reason for the return. The system automatically checks that the return quantity does not exceed the amount originally purchased on the invoice.
4.Financial Calculation: The system automatically calculates the subtotal, applies any discounts, adds the appropriate tax, and displays the final total for the return.
5.Submission: Once submitted, the system generates a unique document number for the return and saves the record, linking it to the original invoice and purchase order for full traceability.
3.3Key Concepts
–Invoice Linking: Every return is tied to a specific invoice, which ensures that the return is based on verified historical data.
–Quantity Validation: A built-in safeguard that prevents users from returning more items than were originally received, maintaining inventory integrity.
–Automated Calculations: The system handles the math for subtotals, taxes, and discounts, reducing the risk of manual entry errors.
–Traceability: By generating a unique document number and linking to the original purchase order, the system creates a clear audit trail for every return.
3.4Business Value
–Accuracy: By auto-populating data from invoices and validating quantities, the feature eliminates manual data entry errors and prevents over-returning of stock.
–Efficiency: Staff spend less time manually calculating totals or looking up purchase details, as the system handles these tasks automatically.
–Compliance & Auditability: Maintaining a formal, linked record of all returns ensures your inventory and financial reporting remain transparent and easy to audit.
