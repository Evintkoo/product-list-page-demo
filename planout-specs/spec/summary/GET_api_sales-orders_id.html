1.  Logic
1.1Overview

This feature provides a secure way for the system to retrieve the full details of a specific sales order. When a user views a sales order in the Lumi ERP, this function fetches the order's core information—such as its current status and creation date—along with a list of all items included in that order. The system is designed to ensure that users can only access orders belonging to their own company, maintaining strict data privacy and security.

1.2Step-by-Step Flow
1.Authentication Check: The system verifies that the user is logged in and identifies which company they belong to. If the user is not logged in, the request is denied.
2.Order Retrieval: The system searches for the specific sales order using the provided ID. It applies a filter to ensure the order belongs to the user's company and is a standard sales order (excluding wholesale store orders).
3.Validation: If the order cannot be found—either because it doesn't exist or because it belongs to a different company—the system returns a "Not Found" error.
4.Item Collection: Once the order is located, the system gathers all the individual line items associated with that specific order.
5.Data Delivery: The system compiles the order details and the list of items into a single report and sends it back to the user's screen.
1.3Key Concepts
–Authentication: The process of confirming the user's identity and company affiliation to ensure they have permission to view the requested data.
–Data Scoping: A security measure that automatically filters information so that users only see records relevant to their own organization.
–Line Items: The individual products, quantities, and prices that make up a single sales order.
–Order Status: A label (such as "Draft," "Approved," or "Delivered") that tells the system which version of the order screen to display to the user.
1.4Business Value

This feature is essential for the daily operations of the sales team. By providing a reliable and secure way to pull up order details, it allows staff to quickly check the status of a customer's request and review the specific items ordered. Because the system automatically handles security and filtering, it reduces the risk of data leaks between companies and ensures that users only interact with the information they are authorized to see.

2.  Data
2.1Overview

This feature provides a way for users to view the specific details of a sales order. When a user requests a sales order by its unique ID, the system retrieves the order information along with its associated line items (such as product names, quantities, and prices). The feature is designed to be secure, ensuring that users can only access orders belonging to their own company.

2.2Step-by-Step Flow
1.Session Validation: The system checks if the user is logged in and has a valid company session. If the session is missing or invalid, the request is rejected.
2.Data Retrieval: The system searches for the requested sales order. It strictly filters the search to ensure the order belongs to the user's company and is a standard sales order (excluding wholesale store orders).
3.Verification: If the order is not found—either because it doesn't exist or because it belongs to a different company—the system returns a "Not Found" error.
4.Item Collection: If the order is found, the system gathers all individual line items associated with that specific order.
5.Response: The system compiles the order details (status, creation date) and the list of items into a structured format and sends it back to the user.
2.3Key Concepts
–Multi-tenancy: A security practice that ensures data is isolated; users can only view information that belongs to their specific company.
–Sales Order Header: The primary record containing high-level information about the order, such as its current status and creation date.
–Line Items: The individual products, quantities, and prices that make up the contents of a sales order.
–Scope Filtering: A rule that automatically excludes certain types of data (in this case, wholesale store orders) from the search results to ensure the user only sees relevant business transactions.
2.4Business Value

This feature enables the Sales Order detail page to function correctly by providing accurate, real-time data. By enforcing strict security and filtering rules, it protects sensitive company data while ensuring that sales teams can quickly access the specific order information they need to manage their workflows, such as checking order status or reviewing itemized lists.
