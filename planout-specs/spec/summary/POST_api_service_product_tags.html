1.  Logic
1.1Overview

This feature introduces a new way to create "Service Product Tags" within the Lumi ERP system. These tags help categorize and organize service products. This functionality is designed to be flexible, supporting both quick-add actions (such as creating a tag directly while editing a product) and standard administrative tasks on the main Tags management page.

1.2Step-by-Step Flow
1.Authentication Check: The system verifies that the user is logged in and authorized to perform the action.
2.Data Validation: The system checks that a name has been provided for the tag and that it is formatted correctly.
3.Uniqueness Verification: The system checks the existing list of tags to ensure the new name is not a duplicate.
4.Data Storage: If all checks pass, the system saves the new tag to the database with a unique identifier and a timestamp.
5.Confirmation: The system returns the details of the newly created tag (including its unique ID) so the user interface can immediately update to show the new tag.
6.Error Handling: If any step fails—such as an invalid name, a duplicate entry, or a system error—the user receives a clear message explaining why the tag could not be created.
1.3Key Concepts
–Service Product Tag: A label used to categorize service products, making them easier to find and manage.
–Validation: The process of ensuring the information provided by the user meets the system's requirements (e.g., ensuring a name is not blank).
–Uniqueness Constraint: A business rule that prevents the system from having two tags with the exact same name, ensuring data remains clean and organized.
–Unique Identifier (ID): A permanent, system-generated code assigned to each tag to distinguish it from others, even if they have similar names.
1.4Business Value

By providing a standardized way to create tags, this feature improves data consistency across the ERP. It streamlines the user experience by allowing staff to create new categories on the fly without leaving their current workflow, ultimately saving time and reducing the administrative burden of managing service product catalogs.

2.  Data
2.1Overview

This feature introduces a new way to create "Service Product Tags" within the Lumi ERP system. These tags help organize and categorize service products. This functionality is designed to be flexible, allowing users to create new tags on the fly—whether they are working within a specific service product form or managing the master list of tags in the system settings.

2.2Step-by-Step Flow
1.Request Submission: The user initiates the creation of a new tag (e.g., by clicking "Save" in a "New Tag" modal).
2.Validation: The system checks that the request is properly formatted and that the required "Name" field is provided.
3.Uniqueness Check: The system verifies that a tag with the requested name does not already exist to prevent duplicate entries.
4.Persistence: If the name is unique and valid, the system saves the new tag to the database, automatically assigning it a unique identifier and a creation timestamp.
5.Confirmation: The system returns the newly created tag details (including its unique ID) to the user interface, allowing the application to immediately update dropdown menus or lists without requiring a page refresh.
2.3Key Concepts
–Service Product Tag: A label used to categorize service products for better organization and reporting.
–Uniqueness Constraint: A rule ensuring that no two tags share the exact same name, keeping the system organized and preventing confusion.
–Unique Identifier (ID): A permanent, system-generated code assigned to each tag to ensure it can be reliably tracked and referenced by the software.
–Validation: The process of ensuring the information provided by the user meets the necessary requirements before it is saved to the database.
2.4Business Value
–Improved Efficiency: Users can create new tags directly within the workflow (e.g., while editing a product), eliminating the need to navigate away to a separate settings page.
–Data Integrity: By enforcing unique names, the system prevents the creation of duplicate or ambiguous categories, ensuring clean and reliable reporting.
–Seamless User Experience: Because the system returns the new tag information immediately upon creation, the user interface can update dynamically, providing a smooth and responsive experience.
