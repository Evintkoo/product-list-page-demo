1.  Logic
1.1Overview

This feature provides a simple way to update the "active" status of a customer within the Lumi ERP system. By sending a request to the system, authorized users can toggle a customer between active and inactive states. The system automatically records who performed the update and when it occurred, ensuring an accurate audit trail for customer management.

1.2Step-by-Step Flow
1.Validation: The system checks that the request includes a valid customer identifier and a clear "active" or "inactive" status.
2.Authentication: The system verifies that the person making the request is logged in and authorized to perform updates.
3.Verification: The system searches the database to ensure the specific customer exists.
4.Update: If the customer is found, the system updates their status, logs the ID of the user who made the change, and records the current date and time.
5.Confirmation: The system returns a success message confirming the customer's ID, their new status, and the timestamp of the update.
1.3Key Concepts
–Active Status: A true/false setting that determines if a customer is currently considered active in the system.
–Authentication: A security check to ensure only verified users can modify customer records.
–Audit Trail: The automatic recording of the user who performed the update and the exact time it happened, which is essential for tracking changes.
–Validation: A safety check to ensure the information sent to the system is in the correct format before processing begins.
1.4Business Value

This feature improves data integrity and operational efficiency by allowing staff to quickly manage customer availability. By automating the "updated by" and "updated at" fields, the business maintains a reliable history of account changes, which is critical for reporting, compliance, and troubleshooting customer account issues.

2.  Data
2.1Overview

This feature provides a way to update the "active" status of a customer record within the Lumi ERP system. By using this tool, authorized users can toggle a customer's status (e.g., marking them as active or inactive) without needing to modify other customer details. The system automatically tracks who performed the update and when it occurred to ensure accurate record-keeping.

2.2Step-by-Step Flow
1.Request Initiation: A user sends a request to update a specific customer, identifying them by their unique ID.
2.Validation: The system checks the request to ensure the new status is provided in the correct format (a simple true/false value).
3.Processing: If the request is valid, the system locates the customer record and updates their status, records the ID of the user who made the change, and logs the current date and time.
4.Confirmation: Once the update is saved, the system returns a confirmation containing the customer's ID, their new status, and the timestamp of the update.
5.Error Handling: If the customer cannot be found, the request is invalid, or the user lacks proper authorization, the system will return an appropriate error message instead of performing the update.
2.3Key Concepts
–Customer Status: A simple "on/off" (boolean) setting that determines if a customer is currently active in the system.
–Audit Trail: The automatic recording of the "updater ID" and "updated at" timestamp, which provides accountability for every change made to a customer's status.
–Validation: A safety check that ensures the information sent to the system is formatted correctly before any changes are applied to the database.
–Unique Identifier: A specific code used to ensure the system updates the correct customer record every time.
2.4Business Value

This feature streamlines customer management by allowing for quick, targeted updates to customer status. By automating the audit trail (tracking who changed what and when), the business maintains better data integrity and compliance, reducing the manual effort required to keep customer records current and accurate.
