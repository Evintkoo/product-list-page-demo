1.  Frontend
1.1Overview

The "New Retail Customer" feature provides a dedicated interface for staff to register new retail clients within the Lumi ERP system. This page streamlines data entry by grouping information into logical sections—such as user details, tax information, and address management—ensuring that all necessary information is captured accurately before the customer record is created.

1.2Step-by-Step Flow
1.Access & Authentication: Upon opening the page, the system verifies that the user is logged in. If the session is invalid, the user is redirected to the login screen.
2.Initialization: The system automatically loads default settings and populates necessary dropdown menus specifically configured for retail customers.
3.Data Entry: The user fills out the customer’s profile, including personal details, tax information, and reporting settings.
4.Address Management: The user can add one or more addresses via a dedicated pop-up window. These addresses are held in a temporary list on the screen and are not saved to the database until the final submission.
5.Validation & Submission: When the user clicks "Save," the system validates that all required fields are present and ensures at least one address is designated as the "Main Address."
6.Completion: Once validated, the system sends the complete customer profile to the database. Upon a successful save, the user is automatically navigated to the new customer's profile page.
1.3Key Concepts
–Retail Customer Type: A specific classification for customers that ensures the system applies the correct business rules and default settings during registration.
–Temporary Address List: A feature that allows users to compile multiple addresses (e.g., billing, shipping, or home) in a list before finalizing the customer record.
–Main Address: A mandatory designation for at least one address in the list, which the system uses as the primary contact point for the customer.
–Form Validation: An automated check performed by the system to ensure that critical information (such as names, emails, and required phone numbers) is provided before the record can be created.
1.4Business Value
–Data Integrity: By enforcing validation rules and requiring a "Main Address," the system prevents incomplete or unusable customer records from entering the database.
–Operational Efficiency: The intuitive, tabbed, or card-based layout allows staff to quickly navigate and input complex customer data without feeling overwhelmed.
–Seamless Workflow: By handling the creation of the customer and their associated addresses in a single action, the system reduces the time spent on manual data entry and minimizes the risk of synchronization errors.
2.  Logic
2.1Overview

The "New Retail Customer" feature allows users to efficiently add a new retail-type customer to the Lumi ERP system. The process is designed to be seamless, allowing users to input customer contact details and multiple associated addresses in a single session. The system automatically categorizes these entries as "retail," ensuring consistency across the database.

2.2Step-by-Step Flow
1.Access and Validation: When the page loads, the system verifies that the user is logged in. If the session is valid, it retrieves the necessary default settings and dropdown options to prepare the empty form.
2.Data Entry: The user fills out the customer’s name and email. Using the "Addresses Card," the user can add one or more addresses, specifying details like phone numbers, fax, and whether the address serves as the main or shipping location.
3.Submission: Once the user clicks the "Save" button, the system bundles the customer information and all listed addresses into a single request.
4.Processing: The system automatically tags the entry as a "retail" customer and sends the data to the database.
5.Outcome:

* Success: If the data is valid, the system creates the customer record and automatically redirects the user to the new customer's profile page.

* Failure: If an error occurs, the system keeps the user on the current page and preserves all entered information, allowing the user to correct mistakes and try again without losing their work.

2.3Key Concepts
–Retail Classification: A background setting that automatically labels the new entry as a "retail" customer, removing the need for the user to manually select a customer type.
–Addresses Card: A dedicated section of the form that manages a list of addresses, allowing for multiple locations to be attached to a single customer record before saving.
–State Preservation: A safety feature that ensures form data is not cleared if a submission fails, preventing data loss and reducing user frustration.
–Session Security: An automated check that ensures only authorized users can access the customer creation form, redirecting unauthorized users to the login screen.
2.4Business Value

This feature streamlines the onboarding of new retail clients by centralizing data entry. By allowing users to define multiple addresses (such as billing or shipping) during the initial creation process, the system reduces the need for follow-up edits. Furthermore, the "state preservation" logic improves user productivity by ensuring that minor input errors do not result in the loss of time-consuming data entry.

3.  Data
3.1Overview

The "New Retail Customer" feature allows staff to efficiently add individual retail customers to the Lumi ERP system. This process captures essential contact information and multiple address details (such as billing or shipping locations) in a single, streamlined action. The system ensures data integrity by processing the customer profile and their associated addresses together as one complete unit.

3.2Step-by-Step Flow
1.Initialization: When the page loads, the system retrieves necessary configuration data, such as available address types (e.g., billing, shipping, home), to populate the form fields.
2.Data Entry: The user fills out the customer’s profile and adds one or more addresses using the "Addresses Card" interface.
3.Submission: Upon clicking the "Save" button, the system validates the information provided to ensure it meets all requirements.
4.Processing: The system creates a new customer record marked as "retail" and simultaneously links all provided address details to that specific customer.
5.Confirmation: Once the data is successfully saved, the system confirms the creation and navigates the user to the new customer’s profile page. If an error occurs, the system retains the entered information so the user can make corrections without losing their work.
3.3Key Concepts
–Retail Customer: A specific classification of customer within the ERP, automatically applied to all entries made through this feature.
–Address Card: A flexible section of the form that allows users to associate multiple locations with a single customer, including specific contact numbers and fax details for each location.
–Transaction: A safety mechanism that ensures the customer profile and their addresses are saved together; if one part fails, the entire process is rolled back to prevent incomplete or "orphaned" data.
–Validation: An automated check performed before saving to ensure all required fields are correctly formatted, preventing errors from entering the database.
3.4Business Value

This feature simplifies the onboarding of retail clients by providing a dedicated, intuitive interface that eliminates manual data entry errors. By grouping customer profiles with their associated contact and location details, the system maintains a clean and organized database. This structure ensures that downstream processes—such as shipping, billing, and customer support—have immediate access to accurate, comprehensive information, ultimately improving operational efficiency and customer service.
