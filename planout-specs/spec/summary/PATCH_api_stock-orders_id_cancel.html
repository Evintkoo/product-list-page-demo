1.  Logic
1.1Overview

This feature provides a way to cancel an existing stock order within the Lumi ERP system. By using this endpoint, users can transition an order that is no longer needed into a "cancelled" state. This action is final, ensuring that the order's history is accurately tracked while maintaining the integrity of the inventory records.

1.2Step-by-Step Flow
1.Request Initiation: The system receives a request to cancel a specific stock order identified by its unique ID.
2.Validation: The system verifies that the order exists and belongs to the user's company.
3.Status Check: The system confirms the order is currently in a "draft" or "confirmed" state. If the order is already in another state (such as already cancelled or completed), the request is rejected.
4.Processing: If valid, the system updates the order status to "cancelled" and records the user who performed the action.
5.History Logging: Simultaneously, the system creates a permanent record in the order's history log to document the cancellation.
6.Confirmation: The system returns a success response containing the updated order details, including the new status and the time of the update.
1.3Key Concepts
–Stock Order: A formal request for inventory movement within the ERP system.
–Workflow State: The current phase of an order (e.g., draft, confirmed, or cancelled).
–Terminal State: A status that cannot be changed further; once an order is "cancelled," it cannot be reopened.
–Transaction: A safety mechanism that ensures both the order update and the history log entry are saved together; if one fails, the entire process is rolled back to prevent data inconsistencies.
–Ownership Validation: A security check that ensures users can only modify orders belonging to their own company.
1.4Business Value
–Operational Accuracy: Prevents accidental or unauthorized modifications to orders that have already progressed beyond the cancellation window.
–Audit Readiness: By automatically logging the cancellation in the history table, the system provides a clear trail of who cancelled an order and when, which is essential for inventory reporting and accountability.
–Process Discipline: Enforces a strict workflow where cancelled orders are treated as final, encouraging users to create new, accurate orders rather than attempting to modify invalid ones.
2.  Data
2.1Overview

This feature provides a way to cancel an existing stock order within the Lumi ERP system. When a user triggers this action, the system updates the order's status to "cancelled" and creates a permanent record of this change in the system's history. This process is designed to be safe and reliable, ensuring that only valid orders can be cancelled and that every cancellation is tracked for auditing purposes.

2.2Step-by-Step Flow
1.Locate and Secure: The system identifies the specific stock order requested and locks it to ensure no other changes can happen while the cancellation is being processed.
2.Verify Existence: The system checks if the order actually exists and confirms that it belongs to the company making the request.
3.Validate Status: The system checks the current state of the order. Only orders that are currently in "draft" or "confirmed" status are eligible for cancellation.
4.Update Status: If valid, the system updates the order status to "cancelled," records who performed the action, and updates the timestamp.
5.Log History: Simultaneously, the system adds an entry to the order's history log to maintain a clear audit trail of the status change.
6.Finalize: The transaction is completed, and the updated order details are returned to the user.
2.3Key Concepts
–Atomic Transaction: A "all-or-nothing" process where the status update and the history log entry must both succeed together; if one fails, the entire action is cancelled to prevent data errors.
–Terminal State: Once an order is marked as "cancelled," it cannot be changed again. If a user still needs the items, they must create a brand-new stock order.
–Workflow History: A dedicated record that tracks the lifecycle of an order, providing transparency on when and by whom changes were made.
–Validation: Built-in safeguards that prevent the system from processing invalid requests, such as trying to cancel an order that doesn't exist or one that has already been processed.
2.4Business Value

This feature improves inventory management by providing a clean, controlled way to handle cancelled orders. By enforcing strict rules on which orders can be cancelled, the system prevents accidental data loss and ensures that inventory records remain accurate. Furthermore, the automatic logging of these cancellations provides a reliable audit trail, which is essential for operational transparency and accountability.
