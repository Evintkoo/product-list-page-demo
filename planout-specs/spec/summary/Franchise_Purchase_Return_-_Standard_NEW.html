1.  Frontend
1.1Overview

The "Franchise Purchase Return" feature allows users to initiate a return of products from a franchise store back to a supplier. This process is designed to be simple and controlled, ensuring that returns are accurately documented and do not exceed the quantities originally ordered or currently held in stock.

1.2Step-by-Step Flow
1.Initialization: When opening the page, the system automatically loads available store locations and internal suppliers to populate the selection menus. A unique document number is also generated for the return.
2.Header Information: The user selects the "Return From" location (the store) and the "Return To Supplier" location. Optionally, the user can link the return to a specific previous purchase order, add a reference number, and include any relevant notes.
3.Item Selection: Once the return context is set, the system displays the relevant products. Key details—such as current store quantity, original order quantity, and the maximum allowed return quantity—are automatically populated and locked to prevent manual errors.
4.Return Details: For each item, the user enters the specific quantity they wish to return and provides a reason for the return. The system validates that the return quantity does not exceed the maximum allowed limit.
5.Submission: Upon clicking "Save," the system processes the data and creates the return record. The user is then automatically redirected to the details page for that specific return, where it is marked as a "Draft."
6.Cancellation: If the user decides not to proceed, they can click "Cancel" to discard all changes and return to the main list page.
1.3Key Concepts
–Document Number: A unique, system-generated identifier for the return, formatted to include the warehouse location and date for easy tracking.
–Maximum Return Quantity: A safety limit calculated by the system to ensure that users cannot return more items than were originally ordered or are currently available in the store.
–Draft Status: The initial state of a new return, indicating that the record has been created but is still in the early stages of the approval workflow.
–Validation: Automated checks that ensure required fields are filled and that return quantities remain within permissible limits before the data is saved.
1.4Business Value

This feature streamlines the inventory management process by providing a standardized way to handle returns. By automating the population of product data and enforcing strict quantity limits, it reduces the risk of manual entry errors and ensures that all returns are properly linked to existing purchase records. This creates a clear audit trail and helps maintain accurate inventory levels across the franchise network.

2.  Logic
2.1Overview

The "Franchise Purchase Return" feature allows users to initiate a formal return of items previously purchased by a franchise. This process ensures that inventory adjustments are tracked accurately by linking the return to specific stores, suppliers, and original purchase orders. The system provides a structured form to capture return details, validate quantities, and document the reason for the return, ultimately creating a draft record for further processing.

2.2Step-by-Step Flow
1.Access & Initialization: When a user opens the page, the system verifies their identity. If authorized, it prepares a new, unique form and populates dropdown menus with available store locations and internal suppliers.
2.Form Completion: The user fills out the return header (e.g., which store is returning the items, which supplier is receiving them, and optional reference numbers or notes).
3.Order Linking: If applicable, the user can search for and select a specific original purchase order. The system helps narrow down results based on the selected store and supplier once the user types at least three characters.
4.Item Entry: The user adds items to the return, specifying the quantity to be returned and the reason for the return. The system ensures these entries stay within allowed limits (such as the maximum returnable quantity).
5.Submission: Upon clicking "Save," the system bundles all information—including header details and the list of items—and sends it to the database.
6.Confirmation: Once successfully saved, the user is automatically redirected to a details page where the return is displayed in a "Draft" status, allowing for final review or further action.
2.3Key Concepts
–Franchise Purchase Return: A formal document used to track inventory being sent back from a franchise location to a supplier.
–Draft Status: The initial state of a new return, indicating that the record has been created in the system but is still open for review or modification before final processing.
–Source Order: An optional link to the original purchase transaction, which helps the system validate return quantities and maintain a clear audit trail.
–On-Demand Search: A feature that fetches specific purchase order data only when needed (after typing three characters), keeping the interface fast and responsive.
2.4Business Value
–Inventory Accuracy: By requiring specific return reasons and linking to original orders, the business maintains precise control over stock levels and reduces discrepancies.
–Operational Efficiency: The automated lookup of stores and suppliers, combined with the ability to search for purchase orders, minimizes manual data entry and reduces the risk of human error.
–Audit Readiness: Every return is assigned a unique document number and saved as a draft, ensuring that all returns are documented and traceable from the moment they are initiated.
3.  Data
3.1Overview

The "Franchise Purchase Return" feature provides a standardized way for users to record the return of items from a franchise store back to a supplier. This digital form ensures that all necessary details—such as the origin of the return, the destination supplier, the original purchase order, and specific item quantities—are captured accurately and saved into the system.

3.2Step-by-Step Flow
1.Page Initialization: When a user opens the page, the system verifies their access permissions. It then automatically loads the available list of stores and internal suppliers to populate the "Return From" and "Return To Supplier" dropdown menus.
2.Form Entry: The user selects the store initiating the return and the supplier receiving the goods.
3.Order Search: If the return is linked to a specific purchase, the user can search for the original Franchise Purchase Order. The system will suggest relevant orders once the user types at least three characters, filtering results based on the selected store and supplier.
4.Item Details: The user enters the specific products being returned, including the quantities (current store stock vs. the amount being returned) and the reason for the return.
5.Submission: Once the user completes the form and clicks "Save," the system bundles all the information—including header details and the list of items—and submits it to the database to finalize the return record.
3.3Key Concepts
–Return From: The specific store location that is sending the items back.
–Return To Supplier: The internal supplier designated to receive the returned items.
–Franchise Purchase Order: An optional reference to the original order, which helps the system track the history of the items being returned.
–On-Demand Search: A feature that only retrieves purchase order data after the user provides enough input (3+ characters), ensuring the system remains fast and responsive.
–Return Items: The individual line items within the return, which track specific product quantities and the reason for each return.
3.4Business Value

This feature streamlines inventory management by replacing manual or informal return processes with a structured digital workflow. By linking returns to specific stores, suppliers, and original purchase orders, the business gains better visibility into inventory movement, improves the accuracy of stock records, and creates a clear audit trail for all franchise-related returns.
