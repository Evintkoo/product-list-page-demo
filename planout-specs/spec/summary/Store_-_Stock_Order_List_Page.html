1.  Frontend
1.1Overview

The Store Stock Order List page provides a centralized view for users to manage and track inventory stock orders. This page allows users to browse all existing stock orders, apply specific filters to narrow down results, and navigate to detailed views for individual orders. It is designed to ensure that only authorized users can access the inventory data.

1.2Step-by-Step Flow
1.Authentication Check: Upon loading the page, the system verifies the user's session. If the user is not logged in, they are automatically redirected to the login page.
2.Initial Data Load: Once authenticated, the page automatically fetches and displays a list of all stock orders.
3.Applying Filters: Users can refine the list using several criteria, including the Stock Order reference code, date ranges (From/To), specific stores, warehouses, or order statuses.
4.Executing Search: After setting the desired filters, the user clicks the "Search" button. The system then retrieves only the records that match the selected criteria.
5.Viewing Results: The results are displayed in a table format, showing key details such as the order date, status, store, warehouse, and financial amounts.
6.Navigation: Users can click on any row in the table to view the full details of a specific stock order, or click the "New Stock Order" button to begin creating a new request.
1.3Key Concepts
–Filter-to-API Mapping: The system translates user-friendly filter selections (like "Store" or "Status") into specific data parameters that the database understands to fetch the correct records.
–Starts-with Matching: When searching by the Stock Order reference code, the system looks for matches that begin with the entered text, rather than searching for the text anywhere within the code.
–Status Badges: Visual indicators used in the table to quickly communicate the current state of an order (e.g., Draft, Confirmed, Received, or Cancelled).
–Sortable Columns: Users can click on table headers (such as Date or Status) to organize the list in ascending or descending order, making it easier to find specific information.
–Session Security: A mandatory background check that ensures only authenticated users can view or interact with sensitive inventory data.
1.4Business Value

This feature streamlines inventory management by providing a high-visibility dashboard for tracking stock movement between warehouses and stores. By offering robust filtering and sorting capabilities, it reduces the time staff spend searching for specific orders, improves accuracy in monitoring order statuses, and ensures that inventory workflows remain organized and transparent.

2.  Logic
2.1Overview

The Stock Order List page provides a centralized view for users to browse, search, and manage warehouse stock orders. This feature ensures that only authorized users can access the list and provides a structured table to track order details, statuses, and financial information.

2.2Step-by-Step Flow
1.Authentication Check: When a user navigates to the page, the system verifies their identity. If the user is not logged in, they are automatically redirected to the login screen.
2.Initial Data Load: Once authenticated, the system automatically fetches the first 20 stock orders to display in the table.
3.Applying Filters: Users can refine the list by entering specific criteria, such as order reference codes, date ranges, store or warehouse locations, and workflow statuses.
4.Search Execution: When the user clicks the "Search" button, the system sends a request to the server using only the active filters provided.
5.Table Update: The system receives the filtered results and updates the table, replacing the previous list with the new data.
6.Data Formatting: Each order is processed to ensure dates are readable, monetary values are formatted correctly, and status updates (such as "received" or "partially received") are clearly displayed as visual badges.
2.3Key Concepts
–Authentication: A security check that ensures only logged-in users can view sensitive inventory data.
–Filtering: The ability to narrow down a large list of orders based on specific attributes like date, location, or current status.
–Pagination: A method of displaying data in smaller, manageable chunks (e.g., 20 items at a time) to improve page performance.
–Workflow State: The current progress of an order (e.g., pending, received, or partially received), which helps users track the lifecycle of their stock.
–Mapping: The process of taking raw system data and translating it into a user-friendly table format with clear labels and formatted values.
2.4Business Value

This feature streamlines inventory management by providing a clear, searchable interface for tracking stock movement between warehouses and stores. By allowing users to quickly filter by status or date, the system reduces the time spent searching for specific orders, improves accuracy in monitoring order fulfillment, and ensures that financial data (such as order and receive amounts) is consistently visible and easy to interpret.

3.  Data
3.1Overview

The Stock Order List page provides a centralized view for users to browse, search, and manage stock orders within the Lumi ERP system. This feature allows users to quickly locate specific orders by applying various filters—such as order reference codes, date ranges, store or warehouse locations, and current workflow status—ensuring that inventory management remains organized and efficient.

3.2Step-by-Step Flow
1.Initialization: When the page loads, the system automatically verifies the user's session. If authorized, it fetches the initial list of stock orders.
2.Data Retrieval: The system requests data from the server, specifically filtering for "stock orders" to ensure only relevant records are retrieved.
3.Applying Filters: Users can refine the list by entering search criteria (like a reference code or date range) and clicking the "Search" button. The system sends these specific criteria to the server to narrow down the results.
4.Data Processing: Once the server returns the raw data, the system filters out any records that do not match the required "stock order" type and formats the information into a clean, readable layout.
5.Display: The processed data is populated into the Stock Order Table, allowing the user to view the relevant order details.
6.Updates: Any subsequent actions—such as changing filters, navigating through pages, or refreshing the view—trigger a new request to the server to update the table with the most current information.
3.3Key Concepts
–Stock Order: A specific type of inventory record that tracks the movement of goods between warehouses and stores.
–Filtering: The ability to narrow down a large list of orders based on specific criteria, such as date, location, or current status.
–Pagination: A method of breaking down a large list of records into smaller, manageable pages to improve performance and readability.
–Workflow State: The current stage of an order in its lifecycle (e.g., pending, in-transit, or received).
–Reference Code: A unique identifier used to track and locate a specific stock order document.
3.4Business Value

This feature streamlines inventory operations by providing a high-performance, searchable interface for stock management. By allowing users to filter and paginate through large volumes of data, the system reduces the time spent searching for specific orders, minimizes manual errors, and provides real-time visibility into the status of stock movements across the organization.
