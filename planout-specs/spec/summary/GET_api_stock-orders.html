1.  Logic
1.1Overview

The Stock Orders API feature provides a secure way for users to retrieve lists of stock orders within the Lumi ERP system. This feature is designed to support different views—such as Warehouse, Service Orders, and Work Orders—by filtering data based on the "source type" of the order. The system automatically ensures that users only see data belonging to their own company, maintaining strict data privacy.

1.2Step-by-Step Flow
1.Authentication: The system verifies the user's identity. If the user is not logged in or authorized, the request is rejected.
2.Parameter Validation: The system checks the request for the required "source type" (e.g., warehouse or service order). If this information is missing or invalid, the request is rejected.
3.Data Retrieval: The system searches the database for stock orders that match the requested source type, automatically limiting the results to the user's specific company.
4.Sorting and Pagination: The system organizes the results based on the user's preferred sorting criteria (defaulting to the newest items first) and breaks the list into manageable pages to ensure fast performance.
5.Response: The system returns the requested list of orders to the user. If no orders match the criteria, an empty list is returned.
1.3Key Concepts
–Source Type: A category label used to distinguish between different types of orders (e.g., Warehouse vs. Service Orders), allowing the interface to display the correct information on the appropriate tab.
–Pagination: A method of breaking large amounts of data into smaller, numbered pages to improve system speed and readability.
–Company Scoping: A security measure that automatically filters all database queries so that users only see records associated with their specific organization.
–Sorting: The ability to arrange the order list by specific criteria, such as the date the order was created. Note that some financial fields, like order amounts, cannot be used for sorting.
1.4Business Value

This feature enables efficient inventory management by allowing users to quickly find and organize stock orders across different operational areas. By providing a standardized, secure, and paginated way to access this data, the API ensures that the user interface remains responsive and that sensitive company information remains protected. It simplifies the user experience by allowing the application to dynamically switch between different order views using a single, reliable data source.

2.  Data
2.1Overview

The Stock Orders feature provides a way to retrieve and view lists of stock-related orders within the Lumi ERP system. It is designed to support different views (tabs) based on the origin of the order, such as warehouse stock, service orders, or work orders. The system automatically ensures that users only see data relevant to their own company, keeping information secure and organized.

2.2Step-by-Step Flow
1.Security Check: The system identifies the user's company and automatically restricts the search to only show orders belonging to that specific company.
2.Categorization: The system applies a filter based on the "source type" (e.g., Warehouse, Service, or Work Order) to ensure the correct list is displayed for the selected tab.
3.Search: If a search term is provided, the system narrows down the results by looking for matching order numbers.
4.Sorting: The system organizes the results. By default, it shows the newest orders first. Note that some financial fields cannot be used for sorting.
5.Pagination: To keep the interface fast and readable, the system breaks the results into manageable pages (defaulting to 20 items per page) and calculates the total number of available records.
6.Delivery: The system returns the requested list of orders along with summary information about the total count and current page.
2.3Key Concepts
–Source Type: A category label that determines which tab an order appears in, such as "Warehouse" or "Service Order."
–Company Scoping: An automatic security feature that ensures users only access data belonging to their own organization.
–Pagination: A method of displaying large amounts of data in smaller, easier-to-manage chunks rather than loading everything at once.
–Sorting Restrictions: Specific rules that prevent the system from organizing data by certain financial fields to maintain performance and data integrity.
2.4Business Value

This feature enables efficient inventory and order management by providing a clean, searchable, and organized view of all stock-related activities. By automatically filtering data by company and order type, it reduces manual effort for staff, prevents unauthorized data access, and ensures that users can quickly locate the specific order information they need to keep operations running smoothly.
