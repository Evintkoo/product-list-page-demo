1.  Frontend
1.1Overview

The Retail Customer Detail Page provides a comprehensive, read-only view of a specific customer's profile within the Lumi ERP system. This page acts as a central hub for staff to review all relevant information about a retail customer, including their contact details, tax status, internal business settings, and audit history, without the risk of accidental changes.

1.2Step-by-Step Flow
1.Page Initialization: When a user navigates to the page, the system identifies the specific customer using their unique ID from the web address.
2.Data Retrieval: The system automatically fetches the customer's full profile from the database.
3.Loading & Error Handling: While the data is being retrieved, a loading indicator is shown. If the customer cannot be found or if a system error occurs, the user is notified accordingly.
4.Displaying Information: Once the data is successfully loaded, the page populates several organized sections (cards) with the customer's information.
5.Navigation & Interaction: The user can use the navigation bar to move through the system or click the "Customers" button to return to the main list. A dedicated "Edit" button is available if the user needs to update the customer's information.
1.3Key Concepts
–Read-Only View: A display mode where information is presented for reference purposes only, ensuring data integrity by preventing accidental edits.
–Customer Cards: The page is organized into logical groupings (such as Tax Information, SAP Reporting, and Addresses) to make it easy for users to find specific data points quickly.
–Audit Trail: The "Changes" section tracks who created or updated the customer record and when, providing accountability and history.
–System Integration: The page displays specific fields (like SAP reporting values and tax identifiers) that are essential for syncing customer data with the company's broader financial and reporting systems.
1.4Business Value

This feature streamlines customer management by providing a "single source of truth" for retail customer data. By consolidating identity, tax, and internal business settings into one clear, accessible page, staff can quickly verify customer details during daily operations. This reduces the time spent searching for information across different systems and ensures that all departments—from sales to finance—are viewing consistent, accurate customer records.

2.  Logic
2.1Overview

The Retail Customer Detail page is designed to provide a comprehensive, read-only view of a specific customer's profile within the Lumi ERP system. When a user navigates to this page, the system automatically retrieves all relevant data associated with that customer and organizes it into logical sections for easy review.

2.2Step-by-Step Flow
1.Page Initialization: When you open the Retail Customer Detail page, the system identifies the specific customer by their unique ID.
2.Data Retrieval: The system automatically requests the full customer profile from the database.
3.Data Processing: Once the information is received, the system maps the raw data into specific categories (such as contact details, tax information, and SAP reporting data).
4.Display: The information is populated into the corresponding cards on the screen.
5.Error Handling: If the customer cannot be found, the system displays a "not found" message. If any other technical issue occurs during retrieval, a general error message is shown to the user.
2.3Key Concepts
–Read-Only View: The information displayed is for reference purposes only and cannot be edited directly on this page.
–Data Cards: The page organizes information into thematic groups (e.g., Tax Information, SAP Reporting, and Address details) to ensure the interface remains clean and easy to navigate.
–Audit Trail: The "Changes Card" provides transparency by showing when the record was created or last updated and by whom.
–Address Management: The system supports multiple address entries for a single customer, clearly labeling which is the primary address and which is used for shipping.
2.4Business Value

This feature centralizes all critical customer data into a single, reliable source of truth. By providing a structured, read-only view, it allows sales and administrative staff to quickly verify customer details—such as tax IDs, SAP configurations, and contact information—without the risk of accidental data modification. This improves operational efficiency and ensures that team members have accurate information when managing customer relationships or reporting.

3.  Data
3.1Overview

The Retail Customer Detail Page is a read-only view designed to provide a comprehensive snapshot of a specific customer's profile within the Lumi ERP system. When a user selects a customer, the system retrieves all relevant data—including contact details, tax information, SAP reporting codes, and address history—and displays it in an organized, easy-to-read format.

3.2Step-by-Step Flow
1.Page Initialization: When a user opens the Retail Customer Detail Page, the system identifies the specific customer using their unique ID.
2.Data Retrieval: The system requests the full customer profile from the database, which includes the primary customer record and all associated address records.
3.Validation: The system checks if the customer exists. If the customer is found, the data is processed for display; if not, the system triggers a "not found" error message.
4.Information Mapping: The retrieved data is organized into specific sections (cards) on the screen, such as contact details, tax information, and audit logs.
5.Display: The page renders all information as read-only, ensuring that the user can view the complete customer history and configuration without the risk of accidental modification.
3.3Key Concepts
–Read-Only View: A display mode where information is presented for reference purposes only and cannot be edited directly on the page.
–Audit Information: Tracking details that show when a record was created or last updated, and which user performed those actions.
–SAP Reporting Fields: Specific financial and organizational codes used to integrate customer data with SAP systems for accounting and reporting purposes.
–Address Association: The ability to link multiple addresses (such as billing or shipping) to a single customer profile, clearly identifying the purpose of each address.
3.4Business Value

This feature provides a "single source of truth" for retail customer information. By centralizing identity, tax, financial, and address data into one view, staff can quickly verify customer details, resolve inquiries, and ensure that financial reporting (via SAP) is accurate. The read-only nature of the page protects data integrity, ensuring that sensitive customer and tax configurations remain stable while being accessible to authorized personnel.
