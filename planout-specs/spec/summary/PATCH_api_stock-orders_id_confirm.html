1.  Logic
1.1Overview

This feature provides a way to finalize a stock order within the Lumi ERP system. By triggering this action, a stock order is moved from a "draft" state to a "confirmed" state. This process ensures that the order is officially recognized in the system, while maintaining a clear audit trail of the change.

1.2Step-by-Step Flow
1.Identification: The system receives a request to confirm a specific stock order using its unique ID.
2.Verification: The system checks that the order exists and belongs to your company. If the order cannot be found, the request is rejected.
3.Status Check: The system verifies that the order is currently in "draft" status. If the order has already been confirmed or is in another state, the request is rejected to prevent accidental changes.
4.Finalization: Once validated, the system updates the order status to "confirmed" and records the exact time of confirmation.
5.Audit Logging: Simultaneously, the system creates a history record to document the transition from "draft" to "confirmed," including who performed the action.
6.Confirmation: The system returns the updated order details to confirm the process was successful.
1.3Key Concepts
–Stock Order: A document or record representing a request for inventory movement.
–Draft State: The initial phase of an order where it can still be edited before being officially finalized.
–Confirmed State: The final phase of an order, indicating it has been reviewed and approved.
–Workflow History: An audit log that tracks the lifecycle of an order, showing when it changed status and who authorized the change.
–Transaction: A safety mechanism that ensures the status update and the history log are both saved successfully; if one fails, the entire process is rolled back to prevent data errors.
1.4Business Value
–Data Integrity: By restricting confirmation to "draft" orders only, the system prevents duplicate processing or accidental modifications to orders that are already finalized.
–Accountability: The automatic creation of a history record ensures there is a clear, unchangeable trail of who confirmed an order and when, which is essential for internal reporting and auditing.
–Operational Efficiency: This feature provides a standardized, reliable way for team members to transition orders through the supply chain workflow without manual intervention or risk of inconsistent data.
2.  Data
2.1Overview

The "Confirm Stock Order" feature allows authorized users to finalize a stock order that is currently in a "draft" state. This action officially transitions the order to a "confirmed" status, records the exact time of confirmation, and logs who performed the action. This process ensures that stock orders are tracked accurately within the system's workflow history.

2.2Step-by-Step Flow
1.Locate the Order: The system identifies the specific stock order using the provided ID and verifies that it belongs to the user's company.
2.Validate Status: The system checks if the order is currently in "draft" mode. If the order has already been confirmed or is in another state, the request is rejected to prevent duplicate or invalid processing.
3.Update Order Details: The system updates the order status to "confirmed," records the current date and time, and saves the ID of the user who performed the update.
4.Log History: Simultaneously, the system creates a permanent record in the workflow history, noting the transition from "draft" to "confirmed" and identifying the user responsible for the change.
5.Finalize: Once these steps are successfully completed, the system confirms the update is finished.
2.3Key Concepts
–Draft State: The initial status of a stock order, indicating it is still being prepared and has not yet been finalized.
–Atomic Transaction: A safety mechanism that ensures the order update and the history log are processed together; if one part fails, the entire action is canceled to prevent data inconsistencies.
–Workflow History: A permanent audit trail that tracks the lifecycle of a stock order, specifically recording status changes and the individuals who initiated them.
–Conflict Check: A validation step that prevents users from confirming an order that is no longer in the correct state (e.g., trying to confirm an order that is already confirmed).
2.4Business Value
–Data Integrity: By requiring orders to be in a "draft" state before confirmation, the system prevents accidental or duplicate processing of stock orders.
–Accountability: The automated logging of the user who confirmed the order provides a clear audit trail, which is essential for internal oversight and troubleshooting.
–Operational Clarity: Moving orders from "draft" to "confirmed" provides real-time visibility into which orders are ready for the next stage of the supply chain process.
