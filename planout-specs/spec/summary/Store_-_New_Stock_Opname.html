1.  Frontend
1.1Overview

The "New Stock Opname" feature allows staff to initiate a stock-taking process for a specific store. This page provides a structured way to record physical inventory counts, compare them against system records, and document any discrepancies. It is designed to help businesses maintain accurate inventory levels by identifying and adjusting for missing or excess stock.

1.2Step-by-Step Flow
1.Initialization: When the page loads, the system automatically retrieves necessary setup information (such as available stores, product categories, and suppliers) to populate the form options.
2.Form Setup: The user selects the target store and sets the document date. The system defaults the status to "DRAFT" to indicate the process has begun but is not yet finalized.
3.Autofill Configuration: The user can define criteria to automatically pull a list of products into the form. This includes filtering by product type, brand, supplier, or recent movement history, and choosing whether to include items currently showing zero stock.
4.Manual Entry & Adjustment: The user adds products to the list, entering the "counted quantity" for each. The system ensures that each product is only listed once to prevent calculation errors.
5.Validation: Before saving, the system checks that all required fields are filled and that no negative numbers have been entered for counted quantities.
6.Submission: Once the user clicks "Save," the system processes the data and redirects the user to the main list of stock-taking documents.
1.3Key Concepts
–Stock Opname: The formal process of counting physical inventory to verify that it matches the quantities recorded in the system.
–Draft Status: A temporary state for a document that is still being edited and has not yet been officially confirmed or approved.
–Autofill Criteria: A set of filters used to quickly generate a list of products for counting, saving the user from having to add every item manually.
–Variance: The difference between the physical quantity counted by the staff and the quantity currently recorded in the system.
–Duplicate Prevention: A built-in safety check that prevents the same product from being added to the same stock-taking document multiple times, ensuring data integrity.
1.4Business Value
–Improved Inventory Accuracy: By formalizing the stock-taking process, businesses can identify and correct discrepancies between physical stock and system records.
–Operational Efficiency: The "Autofill" feature significantly reduces the time required to prepare a stock-taking list by automatically pulling relevant products based on specific business rules.
–Error Reduction: Automated validation—such as preventing negative counts and duplicate product entries—ensures that the data submitted is clean and reliable for financial reporting.
–Better Decision Making: Accurate stock data allows management to make informed decisions regarding purchasing, restocking, and identifying potential inventory loss or theft.
2.  Logic
2.1Overview

The "New Stock Opname" feature allows staff to perform a physical inventory count at a specific store. This process ensures that the actual stock levels on the shelf match the records in the system. The feature includes an "autofill" capability to help users quickly pull in lists of products based on specific criteria (such as brand or supplier), making the counting process more efficient.

2.2Step-by-Step Flow
1.Authentication Check: When the page loads, the system verifies that the user is logged in. If not, they are redirected to the login screen.
2.Data Loading: Once authenticated, the system retrieves necessary information (such as lists of stores, product types, brands, and suppliers) to populate the dropdown menus on the form.
3.Form Entry: The user selects the store and enters the physical count for specific products. They can also use the "Autofill" tool to automatically generate a list of products to count based on filters like product type or recent movement.
4.Validation: When the user clicks "Save," the system checks that a store is selected and ensures that no counted quantities are negative.
5.Calculation: The system automatically compares the user's physical count against the current system records. It calculates the difference (variance) and the financial impact (adjustment amount) based on the product's average cost.
6.Submission: The completed data is sent to the system, a unique reference code is generated, and the user is redirected to the list of all stock opname documents.
2.3Key Concepts
–Stock Opname: The process of physically counting inventory to verify that the actual stock matches the system records.
–Autofill Criteria: A set of filters (like brand, supplier, or product type) that helps users quickly generate a list of items to count, rather than adding them one by one.
–Variance: The difference between the physical quantity counted by the user and the quantity currently recorded in the system.
–Adjustment Amount: The financial value of the variance, calculated by multiplying the difference in quantity by the average cost of the product.
–System Quantity: The amount of stock the system currently believes is on hand before the physical count is performed.
2.4Business Value
–Accuracy: By automating the calculation of variances and financial adjustments, the system reduces human error and ensures inventory records are precise.
–Efficiency: The autofill feature saves time by allowing users to quickly generate targeted lists of products to count, rather than manually searching for every item.
–Accountability: Every stock opname is tracked with a unique reference code and linked to specific stores, providing a clear audit trail for inventory changes.
–Financial Visibility: The system provides immediate insight into the financial impact of inventory discrepancies, helping management identify and address stock loss or reporting issues promptly.
