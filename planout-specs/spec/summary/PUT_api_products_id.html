1.  Logic
1.1Overview

This feature allows authorized users to perform a full update on an existing product record within the Lumi ERP system. When a user submits changes—such as updating the product name, price, or stock levels—the system ensures the request is secure, validates that the data is accurate, and automatically logs these changes for auditing purposes.

1.2Step-by-Step Flow
1.Security Check: The system verifies that the user is logged in and possesses the necessary permissions to modify product information.
2.Record Retrieval: The system locates the specific product in the database using the provided ID. If the product does not exist, the process stops and notifies the user.
3.Data Validation: The system checks if the user is trying to change the product's SKU. If they are, it confirms that the new SKU is not already being used by another product to prevent duplicates.
4.Change Tracking: The system compares the new information against the existing data to identify exactly which fields are being modified.
5.Update and Audit: The system saves the updated product details and simultaneously records each specific change in an audit log. If any part of this process fails, the system cancels the entire operation to ensure data consistency.
6.Confirmation: Once successfully saved, the system returns the updated product information to the user.
1.3Key Concepts
–Authentication & Authorization: Security measures that confirm who the user is and ensure they have the specific rights required to edit product data.
–SKU Uniqueness: A validation rule that prevents two different products from sharing the same Stock Keeping Unit (SKU) identifier.
–Audit Log: A permanent record of changes that tracks what was modified, what the value was before the change, and what it was changed to.
–Transaction: A safety mechanism that ensures the product update and the audit log entry are treated as a single action; if one fails, both are rolled back to prevent data errors.
1.4Business Value

This feature provides a reliable and secure way to maintain product data integrity. By enforcing strict validation and maintaining a detailed audit trail, the business can ensure that product information remains accurate and that there is full accountability for any changes made to the inventory catalog.

2.  Data
2.1Overview

This feature enables the full update of product information within the Lumi ERP system. When a user submits changes to a product, the system ensures that all product details are updated accurately. Additionally, the system includes a built-in security measure that automatically tracks and logs any changes made to a product's "active" status, providing a clear history of when a product was enabled or disabled.

2.2Step-by-Step Flow
1.Locate Product: The system identifies the specific product in the database using the unique ID provided in the request.
2.Initiate Update: The system begins a secure transaction to ensure that the product update and any necessary audit logging happen together as a single, reliable action.
3.Apply Changes: The system updates the product’s core information (such as name, description, price, and stock levels) and records the current time of the update.
4.Check Status Toggle: The system compares the product's previous "active" status with the new status.
5.Log Changes (if applicable): If the "active" status has changed, the system creates an entry in the audit log detailing the previous status, the new status, and the time the change occurred.
6.Finalize: The system saves all changes permanently. If any errors occur during this process, the system will report the issue (such as invalid data or a server error) to ensure the database remains consistent.
2.3Key Concepts
–Full Update: A process where the system replaces the existing product information with the new data provided in the request.
–Transaction: A safety mechanism that ensures all parts of an update (the product change and the audit log) are completed successfully together; if one part fails, the entire update is canceled to prevent data errors.
–Audit Log: A secure record-keeping feature that tracks specific, important changes to product data for accountability and historical reference.
–Constraint Violation: A scenario where the submitted data does not meet the system's rules (e.g., missing required information or invalid formats), resulting in a request rejection.
2.4Business Value

This feature ensures data integrity by providing a reliable way to manage product catalogs while maintaining a transparent history of status changes. By automatically logging when a product is toggled between active and inactive, the business gains better visibility into inventory management and operational changes, reducing the risk of unauthorized or accidental status updates going unnoticed.
