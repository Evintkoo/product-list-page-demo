1.  Data
1.1Overview

This feature provides a structured way to retrieve and display a list of "Franchise Purchase Returns" within the Lumi ERP system. It allows users to view, filter, and search through return records specifically related to franchise operations. The system automatically organizes this data, resolves relevant names (like stores, suppliers, and warehouses), and provides pagination to ensure the list remains easy to navigate.

1.2Step-by-Step Flow
1.Request Parameters: The system receives a request containing optional filters, such as the current status of the return, specific store or supplier IDs, date ranges, or partial reference codes for the return or the original order.
2.Data Retrieval: The system queries the database, specifically looking for records marked as franchise-related returns.
3.Information Enrichment: As it gathers the data, the system automatically looks up and attaches human-readable names for the locations (stores and warehouses), the supplier involved, the original purchase order, and the user who created the record.
4.Sorting and Pagination: The results are sorted by the date they were created (newest first). The system also calculates the total number of matching records to support page-by-page navigation.
5.Response Delivery: The system returns a clean, organized list of return records along with the pagination details, ready to be displayed in the user interface.
1.3Key Concepts
–Franchise Purchase Return: A record representing stock being returned from a franchise location, either back to a supplier or to an internal warehouse.
–Workflow State: The current status of a return (e.g., Draft, Sent, Approved, or Cancelled), which helps users track the progress of the return process.
–Reference Code: A unique identifier for the return, used to quickly locate specific documents.
–Pagination: A method of breaking a large list of records into smaller, manageable chunks (e.g., 20 items per page) to improve performance and readability.
–Entity Resolution: The process of automatically matching internal system IDs (like a store ID) to their actual names (like "Downtown Store") so the list is meaningful to the user.
1.4Business Value
–Operational Visibility: Provides franchise managers and staff with a clear, searchable view of all active and historical returns, reducing the time spent searching for specific documents.
–Improved Accuracy: By automatically resolving names for stores, suppliers, and warehouses, the system ensures that users see consistent and correct information without needing to cross-reference other reports.
–Efficient Workflow Management: With built-in filtering by status and date, users can quickly identify returns that require immediate attention, such as those waiting for approval or those that have been recently sent.
–Scalability: The pagination logic ensures that the system remains fast and responsive, even as the number of franchise return records grows over time.
