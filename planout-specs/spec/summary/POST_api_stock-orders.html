1.  Logic
1.1Overview

This feature provides a way for the system to create a new stock order and its associated items in one single action. By sending a request to this endpoint, you can define the warehouse source, the destination store, and a list of specific products to be ordered. The system automatically handles the calculations for order costs and ensures that all information is saved accurately and consistently.

1.2Step-by-Step Flow
1.Initiation: The system receives a request containing the order details (such as the reference code, warehouse locations, and the list of items).
2.Validation: The system checks if the provided reference code is unique. If a code already exists, the request is rejected to prevent duplicate entries.
3.Preparation: The system creates a new order record, automatically filling in administrative details like the creator's ID, the current date, and the company association.
4.Item Processing: For every product in the order, the system calculates the total cost based on the quantity and the average cost of the item. It then saves each item as part of the order.
5.Finalization: Once all items are processed, the system calculates the total order amount for the entire request and saves the final order record.
6.Confirmation: If everything is successful, the system confirms the creation of the order. If any part of the process fails, the entire operation is canceled to ensure no partial or incorrect data is saved.
1.3Key Concepts
–Stock Order: A formal request to move inventory from a warehouse to a specific store.
–Reference Code: A unique identifier (like an order number) used to track and distinguish specific stock orders.
–Transaction: A "safety-first" approach where the system treats the entire order and its list of items as one single unit of work; if one part fails, the whole thing is undone to keep records clean.
–Workflow State: The current status of the order (e.g., pending, approved, or in-transit).
–Calculated Fields: Values like "order amount" that the system computes automatically based on the items provided, reducing the need for manual entry and preventing calculation errors.
1.4Business Value
–Data Integrity: By using a single transaction, the system guarantees that you will never have an "orphaned" order (an order without items) or incomplete data, ensuring your inventory reports remain accurate.
–Efficiency: This feature automates the calculation of order costs and the assignment of system-managed fields (like timestamps and user IDs), saving time and reducing manual data entry errors.
–Reliability: The built-in validation for unique reference codes prevents confusion and conflicts in your supply chain tracking, ensuring that every order is uniquely identifiable.
2.  Data
2.1Overview

The `POST /api/stock-orders` feature allows users to create a new stock order and its associated line items in one single action. This ensures that when you request a transfer of goods between locations, the system captures both the high-level order details (such as the source warehouse, destination store, and due date) and the specific list of products being ordered simultaneously.

2.2Step-by-Step Flow
1.Validation: The system checks if the provided reference code is unique to prevent duplicate orders.
2.Initialization: The system prepares the order by generating a unique ID and capturing the current date and time.
3.Order Creation: The main stock order record is created, automatically tagging it with the current user’s information and the company ID.
4.Item Processing: The system iterates through the list of products provided in the request, creating individual line items for each and linking them to the main stock order.
5.Finalization: The entire process is treated as a single "transaction." If any part of the process fails (e.g., an invalid product entry), the system cancels the entire operation to ensure no partial or incorrect data is saved.
2.3Key Concepts
–Transaction: A safety mechanism that ensures all parts of an order are saved together. If one part fails, the entire request is rolled back to keep the data clean and consistent.
–Reference Code: A unique identifier for the order that helps prevent accidental duplication of records.
–System-Managed Fields: Information that the software handles automatically—such as timestamps, user IDs, and unique record IDs—so the user doesn't have to provide them manually.
–Stock Order Items: The individual product lines within an order, which track specific quantities and remarks for each item being moved.
2.4Business Value

This feature streamlines inventory management by allowing for "all-or-nothing" order creation. By bundling the order and its items into a single request, the business reduces the risk of data errors or mismatched records. This ensures that inventory tracking remains accurate and reliable, providing a clear audit trail of who created the order and when, while maintaining strict consistency across the entire supply chain.
