1.  Logic
1.1Overview

This feature provides a search and retrieval function for the "Stock Opname" list within the Lumi ERP system. It allows users to filter stock orders based on specific criteria—such as reference codes, date ranges, store locations, and current workflow status—to quickly locate relevant inventory records.

1.2Step-by-Step Flow
1.Validation: The system first checks that the request is specifically for "warehouse" stock. If this is missing or incorrect, the request is rejected.
2.Initialization: The system prepares to search the database for all records categorized as "stock orders."
3.Applying Filters: The system checks which optional filters (reference code, date range, store ID, or status) have been provided by the user. Only the filters with active values are applied to the search.
4.Refining Results:
–If a reference code is provided, the system searches for partial matches in both the internal reference code and the supplier's reference code.
–Date ranges are applied to include all records created on or between the selected start and end dates.
5.Data Retrieval: The system executes the search and returns the matching list of stock orders to the user interface. If an unexpected error occurs during this process, the system notifies the user that the lookup failed.
1.3Key Concepts
–Stock Type: A mandatory category filter that ensures the system only retrieves relevant warehouse-related stock orders.
–Partial Matching: A search method where the system finds records containing the provided text, even if it is only a portion of the full reference code.
–Workflow State: The current status of a stock order (e.g., pending, received, or completed), which can be used to narrow down search results.
–Inclusive Date Filtering: A search logic where the "from" and "to" dates are included in the results, ensuring no records from those specific days are missed.
1.4Business Value

This feature improves operational efficiency by allowing warehouse staff and managers to quickly pinpoint specific stock orders without manually scanning through large datasets. By providing flexible filtering options, the system ensures that users can generate accurate reports and monitor inventory status in real-time, leading to better decision-making and reduced administrative overhead.

2.  Data
2.1Overview

The Stock Opname feature provides a way for users to search and retrieve a list of warehouse stock orders from the system. By using various filters, users can quickly locate specific inventory records based on reference codes, date ranges, store locations, or the current processing status of the order.

2.2Step-by-Step Flow
1.Initiate Request: The user triggers a search, which sends a request to the system. This request must specify that it is for "warehouse" stock to ensure the correct data is retrieved.
2.Apply Filters: The system checks for any additional search criteria provided by the user:

* Reference Code: Searches for partial matches in both the internal reference code and the supplier’s reference code.

* Date Range: Filters records created between a specific start and end date (inclusive).

* Store ID: Limits results to a specific store location.

* Status: Filters records based on their current workflow state (e.g., pending, received).

3.Data Retrieval: The system queries the database using the provided filters.
4.Response:

* If successful, the system returns the matching list of stock orders to be displayed in the table.

* If the request is invalid (e.g., missing the required "warehouse" type) or if a system error occurs, the user receives an appropriate error notification.

2.3Key Concepts
–Stock Opname: A process for verifying inventory levels; in this system, it refers to the management of warehouse stock orders.
–Reference Code: A unique identifier for an order, which can be searched by either the internal system code or the supplier's provided code.
–Workflow State: The current stage of an order in the business process (e.g., whether it is still being processed or has been completed).
–Inclusive Filtering: When searching by date, the system includes records from both the start and end dates selected by the user.
2.4Business Value

This feature improves operational efficiency by allowing warehouse staff and managers to quickly find and audit specific stock orders. By providing flexible search options, users spend less time manually scrolling through lists and can instead pinpoint the exact information needed to manage inventory levels accurately and resolve discrepancies faster.
