1.  Frontend
1.1Overview

The Standard Purchase Order list feature provides a centralized dashboard for viewing and managing all standard asset purchase orders within the Lumi ERP system. This interface allows users to quickly locate specific orders using various search criteria and provides a high-level summary of order details, including their current status and progress regarding deliveries, invoices, and returns.

1.2Step-by-Step Flow
1.Automatic Loading: When you first open the page, the system automatically retrieves and displays all standard purchase orders.
2.Applying Filters: You can narrow down the list by entering specific criteria, such as the internal reference code, supplier-provided reference number, date ranges, specific suppliers, receiving warehouses, or the current workflow status (e.g., Draft, Sent, or Received).
3.Executing Search: Once your filters are set, clicking the "Search" button triggers the system to refresh the list and display only the orders that match your criteria.
4.Reviewing Data: The results are presented in a table format, showing key information like dates, amounts, and the current status of each order.
5.Monitoring Progress: The table includes summary columns that indicate if an order is closed and provide quick counts for related activities like deliveries, invoices, and returns.
1.3Key Concepts
–Reference Code: The unique internal identifier generated by the system for each purchase order.
–Supplier Reference Number: The external tracking number provided by the supplier, used for matching the order against their documentation.
–Workflow Status: The current stage of the order in the procurement process, categorized as Draft, Sent, or Received.
–Derived Counts: Calculated totals displayed in the list that show how many invoices, deliveries, or returns are associated with a specific order, helping you track fulfillment progress at a glance.
–Filter Bar: A set of input fields and dropdowns that allow you to refine the list of orders based on your specific reporting or operational needs.
1.4Business Value

This feature improves operational efficiency by providing a "single source of truth" for all standard purchase orders. By enabling quick searching and filtering, procurement teams can spend less time hunting for documents and more time managing supplier relationships. Additionally, the inclusion of status badges and activity counts (invoices, deliveries, returns) allows users to proactively identify bottlenecks or incomplete orders, ensuring better control over the inventory procurement lifecycle.

2.  Logic
2.1Overview

The Purchase Order browsing feature provides a centralized view for managing standard asset procurement. It allows users to view a comprehensive list of all purchase orders, with the ability to filter results by specific suppliers or warehouses. The system automatically pulls in relevant details and provides a quick summary of related activities—such as returns, invoices, and deliveries—directly within the list view.

2.2Step-by-Step Flow
1.Data Retrieval: When the page loads, the system fetches all standard purchase orders. If you have selected a specific supplier or warehouse filter, the system narrows the results to match those criteria.
2.Information Enrichment: For every order found, the system automatically looks up the human-readable names for the associated warehouse and supplier, replacing internal ID codes with names that are easy to identify.
3.Activity Calculation: The system scans related records to count how many returns, invoices, and deliveries are linked to each specific purchase order.
4.Display: All this information is organized into a clear table, showing key dates, status, financial totals, and the activity counts, allowing you to see the progress of each order at a glance.
2.3Key Concepts
–Filtering: The ability to narrow down the list of orders by choosing a specific supplier or warehouse to focus on relevant data.
–Enrichment: The process of automatically pulling in descriptive names (like "Warehouse A" or "Supplier B") so you don't have to look up what a numerical ID represents.
–Derived Counts: A summary feature that calculates the number of related documents (returns, invoices, and deliveries) for each order, providing immediate visibility into the order's lifecycle.
–Workflow State: The current status of the purchase order, helping you track where it sits in the procurement process.
2.4Business Value
–Improved Efficiency: By displaying counts for returns, invoices, and deliveries directly in the list, users can identify the status of an order without needing to open each individual record.
–Better Decision Making: The ability to filter by warehouse or supplier allows procurement teams to quickly assess supply chain performance and inventory distribution.
–Enhanced Clarity: Replacing technical identifiers with clear names and organized columns ensures that the information is accessible and easy to interpret for all team members.
3.  Data
3.1Overview

The Purchase Order browsing feature provides a centralized dashboard for managing "Standard Asset" purchase orders within the Lumi ERP system. This tool allows users to efficiently search, filter, and view the status of all standard procurement activities. Beyond basic order details, the system automatically calculates and displays the volume of related activity—such as deliveries, invoices, and returns—giving users an immediate snapshot of an order's progress without needing to open individual records.

3.2Step-by-Step Flow
1.Request: The user initiates a search or navigates to the Purchase Order list.
2.Filtering: The system applies any user-defined criteria, such as specific reference codes, supplier names, order status, or date ranges.
3.Data Retrieval: The system fetches the relevant purchase orders, specifically filtering for "Standard" asset types.
4.Activity Calculation: For every order retrieved, the system automatically counts the number of associated deliveries, invoices, and returns linked to that specific order.
5.Formatting: The raw data is organized into a user-friendly format, mapping internal system codes to clear, readable columns (e.g., Status, Amount, and activity counts).
6.Display: The final list is presented to the user, sorted by the most recently created orders first.
3.3Key Concepts
–Standard Asset: A specific category of purchase order used for routine procurement, distinct from other specialized order types.
–Workflow State: The current stage of the purchase order in its lifecycle (e.g., pending, approved, or completed).
–Derived Counts: Automatically generated totals that show how many invoices, deliveries, or returns are tied to a single purchase order, providing instant visibility into the order's fulfillment status.
–Pagination: A method of displaying large amounts of data in smaller, manageable chunks to ensure the system remains fast and easy to navigate.
3.4Business Value
–Improved Visibility: By displaying counts for invoices, deliveries, and returns directly in the list view, staff can instantly identify which orders are fully processed and which require attention.
–Operational Efficiency: Users can quickly locate specific orders using flexible search and filter options, reducing the time spent manually tracking procurement documents.
–Better Decision Making: Having a clear, real-time overview of order statuses and associated documentation helps teams manage supplier relationships and inventory replenishment more effectively.
