1.  Logic
1.1Overview

The logout feature ensures that when a user chooses to sign out of the Lumi ERP system, their active session is securely terminated. This process invalidates the user's current access credentials in our database and removes the digital "key" (cookie) stored on their browser, preventing any further unauthorized access using that specific session.

1.2Step-by-Step Flow
1.Identify Session: The system looks for the user's unique session token stored in their browser cookies.
2.Verify Existence: The system checks if a session token was provided. If no token is found, the request is rejected.
3.Validate Status: The system searches the database to confirm the session is legitimate and has not already been closed. If the session is missing or already revoked, the request is rejected.
4.Revoke Access: The system updates the database to mark the session as officially closed, effectively disabling it.
5.Clear Browser Data: The system sends a command to the user's browser to delete the session cookie.
6.Confirm Logout: The system sends a success message to the user, confirming they have been logged out.
1.3Key Concepts
–Session Token: A unique digital identifier that acts as a temporary "key" to keep a user logged in while they navigate the application.
–Revocation: The act of officially canceling a session in the database so that it can no longer be used to access the system.
–Cookie: A small piece of data stored by the browser that holds the session token, allowing the system to recognize the user across different pages.
1.4Business Value

This feature is critical for maintaining the security and integrity of the Lumi ERP system. By explicitly revoking sessions, we ensure that once a user logs out, their account cannot be accessed by anyone else using the same device or browser. This protects sensitive business data and ensures that user activity is accurately tracked and controlled.

2.  Data
2.1Overview

The logout feature ensures that when a user chooses to sign out of the Lumi ERP system, their current session is securely terminated. This process verifies the user's active connection and updates our records to ensure that the session can no longer be used to access the system, effectively protecting the user's account from unauthorized access after they have left.

2.2Step-by-Step Flow
1.Session Verification: The system checks the database to confirm that the user’s current session is valid, active, and has not yet expired.
2.Validation Check: If the system cannot find an active session (for example, if the user is already logged out or the session has timed out), it informs the user that the request is unauthorized.
3.Session Revocation: If a valid session is found, the system updates the database to mark that specific session as "revoked" using the current timestamp.
4.Confirmation: Once the database has been successfully updated, the system sends a confirmation back to the user to signal that the logout process is complete.
2.3Key Concepts
–Session: A temporary digital "handshake" that keeps a user logged in while they navigate the application.
–Revocation: The act of officially canceling a session, ensuring that the digital key used to access the system is no longer valid.
–Unauthorized Status: A standard response indicating that the system could not identify a valid, active session to log out.
2.4Business Value

This feature is critical for maintaining the security and integrity of the Lumi ERP platform. By explicitly revoking sessions, we prevent "session hijacking," where an unauthorized party might attempt to use an old, active session to gain access to sensitive business data. This provides users with peace of mind, knowing that their account is fully secured the moment they click "logout."
