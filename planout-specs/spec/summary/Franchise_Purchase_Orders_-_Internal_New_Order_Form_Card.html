1.  Frontend
1.1Overview

The Franchise Purchase Order form is a new interface component designed to streamline the creation of internal purchase orders within the Lumi ERP system. This form allows users to specify the origin of goods (warehouse and supplier) and the destination (store), while providing optional fields for tracking and scheduling. The system ensures data integrity by enforcing mandatory selections before an order can be submitted.

1.2Step-by-Step Flow
1.Document Identification: The system automatically generates a unique document number for the order, which is displayed as a read-only field.
2.Required Selections: The user must select a source warehouse, a destination store, and a supplier from the provided dropdown menus. These fields are validated in real-time to ensure they are not left blank.
3.Optional Details: The user may optionally enter a reference code, select a due date using the calendar picker, and add any relevant notes.
4.Validation: As the user fills out the form, the system performs immediate checks. If a required field is missing, the system flags it to prevent incomplete submissions.
5.Submission: Once all required information is provided, the user clicks the "Create Order" button. The system processes the data and confirms the creation of the purchase order. If the submission fails, the system provides feedback to the user.
1.3Key Concepts
–Required Fields: Specific data points (Warehouse, Store, and Supplier) that must be provided to successfully create an order.
–Real-time Validation: A feature that checks for errors as the user interacts with the form, providing immediate feedback rather than waiting until the end.
–System-Generated Fields: Information, such as the Document Number, that is handled automatically by the software and does not require user input.
–Dropdown Integration: Menus that pull current, accurate data directly from the system’s warehouse, store, and supplier databases.
1.4Business Value

This feature standardizes the purchase order process, reducing manual entry errors and ensuring that all necessary logistics data is captured consistently. By automating the document numbering and integrating live data for warehouses and stores, the form minimizes administrative overhead and ensures that inventory movements are accurately tracked from the moment an order is initiated.

2.  Logic
2.1Overview

The Franchise Purchase Order form is a new internal tool designed to streamline how inventory is requested and moved between locations. This feature provides a structured interface for staff to create purchase orders by selecting the source warehouse, the destination store, and the supplier, while also allowing for optional details like reference numbers, delivery dates, and internal notes.

2.2Step-by-Step Flow
1.Data Entry: The user fills out the form by selecting the required warehouse, store, and supplier from dropdown menus. They may also optionally provide a reference code, a due date, and any relevant notes.
2.Validation: The system checks that the three required fields (warehouse, store, and supplier) have been completed. If any are missing, the system will prompt the user to provide the necessary information before proceeding.
3.Data Formatting: Once validated, the system organizes the information into a standardized format, ensuring dates and text are correctly prepared for the system’s records.
4.Submission: The system sends the completed order to the central database.
5.Confirmation: Upon successful submission, the system confirms the order has been created and assigns it a unique identifier for tracking purposes.
2.3Key Concepts
–Franchise Purchase Order: A formal request document used to track the movement of inventory from a supplier or warehouse to a specific franchise store.
–Required Fields: Essential pieces of information (Warehouse, Store, and Supplier) that must be provided to ensure the order can be processed and tracked accurately.
–Reference Code: An optional, user-defined identifier (such as an internal tracking number) used to help staff easily locate or cross-reference the order later.
–Due Date: An optional field that allows the user to specify when the inventory is expected to arrive, assisting with better scheduling and inventory planning.
2.4Business Value

This feature centralizes the purchase order process, reducing manual errors by enforcing the collection of critical data points. By standardizing how orders are created, the business gains better visibility into inventory movement, improves the accuracy of supply chain tracking, and ensures that all stakeholders—from warehouse managers to store owners—have a clear, consistent record of incoming stock.

3.  Data
3.1Overview

The Franchise Purchase Order form is a new feature within the Lumi ERP system designed to streamline how inventory is moved or ordered between locations. This form allows users to create a formal request by selecting the source warehouse, the destination store, and the supplier, while also providing space for reference codes, delivery deadlines, and additional notes.

3.2Step-by-Step Flow
1.Data Loading: When the form opens, the system automatically retrieves the current lists of available suppliers, stores, and warehouses to ensure the user is selecting from up-to-date information.
2.Selection: The user selects the source warehouse and the destination store from the provided lists. The store selection includes a search feature to help users quickly find the correct location.
3.Optional Details: The user selects a supplier (if applicable) and enters a unique reference code for the order.
4.Scheduling and Notes: The user sets the required delivery date and adds any necessary comments or instructions in the notes field.
5.Submission: Once the user submits the form, the system packages all selected and entered information into a formal purchase order and saves it to the inventory database.
3.3Key Concepts
–Source Warehouse: The specific facility where the inventory is currently held or being shipped from.
–Destination Store: The specific franchise location that will receive the inventory.
–Reference Code: A unique identifier or tracking number assigned to the order for easy record-keeping.
–Due Date: The specific date by which the purchase order is expected to be fulfilled.
–Supplier: An optional entity that may be associated with the order if the inventory is being sourced externally rather than internally.
3.4Business Value

This feature centralizes the purchase order process, reducing manual data entry errors and ensuring that inventory movements are tracked accurately across the franchise network. By providing a standardized form, the system ensures that all necessary information—such as delivery deadlines and reference codes—is captured consistently, which improves communication between warehouses and stores and leads to better inventory management.
