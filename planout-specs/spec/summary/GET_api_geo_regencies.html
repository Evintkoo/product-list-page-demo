1.  Logic
1.1Overview

This feature provides a way for the system to retrieve a list of regencies or municipalities based on a selected province. It is designed to power "cascading" dropdown menus, where selecting a province automatically updates the available options in the regency/municipality field. This ensures that users are only presented with relevant, accurate location data.

1.2Step-by-Step Flow
1.Request Initiation: The system receives a request that includes a specific province identifier.
2.Validation: The system checks to ensure the province identifier is present. If it is missing, the request is rejected with an error message.
3.Data Retrieval: The system searches the database for all active regencies or municipalities associated with the provided province ID.
4.Sorting: The retrieved list is organized alphabetically by name to ensure a user-friendly experience.
5.Response: The system returns the final list of regencies (including their unique IDs and names) to the user interface to populate the dropdown menu.
1.3Key Concepts
–Cascading Dropdown: A user interface pattern where the options in one menu change dynamically based on the selection made in a previous menu.
–Province Identifier: A unique code used to pinpoint a specific province, ensuring the system fetches the correct corresponding regencies.
–Active Records: A filter applied to ensure that only currently valid or "live" locations are displayed to the user, hiding any outdated or inactive entries.
1.4Business Value
–Improved Data Accuracy: By filtering regencies based on the selected province, the system prevents users from selecting invalid location combinations.
–Enhanced User Experience: Cascading menus reduce the number of options a user has to scroll through, making data entry faster and less prone to error.
–Standardization: This feature provides a consistent way for different parts of the Lumi ERP system to fetch location data, ensuring that address and area information remains uniform across the platform.
2.  Data
2.1Overview

This feature provides a way for the Lumi ERP system to retrieve a list of regencies (or municipalities) based on a selected province. It is designed to populate dropdown menus in the user interface, ensuring that when a user selects a province, they are presented with the correct, relevant, and active regencies for that specific area.

2.2Step-by-Step Flow
1.Input Validation: The system receives a request containing a province identifier. It first checks to ensure this identifier is provided; if it is missing or empty, the request is rejected.
2.Data Retrieval: Once validated, the system searches the database for all regencies associated with that specific province.
3.Filtering: The system automatically filters the results to include only "active" regencies, ensuring that outdated or disabled options are not shown to the user.
4.Sorting: The retrieved list is organized alphabetically by name to provide a clean, user-friendly experience.
5.Response: The system formats the final list of regencies (providing their unique IDs and names) and sends them back to the application to populate the dropdown menu.
2.3Key Concepts
–Regency: A geographical administrative division within a province, used here to help users narrow down location-based data.
–Active Status: A filter that ensures only currently valid or operational regencies are displayed, preventing users from selecting obsolete options.
–Cascading Selection: A design pattern where the options in one dropdown (Regency) are automatically updated based on the selection made in a previous dropdown (Province).
–Validation: A safety check performed at the start of the process to ensure the system has the necessary information to perform the search.
2.4Business Value

This feature improves data accuracy and user efficiency by automating the "cascading" selection process. By ensuring that users only see active, relevant regencies for their chosen province, the system reduces manual data entry errors and streamlines the address or location-selection workflow within the ERP.
