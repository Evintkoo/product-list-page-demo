1.  Logic
1.1Overview

The Product Search API allows users to retrieve a filtered list of products from the Lumi ERP system. It provides a flexible way to search the catalog by combining various criteria—such as product names, codes, brands, or custom information fields—and allows users to control how many results are displayed at once.

1.2Step-by-Step Flow
1.Security Check: The system first verifies that the user is logged in and has the necessary permissions to view the product list.
2.Parameter Processing: The system collects the search criteria (filters) and the requested number of results per page. If no specific page size is provided, it defaults to 20 items.
3.Validation: The system checks that any specific IDs provided for filtering (such as Brand, Product Type, or Tax categories) actually exist in the database. If an ID is invalid, the request is rejected.
4.Search Execution: The system builds a dynamic search query based on the provided filters. It looks for matches across the specified product attributes and applies any requested sorting.
5.Data Retrieval: The system fetches the matching products from the database and returns them to the user.
1.3Key Concepts
–Filtering: The ability to narrow down search results using specific attributes like SKU, name, brand, or custom information fields.
–Pagination: A feature that limits the number of results returned in a single request, helping to keep the system fast and the data easy to manage.
–Validation: A safety step that ensures the search criteria are not only formatted correctly but also refer to valid data existing within the ERP.
–Authorization: A security measure ensuring that only users with the appropriate access rights can perform product searches.
1.4Business Value

This feature empowers users to quickly locate specific items within a large product catalog without manual browsing. By supporting a wide range of search filters, it improves operational efficiency for staff who need to manage inventory, update product details, or assist customers. The inclusion of pagination ensures that the application remains responsive even as the product catalog grows.

2.  Data
2.1Overview

The Product Search API allows users to retrieve a filtered list of products from the Lumi ERP system. It provides a flexible way to search the catalog by combining various criteria—such as product names, codes, brands, types, and tags—into a single request. The feature is designed to be efficient, allowing users to specify how many results they want to see at once and how those results should be sorted.

2.2Step-by-Step Flow
1.Request Submission: The user sends a request to the system with specific search criteria (e.g., searching for a specific brand or a product name containing certain text).
2.Validation: The system checks if the provided search criteria are valid. If the user references a specific ID (like a Brand or Tax ID) that does not exist in the system, the request is rejected.
3.Filtering: The system applies the requested filters to the product database. This includes:

* Text matching: Finding products where the name, SKU, or info fields contain the provided text.

* Exact matching: Finding products that match specific IDs for brands, types, or tax categories.

* Tag filtering: Finding products associated with specific tags.

4.Sorting and Pagination: The system organizes the results based on the user's preferred order (e.g., by name) and limits the number of items returned to match the requested page size.
5.Response: The system returns the matching list of products. If the request is invalid, unauthorized, or encounters an error, the system provides an appropriate status code to explain the issue.
2.3Key Concepts
–Filters: The criteria used to narrow down the product list, such as searching by name, SKU, or category.
–Exact Match: A search requirement where the system looks for an item that matches a specific ID exactly, rather than just containing a piece of text.
–Text Containment: A search method that returns results if the search term is found anywhere within a specific field (e.g., searching "Blue" would return "Blue Shirt" and "Dark Blue Pants").
–Pagination: A method to control the volume of data returned by limiting the number of products shown per request, which helps keep the system fast and responsive.
–Sorting: The ability to arrange the final list of products in a specific order, such as alphabetically by name.
2.4Business Value

This feature empowers users to quickly locate specific items within a large product catalog without needing to manually browse through every entry. By supporting complex, multi-parameter searches, it reduces the time spent on administrative tasks and ensures that sales, inventory, and procurement teams can access the exact product data they need to make informed business decisions.
