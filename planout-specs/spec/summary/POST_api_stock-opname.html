1.  Data
1.1Overview

The "Create Stock Opname" feature provides a reliable way to record physical inventory counts in the Lumi ERP system. When a user submits a stock count, the system automatically compares the physical count against the current system records, calculates any discrepancies (variances), and saves the entire document as a single, unified record.

1.2Step-by-Step Flow
1.Submission: The user sends a request containing the main stock opname details (such as the store location and date) and a list of individual items counted.
2.Duplicate Check: The system verifies that this specific request has not been processed previously to prevent accidental duplicate entries.
3.Transaction Start: The system initiates a secure "all-or-nothing" process. This ensures that either the entire document and all its items are saved correctly, or nothing is saved at all if an error occurs.
4.Header Creation: The system creates the main stock opname record, automatically generating a unique reference code and timestamps.
5.Item Processing: For every item in the list, the system:

* Retrieves the current system quantity and average cost for that product.

* Calculates the difference between the physical count and the system quantity.

* Determines the financial adjustment amount based on that difference.

* Saves the item details along with these calculated values.

6.Completion: Once all items are processed, the transaction is finalized, and the system confirms the successful creation of the record.
1.3Key Concepts
–Stock Opname: A formal record of a physical inventory count used to reconcile actual stock levels with system records.
–Transaction: A safety mechanism that treats the entire submission as one unit; if any part of the data is invalid, the system rolls back the entire process to prevent partial or corrupted data.
–Variance: The difference between the quantity physically counted by the user and the quantity currently recorded in the system.
–Adjustment Amount: The financial impact of the inventory discrepancy, calculated by multiplying the variance by the product's average cost.
–Duplicate Prevention: A safeguard that uses a unique request identifier to ensure the same inventory count cannot be submitted twice.
1.4Business Value
–Data Integrity: By using a single transaction, the system guarantees that inventory records remain accurate and consistent, preventing "half-saved" documents.
–Automated Reconciliation: The system removes the manual burden of calculating variances and financial adjustments, reducing human error and saving time.
–Audit Readiness: Every stock opname is assigned a unique reference code and timestamp, providing a clear, traceable history of inventory adjustments for reporting and auditing purposes.
–Operational Reliability: Built-in checks for duplicates and invalid data ensure that the inventory database remains clean and trustworthy.
2.  LOGIC
2.1Overview

The "Create Stock Opname" feature provides a reliable way for the system to record physical inventory counts. When a user submits a stock count, this feature captures the details of the inventory check, compares the counted quantities against the system's current records, and calculates any discrepancies (variances) in both quantity and value. This ensures that the inventory records remain accurate and synchronized with the physical stock on hand.

2.2Step-by-Step Flow
1.Validation: The system first checks that the request is unique to prevent accidental duplicate entries.
2.Record Creation: The system creates a new "Stock Opname" header record, automatically assigning it a unique reference code and linking it to the current user and company.
3.Item Processing: For every product included in the count, the system performs the following:

* Checks for duplicate product entries within the same count.

* Retrieves the current system quantity and average cost for that product.

* Calculates the difference between the physical count and the system quantity.

* Calculates the financial impact (adjustment amount) based on the variance.

4.Finalization: All records are saved together. If any part of the process fails, the system cancels the entire operation to ensure no partial or incorrect data is saved.
2.3Key Concepts
–Stock Opname: A formal record of a physical inventory count performed at a specific store on a specific date.
–Atomicity (Transaction): A "all-or-nothing" approach where the system ensures that either the entire inventory count is saved successfully, or nothing is saved at all, preventing data errors.
–Variance: The difference between what the system thinks is in stock and what was actually counted.
–Snapshot: A record of the system's state (quantity and cost) at the exact moment the count was performed, which is preserved for historical auditing.
–Request Uniqueness: A safety mechanism that prevents the same inventory count from being processed twice if a network error occurs during submission.
2.4Business Value

This feature provides a robust audit trail for inventory management. By automatically calculating variances and financial adjustments, it reduces manual calculation errors and saves time for warehouse or store staff. Because the system captures a "snapshot" of costs and quantities at the time of the count, management can easily identify discrepancies, investigate stock shrinkage, and maintain high levels of inventory accuracy for financial reporting.
