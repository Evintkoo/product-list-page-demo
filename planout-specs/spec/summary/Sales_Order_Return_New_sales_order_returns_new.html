1.  Frontend
1.1Overview

The "New Sales Order Return" feature allows staff to process product returns from customers. This interface ensures that returns are linked to valid, existing sales invoices, maintains accurate inventory tracking by requiring a destination warehouse, and prevents over-returning items by validating quantities against the original invoice.

1.2Step-by-Step Flow
1.Initialization: When the page loads, the system prepares the form by loading available warehouses and customers. The return number is left blank, as it is generated automatically upon saving.
2.Customer Selection: The user selects a customer. This action clears any previously selected invoices or products to ensure data consistency.
3.Invoice Selection: Once a customer is chosen, the system displays a list of their eligible sales invoices. Selecting an invoice automatically populates the product table with items from that specific order.
4.Return Details: For each product, the user enters the quantity to be returned and a reason for the return. The system automatically calculates the total quantity and total monetary value of the return.
5.Validation: The system ensures that the returned quantity for any item does not exceed the "remaining" quantity (the amount not yet returned from the original invoice).
6.Submission: Once the user clicks "Save," the system validates that a warehouse, customer, and invoice are selected, and that at least one item is being returned.
7.Completion: Upon a successful save, the system generates a new return record and automatically navigates the user to the details page for that specific return.
1.3Key Concepts
–Remaining Quantity: A system-calculated limit that prevents users from returning more items than were originally purchased or previously returned.
–Draft Status: The initial state of a new return record, indicating it has been created but not yet processed or approved.
–Invoice-Linked Returns: A safety mechanism where returns must be tied to a specific, valid sales invoice to ensure accurate financial and inventory records.
–Total Returned/Amount: Real-time calculations that update as the user modifies quantities, providing immediate visibility into the scope of the return.
1.4Business Value
–Data Integrity: By linking returns directly to invoices and enforcing quantity limits, the system prevents errors and unauthorized returns.
–Operational Efficiency: Automating the calculation of return totals and streamlining the selection process reduces manual data entry and potential for human error.
–Inventory Accuracy: Requiring a destination warehouse ensures that returned goods are tracked correctly within the company's inventory system from the moment the return is initiated.
2.  Logic
2.1Overview

The "Sales Order Return" feature allows users to initiate a return process for items previously sold to a customer. By selecting a customer and a specific invoice, the system automatically identifies which products are eligible for return. The feature ensures data integrity by validating quantities against remaining stock before creating a formal return record in the system.

2.2Step-by-Step Flow
1.Customer Selection: The user selects a customer from the dropdown. The system automatically clears any previously selected invoices or product data to ensure the new return is accurate.
2.Invoice Loading: Once a customer is selected, the system fetches and displays a list of all invoices eligible for return for that specific customer.
3.Product Review: After an invoice is selected, the system displays the items from that invoice. Each item shows a "Remaining" quantity, which indicates how many units are still eligible for return (accounting for any previous returns).
4.Form Completion: The user enters the quantity to be returned and a reason for each item. The system prevents the user from entering a quantity higher than the "Remaining" amount.
5.Submission: Upon clicking "Save," the system validates the form one final time. If valid, it creates the return record.
6.Navigation: Once successfully saved, the system automatically redirects the user to the "Sales Order Return Details" page, where the return is set to "Draft" status, allowing for further processing or cancellation.
2.3Key Concepts
–Remaining Quantity: A read-only value that tracks how many units of an item are still eligible for return. It automatically subtracts any quantities already returned in previous transactions.
–Draft Status: The initial state of a newly created return, where the record is saved but not yet finalized, allowing for final review or adjustments.
–Validation: A built-in safety check that ensures all required fields (Warehouse, Customer, Invoice) are filled and that return quantities do not exceed the available balance.
–Eligible Invoices: Only invoices that have items available for return are displayed, simplifying the selection process for the user.
2.4Business Value
–Accuracy: By automatically calculating the "Remaining" quantity, the system prevents over-returning of items, reducing manual errors and inventory discrepancies.
–Efficiency: The automated flow from customer selection to invoice filtering saves time by removing the need for users to manually search for or verify returnable items.
–Auditability: Every return is linked to a specific invoice and customer, ensuring a clear trail of documentation for all returned goods.
–Workflow Control: By moving the user to a "Draft" state upon creation, the system enforces a structured process, ensuring that returns are properly reviewed before they are finalized.
3.  Data
3.1Overview

The "New Sales Order Return" feature allows staff to initiate the process of returning items from a previously issued sales invoice. This feature captures the necessary details—such as which items are being returned, the quantity, the reason for the return, and the destination warehouse—to ensure accurate inventory and financial tracking within the Lumi ERP system.

3.2Step-by-Step Flow
1.Form Entry: The user fills out the return form, selecting the customer, the original sales invoice, and the warehouse where the items will be returned.
2.Item Selection: The user specifies the quantity to be returned for each item from the invoice and provides a reason for each return.
3.Validation: Upon clicking "Save," the system checks that at least one item has a return quantity greater than zero. If no items are selected, the system prevents submission and displays an error.
4.Submission: The system processes the request, ensuring that only items with a valid return quantity are included. To prevent errors, the "Save" button is disabled during this process to avoid duplicate submissions.
5.Confirmation and Navigation: Once successfully created, the system automatically redirects the user from the entry form to the specific "Sales Order Return Details" page for the new record, where the return status is set to "Draft."
3.3Key Concepts
–Sales Order Return: A formal record documenting that goods previously sold to a customer are being brought back into inventory.
–Sales Invoice: The original document representing the sale, which serves as the reference point for identifying which items are eligible for return.
–Draft Status: The initial state of a new return record, indicating that the return has been created but has not yet been finalized or processed into the warehouse.
–Validation: A safety check performed by the system to ensure that the data entered is complete and logical before it is saved to the database.
3.4Business Value

This feature streamlines the returns process by centralizing data entry and ensuring that every return is linked to an original invoice. By requiring specific reasons for returns and validating quantities before submission, the system reduces manual errors, improves inventory accuracy, and provides a clear audit trail for customer service and accounting teams.
