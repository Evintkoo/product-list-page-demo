1.  Frontend
1.1Overview

The Deactivate Supplier feature provides a safe way to manage supplier status within the Lumi ERP system. When a user initiates the deactivation process, a confirmation window appears to prevent accidental changes. This ensures that users intentionally verify their decision before the system updates the supplier's status.

1.2Step-by-Step Flow
1.Initiation: The user triggers the deactivation process for a specific supplier.
2.Confirmation: A modal window appears asking, "Are you sure?" to confirm the action.
3.User Choice:

* If the user selects Cancel, the window closes, and no changes are made.

* If the user selects OK, the system proceeds to update the supplier's status.

4.Processing: The system automatically flips the supplier's current status (e.g., changing an active supplier to inactive).
5.Completion: Once the update is successfully processed, the modal closes, and the supplier list is updated to reflect the new status.
1.3Key Concepts
–Confirmation Modal: A pop-up window designed to act as a safety net, requiring the user to confirm an action before it is finalized.
–Status Toggle: The logic that automatically switches a supplier's status to the opposite of its current state (Active becomes Inactive, and vice versa).
–Error Handling: If the system encounters an issue while updating the status, an error message will appear within the modal to inform the user.
1.4Business Value

This feature improves data integrity and user experience by reducing the risk of human error. By requiring a deliberate confirmation step, the system prevents accidental deactivations that could disrupt supply chain operations. Additionally, the automated status-flipping logic simplifies the workflow for administrators, allowing them to manage supplier availability quickly and accurately without manual data entry.

2.  Logic
2.1Overview

The "Deactivate Component" feature allows users to easily toggle the status of a supplier within the Lumi ERP system. By clicking the "OK" button in the confirmation modal, the system automatically flips the supplier's current status—deactivating an active supplier or reactivating one that was previously inactive. The system is designed to handle these updates reliably, ensuring the user interface stays synchronized with the actual data.

2.2Step-by-Step Flow
1.Initiation: The user selects a supplier and clicks the "OK" button in the confirmation modal to proceed with the status change.
2.Processing: The system locks the button to prevent accidental duplicate requests while it communicates with the server.
3.Status Update: The system sends a request to the server to invert the supplier's current status (e.g., changing "Active" to "Inactive").
4.Success Handling: If the server confirms the update, the modal closes automatically, and the main supplier list refreshes to display the new status.
5.Error Handling: If the update fails for any reason, the modal remains open, the supplier's status remains unchanged, and an error message is displayed to inform the user of the issue.
2.3Key Concepts
–Toggle Logic: A simple "on/off" mechanism that automatically detects the current state of a supplier and switches it to the opposite state.
–Processing State: A safety feature that prevents the user from clicking the button multiple times while the system is busy, which helps avoid data errors.
–Data Synchronization: The process of ensuring that the list of suppliers shown on the screen always matches the most current information stored in the database.
–Error Resilience: A design approach that keeps the user informed and prevents data loss by keeping the modal open if a request fails, allowing the user to try again or investigate the error.
2.4Business Value

This feature streamlines supplier management by providing a quick, intuitive way to update supplier availability. By automating the status toggle and ensuring the interface remains consistent with the backend, the system reduces manual effort and minimizes the risk of human error. The built-in error handling and processing safeguards ensure that the user experience remains stable and reliable, even if network or server issues occur.

3.  Data
3.1Overview

The "Deactivate Supplier" feature allows users to officially mark a supplier as inactive within the Lumi ERP system. This process ensures that the system accurately reflects which suppliers are no longer in use, preventing them from being accidentally selected for new business activities while maintaining their historical records.

3.2Step-by-Step Flow
1.Selection: The user selects a specific supplier from the supplier list.
2.Verification: The system retrieves the current details of the selected supplier to confirm their identity and current status before proceeding.
3.Deactivation Request: Once confirmed, the system sends a request to update the supplier’s status to "inactive."
4.Status Update: The system processes the request, effectively removing the supplier from active status in the database.
3.3Key Concepts
–Supplier: A business entity or vendor managed within the ERP system.
–Deactivation: The process of changing a supplier's status to "inactive," which effectively archives them without deleting their historical data.
–Status Verification: A safety check performed by the system to ensure the correct supplier record is being modified.
3.4Business Value

This feature provides better data integrity and operational control. By allowing users to deactivate suppliers, the organization can clean up its active vendor list, reduce the risk of errors (such as placing orders with a discontinued supplier), and ensure that reporting remains accurate by focusing only on currently active business partners.
