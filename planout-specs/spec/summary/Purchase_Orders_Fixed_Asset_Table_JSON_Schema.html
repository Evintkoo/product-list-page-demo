1.  Data
1.1Overview

This feature provides the logic for retrieving and displaying a list of purchase orders within the Lumi ERP system. It is designed to support two distinct views: the "Standard" purchase order list and the "Fixed Assets" purchase order list. By using a unified data retrieval process, the system ensures that users can efficiently filter, sort, and view their procurement records, including real-time counts of related deliveries, invoices, and returns.

1.2Step-by-Step Flow
1.Request Initiation: The system receives a request for a list of purchase orders. It automatically identifies the user's company to ensure data privacy and security.
2.Filtering: The system applies any user-selected filters, such as the order type, specific date ranges, supplier information, or the "Fixed Asset" status (which determines whether the order appears on the Standard or Fixed Assets tab).
3.Data Retrieval: The system fetches the core purchase order details from the database.
4.Information Enrichment: For every order found, the system automatically looks up the associated supplier and warehouse names to provide a human-readable display.
5.Document Counting: The system performs a real-time calculation to count how many delivery documents, invoices, and return documents are linked to each purchase order.
6.Pagination and Sorting: The final list is sorted according to user preferences (e.g., by date or reference code) and paginated to ensure the interface remains fast and responsive.
7.Response: The system returns the organized list of orders along with the total count of records to support the pagination controls in the user interface.
1.3Key Concepts
–Fixed Asset Flag: A simple true/false indicator that categorizes a purchase order, allowing the system to separate standard procurement from fixed asset acquisitions.
–Dynamic Counting: Instead of storing static numbers, the system calculates the number of related documents (deliveries, invoices, returns) on the fly, ensuring the information is always up-to-date.
–Scope: All data is automatically filtered by the user's company, preventing cross-company data visibility.
–Pagination: A method of breaking large lists into smaller, manageable pages (e.g., 20 items at a time) to improve system performance.
–Workflow State: The current status of an order (e.g., Draft, Sent, Received, or Cancelled), which helps users track the progress of their procurement.
1.4Business Value
–Improved Organization: By separating standard purchases from fixed assets, procurement teams can manage their workflows more effectively without cluttering their view.
–Operational Visibility: Users can see at a glance how many invoices or deliveries are associated with a specific order, reducing the need to click into individual records to check their status.
–Performance and Scalability: The use of efficient database queries and pagination ensures that the system remains fast, even as the company’s volume of purchase orders grows over time.
–Data Accuracy: Because the system calculates related document counts dynamically, users are guaranteed to see the most current status of their orders without manual reconciliation.
