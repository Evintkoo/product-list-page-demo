1.  Logic
1.1Overview

This feature allows users to update existing customer information and manage their associated addresses through the Lumi ERP system. It ensures that customer data remains accurate and consistent by enforcing strict validation rules before saving any changes. All updates to a customer's profile and their address list are processed as a single "all-or-nothing" operation, meaning if any part of the update fails, the entire request is rejected to prevent data errors.

1.2Step-by-Step Flow
1.Verification: The system checks if the customer exists and belongs to the current company. If not found, the request is rejected.
2.Data Validation: The system verifies that all required fields (name, phone, store, and service tax) are provided and that the data follows specific formats (e.g., valid email, phone length of at least 6 characters, and a unique customer code).
3.Customer Update: The system updates the customer’s core profile information with the new details provided.
4.Address Management: The system processes the list of addresses:

* Existing addresses are updated if changes are provided.

* New addresses are added if they are missing an ID.

* Addresses marked for removal are deleted.

5.Final Integrity Check: The system ensures that at least one address remains and that exactly one address is designated as the "main" address.
6.Completion: If all checks pass, the changes are saved permanently, and the updated customer profile is returned. If any rule is broken, the system cancels all changes to maintain data integrity.
1.3Key Concepts
–Atomic Transaction: A safety mechanism that ensures all updates (customer details and address changes) are saved together; if one part fails, nothing is saved.
–Validation Rules: Mandatory checks that prevent incomplete or incorrect data from being saved, such as ensuring a valid email format or preventing duplicate customer codes.
–Address Lifecycle: The ability to add, update, or remove addresses in a single request, while strictly enforcing that every customer must have at least one address and exactly one "main" address.
–Error Handling: Clear feedback provided to the user if a request is invalid (e.g., missing required fields or unauthorized access), allowing for quick corrections.
1.4Business Value

This feature provides a reliable and efficient way to maintain customer records. By automating the validation of contact details and address management, it reduces the risk of human error and ensures that customer data is always clean and usable for business operations. The "all-or-nothing" update process guarantees that the system never ends up in a partially updated or inconsistent state, providing peace of mind for data accuracy.

2.  Data
2.1Overview

This feature allows the system to update existing customer information and manage their associated addresses through a single request. It ensures that all changes—whether updating contact details or modifying address lists—are processed together as one complete action. The system includes built-in safeguards to ensure that customer data remains accurate and that address requirements (such as always having a primary shipping address) are strictly followed.

2.2Step-by-Step Flow
1.Verification: The system first confirms that the customer exists and belongs to the company making the request.
2.Customer Update: The system updates the customer’s core details (such as name, email, or phone number) with the provided information.
3.Address Processing: The system iterates through the provided list of addresses:

* If an address is marked for removal, it is deleted.

* If an address already exists, it is updated with the new details.

* If it is a new address, it is added to the customer's profile.

4.Business Rule Validation: The system checks that the final list of addresses meets mandatory requirements (e.g., exactly one main address exists).
5.Finalization: If all rules are met, the changes are saved permanently. If any rule is violated, the entire process is canceled to prevent data errors.
2.3Key Concepts
–Atomic Transaction: A "all-or-nothing" approach where the customer details and address changes are saved together; if any part of the update fails, nothing is saved.
–Address Validation: A set of mandatory rules that ensure every customer profile remains functional, specifically requiring at least one address and exactly one designated "main" shipping address.
–Address Lifecycle Management: The ability to add, update, or remove multiple addresses in a single operation based on the instructions provided in the request.
–Data Integrity: Safeguards that prevent unauthorized changes (such as modifying a customer belonging to a different company) or invalid data entries (such as missing required fields).
2.4Business Value

This feature streamlines customer management by allowing front-end applications to synchronize a customer's entire profile in one efficient step. By enforcing strict validation rules at the database level, the system prevents "orphaned" records or incomplete customer profiles, ensuring that shipping and contact information remains reliable for downstream business operations like invoicing and logistics.
