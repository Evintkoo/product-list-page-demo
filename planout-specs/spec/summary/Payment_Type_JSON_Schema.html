1.  Logic
1.1Overview

This feature provides a structured way for the system to retrieve and display a list of payment methods. It allows users to search, filter, and view payment types (such as credit cards or bank transfers) while ensuring the data is organized into manageable pages for better performance and readability.

1.2Step-by-Step Flow
1.Receive Request: The system receives a request containing specific filters (such as active status, name, or refund settings) and pagination preferences (which page to show and how many items per page).
2.Filter Data: The system searches the payment database, applying the requested filters to narrow down the results to only the relevant payment types.
3.Count Results: The system calculates the total number of items that match the filters to determine how many pages of data exist.
4.Calculate Pagination: Based on the total count and the requested page size, the system determines the total number of pages available.
5.Return Data: The system sends back the requested list of payment types along with the pagination details (current page, total pages, and total item count) to be displayed on the screen.
1.3Key Concepts
–Pagination: A method of breaking a large list of data into smaller, numbered pages so the user doesn't have to load everything at once.
–Filtering: The ability to narrow down the list of payment types based on specific criteria, such as whether they are currently active or if they support refunds.
–Metadata: Additional information provided with the data (like the total number of pages) that helps the user interface know how to display navigation controls.
1.4Business Value
–Improved Performance: By loading data in smaller chunks (pagination), the application remains fast and responsive even as the number of payment methods grows.
–Enhanced Usability: Users can quickly find specific payment methods using the search and filter options, reducing the time spent navigating through long lists.
–Data Accuracy: By centralizing the logic for how payment types are retrieved, the system ensures that users always see consistent, up-to-date information regarding which payment methods are active and their specific capabilities (like refund support).
2.  Data
2.1Overview

This feature provides the underlying logic for the "Payment Types" list screen within the Lumi ERP. It allows users to view, search, and filter the various payment methods configured in the system. By organizing these methods—such as credit cards or digital payment services—the system ensures that financial transactions are processed with the correct provider fees and accounting rules applied.

2.2Step-by-Step Flow
1.Define Search Criteria: The system receives your filter requests, such as the payment name, the type of payment, whether refunds are enabled, or if the payment method should bypass standard invoice receivable processes.
2.Calculate Page Position: The system determines which specific "slice" of data to show based on your current page number and how many items you want to see per page.
3.Retrieve Filtered Data: The system searches the database for all active payment methods that match your specific criteria and sorts them alphabetically by name.
4.Calculate Total Count: The system performs a secondary check to count the total number of matching records. This allows the interface to display accurate pagination (e.g., "Showing 1-10 of 50 results").
5.Return Results: The system sends the requested list of payment methods and the total count back to your screen for display.
2.3Key Concepts
–Payment Type: A specific method of payment (e.g., Visa, PayPal, Bank Transfer) that includes details like provider fees and specific accounting behaviors.
–Pagination: A method of breaking a large list of data into smaller, manageable pages to ensure the screen loads quickly and remains easy to navigate.
–Filtering: The ability to narrow down the list of payment methods based on specific attributes, such as whether the method is currently active or if it supports refunds.
–Provider Fee Rate: A percentage or fixed cost associated with a specific payment service, used by the ERP to calculate transaction costs.
2.4Business Value

This feature centralizes the management of payment methods, ensuring that the finance team has a clear, searchable view of all available options. By automating the application of provider fees and accounting rules (like skipping invoice receivables), the system reduces manual data entry errors and ensures that financial reporting remains consistent and accurate across the organization.
