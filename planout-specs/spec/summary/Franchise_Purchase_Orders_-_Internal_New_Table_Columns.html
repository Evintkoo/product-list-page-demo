1.  Frontend
1.1Overview

The Franchise Purchase Order table is a dynamic interface designed to help users build a list of products for internal purchase orders. It allows users to add or remove product rows, search for specific items, and input quantities and pricing. The system automatically handles calculations for individual line items and the overall order total, ensuring accuracy and efficiency during the data entry process.

1.2Step-by-Step Flow
1.Add Items: The user begins with an empty row and can click the "Add Product" button to include additional items in the order.
2.Search and Select: The user searches for a product by typing at least three characters. Once selected, the system automatically populates the "Store Quantity" field.
3.Input Details: For each product, the user manually enters the "Order Quantity," "Supply Price," and any necessary "Store Remarks."
4.Automatic Calculation: As the user enters quantities and prices, the system instantly calculates the "Amount" for that specific row.
5.Review Total: The system maintains a running total at the bottom of the table, which updates automatically whenever a row is modified.
6.Manage Rows: If a user needs to remove an item, they can click the "X" button on the corresponding row to delete it from the order.
1.3Key Concepts
–Dynamic Row Management: The ability to add or remove product entries on the fly, providing flexibility for orders of any size.
–Auto-Calculation: Features that reduce manual math errors by automatically computing row totals and the grand total based on user input.
–Data Validation: Built-in safeguards that ensure quantities are positive numbers and required fields (like remarks and prices) are filled out before the order is processed.
–Smart Search: A search function that triggers after three characters are entered, ensuring the user selects the correct product from the database.
1.4Business Value

This feature streamlines the franchise procurement process by replacing manual entry with a guided, automated interface. By automating calculations and providing immediate feedback on inputs, the system reduces the likelihood of human error, saves time for staff, and ensures that purchase order data is consistent and accurate before it is submitted to the inventory system.

2.  Logic
2.1Overview

This feature introduces a structured data entry table for franchise purchase orders within the Lumi ERP system. It provides a standardized way for users to input product details, ensuring that every item added to an order is accurately recorded, validated, and formatted before it is submitted to the system.

2.2Step-by-Step Flow
1.Initialize Row: When a user begins adding a new item to a purchase order, the system generates a blank row with default values (zero quantities and empty text fields) to ensure a consistent starting point.
2.Data Entry: The user fills in the specific product details, including the product identifier, current store stock, the quantity they wish to order, the supply price, and any relevant notes.
3.Mapping: As the user enters information, the system maps these inputs to the internal purchase order schema, ensuring the data is organized correctly for the database.
4.Validation: Before the order is finalized, the system performs integrity checks. It confirms that a product has been selected and ensures that the order quantity is a valid, positive number.
5.Submission: Once validated, the item data is accepted and ready to be processed as part of the official franchise purchase order.
2.3Key Concepts
–Product Identifier: The unique code used to distinguish one specific item from another in the inventory.
–Store Quantity: The amount of a specific product currently held in the franchise store's inventory.
–Order Quantity: The specific amount of a product the franchise is requesting to purchase; this must always be a positive number.
–Supply Price: The cost per unit of the product being ordered.
–Store Remark: An optional text field allowing the user to add specific notes or instructions regarding that particular line item.
2.4Business Value
–Data Accuracy: By enforcing validation rules (such as requiring a product ID and positive quantities), the system prevents common entry errors that could lead to incorrect shipments or billing issues.
–Operational Efficiency: Standardizing the input process ensures that franchise staff can quickly and reliably create purchase orders without needing to manually format data.
–System Integrity: Mapping inputs directly to the internal schema ensures that the data remains consistent across the entire ERP platform, making it easier to track inventory and financial records accurately.
3.  Data
3.1Overview

This feature introduces a new, interactive table for the Lumi ERP system designed to streamline how franchise purchase orders are created. It provides a structured interface where staff can select products and define order quantities, ensuring that all necessary details for a franchise request are captured accurately in one place.

3.2Step-by-Step Flow
1.Product Selection: The user selects a product from the catalog, which automatically populates the relevant item details.
2.Quantity Entry: The user enters the quantity currently held at the store ("Store Qty") and the quantity they wish to request ("Order Qty").
3.Price Display: The system automatically retrieves and displays the current supply price for the selected product, ensuring the user has up-to-date cost information.
4.Adding Remarks: The user can add any specific notes or instructions for the order in the remarks field.
5.Saving Data: Once the details are entered, the system bundles this information and saves it to the franchise purchase order record.
3.3Key Concepts
–Product Selector: A tool that allows users to pick items from the inventory catalog, ensuring consistency in product identification.
–Supply Price: The cost of a product, which is automatically pulled from the system to prevent manual entry errors.
–Store Quantity: The current stock level reported by the franchise, used to help determine the necessity of the order.
–Order Quantity: The specific amount of product the franchise is requesting to purchase.
–Remark: A flexible text field for any additional context or special instructions regarding a specific line item.
3.4Business Value
–Increased Accuracy: By automating the retrieval of supply prices and using a standardized product selector, the system reduces the risk of manual data entry errors.
–Improved Efficiency: Consolidating all order details into a single, intuitive table allows staff to process franchise requests faster.
–Better Inventory Visibility: Capturing both current store stock and requested order quantities provides management with clearer insights into franchise inventory needs and replenishment patterns.
