1.  Frontend
1.1Overview

The "Edit Retail Customer" page allows users to update existing customer information within the Lumi ERP system. When a user opens this page, it automatically loads the current details of the selected customer into a form. Users can modify various aspects of the customer profile—including personal details, tax information, SAP reporting data, customer groups, and address lists—before saving their changes.

1.2Step-by-Step Flow
1.Data Loading: Upon opening the page, the system fetches the existing customer record and populates all form fields with the current data.
2.Editing: The user updates information across several sections (Details, Tax, SAP Reporting, Customer Groups, and Addresses).
3.Validation: As the user makes changes, the system performs real-time checks. Specifically, it ensures that the Name, Phone number (minimum 6 characters), Store, and Service Tax fields are correctly filled.
4.Submission: When the user clicks "Save," the system performs a final validation. If any required information is missing or incorrect, the system highlights the specific fields that need attention.
5.Completion: If the data is valid, the system saves the updates to the database. Upon a successful save, the user is redirected back to the customer list with a confirmation message.
6.Cancellation: If the user chooses to cancel at any point, all unsaved changes are discarded, and the user is returned to the customer list without any data being updated.
1.3Key Concepts
–Form Validation: A built-in safety check that prevents the submission of incomplete or incorrect data, specifically requiring fields like Name, Phone, Store, and Service Tax.
–Data Persistence: The process of updating the customer record in the system database only when the "Save" button is clicked.
–Address Management: A flexible feature allowing users to add, edit, or remove multiple addresses for a single customer, with the ability to designate one as the "Main Address."
–Error Handling: If a save attempt fails due to invalid data, the system keeps the user on the page and highlights the specific errors so they can be corrected without losing the work already entered.
1.4Business Value

This feature ensures data accuracy and operational efficiency by providing a centralized, user-friendly interface for maintaining customer records. By enforcing mandatory fields and providing immediate feedback on errors, the system prevents incomplete data from entering the ERP, which is critical for accurate reporting, tax compliance, and effective communication with retail customers.

2.  Logic
2.1Overview

The Retail Customer Edit page allows users to update existing customer information within the Lumi ERP system. When a user opens the page, the system automatically retrieves the customer's current details and populates the form. Users can modify various fields—including contact information, tax details, and addresses—and save their changes. The system includes built-in validation to ensure that essential information is provided before any updates are finalized.

2.2Step-by-Step Flow
1.Page Initialization: When the page loads, the system fetches the specific customer's data and the necessary dropdown options (such as store locations and tax categories) simultaneously.
2.Data Loading: Once both the customer data and dropdown options are retrieved, the form is populated with the existing information. If the customer cannot be found, the user is automatically redirected back to the customer list.
3.User Editing: The user updates the desired fields. The system supports a wide range of data, including personal details, tax identifiers, SAP reporting codes, and address management.
4.Validation: When the user clicks "Save," the system checks that the Name, Phone (minimum 6 characters), Store, and Service Tax fields are filled.
5.Submission: If the data is valid, the system sends the updated information to the server.
6.Completion:

* If successful, the user is redirected to the Customer Detail page with a confirmation message.

* If there are errors (e.g., invalid data), the user remains on the edit page, and the specific fields with issues are highlighted so they can be corrected.

2.3Key Concepts
–Data Mapping: The process of ensuring that information entered into the form fields (like "Name" or "Store") is correctly translated into the format the system database requires.
–Validation Rules: Mandatory checks performed by the system to prevent incomplete or incorrect data from being saved.
–Dropdown Lookups: Pre-defined lists (like available stores or tax types) that ensure users select valid options rather than typing them manually.
–Address Management: The ability to add, edit, or remove multiple addresses for a single customer, including designating a "Main Address."
2.4Business Value

This feature ensures data integrity and operational efficiency by providing a structured, validated interface for maintaining customer records. By enforcing mandatory fields and providing clear error feedback, the system reduces the risk of incomplete customer profiles, which is critical for accurate reporting, tax compliance, and effective customer management within the ERP.

3.  Data
3.1Overview

The Retail Customer Edit page allows staff to view and update information for existing retail customers within the Lumi ERP system. This feature ensures that customer records remain accurate and up-to-date by providing a structured form with built-in validation to prevent incomplete or incorrect data entry.

3.2Step-by-Step Flow
1.Page Loading: When you open the edit page for a specific customer, the system automatically retrieves the customer's current details and populates the form.
2.Dropdown Preparation: Simultaneously, the system fetches the latest lists for stores and service tax options to ensure you are selecting from current, valid choices.
3.Validation Check: When you click "Save," the system checks your entries to ensure the customer's name, store, and service tax are provided, and that the phone number is at least 6 characters long.
4.Error Handling: If any required information is missing or invalid, the system will highlight the specific fields that need attention so you can correct them.
5.Successful Update: Once the information is valid and saved, you are redirected to the customer's detail page, where a confirmation message will appear to let you know the update was successful.
6.Missing Record Handling: If you attempt to access a customer record that no longer exists, the system will automatically redirect you back to the main customer list.
3.3Key Concepts
–Data Validation: A safety check that ensures all required fields are filled out correctly before the system accepts the changes.
–Metadata: The supporting information (such as store names and tax categories) used to populate dropdown menus, ensuring consistency across the system.
–Retail Customer: A specific category of customer within the ERP that requires unique fields, such as store assignment and specific tax classifications.
3.4Business Value

This feature streamlines the administrative process of managing retail customer data. By enforcing data quality at the point of entry, it reduces the risk of human error and ensures that reporting and tax calculations remain accurate. The intuitive validation and clear feedback loops help staff manage customer records efficiently, saving time and maintaining a reliable database.
