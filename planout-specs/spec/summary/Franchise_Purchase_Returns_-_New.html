1.  Frontend
1.1Overview

The "Franchise Purchase Returns" feature allows store staff to initiate a return of goods back to the franchisor. This process ensures that inventory adjustments are tracked accurately, linked to original purchase orders, and follow a standardized workflow from the initial draft stage through to final approval.

1.2Step-by-Step Flow
1.Initialization: When the page loads, the system automatically retrieves a list of available stores and internal suppliers (franchisors).
2.Selection: The user selects the store initiating the return and the specific internal supplier receiving the goods.
3.Order Linking: Once the store and supplier are selected, the user can search for and select the relevant original purchase order.
4.Product Review: The system populates a table showing the products from the selected order, including details like current store quantity, original order quantity, and the maximum amount allowed for return.
5.Data Entry: The user enters the specific quantity to be returned for each item and provides a reason for the return.
6.Submission: Upon clicking "Save," the system records the return as a "Draft" and redirects the user to a confirmation page to view the status of the request.
1.3Key Concepts
–Workflow Status: A visual tracker that displays the current stage of the return (Draft, Confirmed, Sent, or Approved), ensuring transparency throughout the process.
–Internal Supplier: A restricted list of suppliers representing the franchisor, ensuring returns are only processed within the authorized franchise network.
–Reference Code: A system-generated, unique identifier for the return document, ensuring every transaction is easily traceable.
–Max Return Quantity: A safety control that prevents users from returning more items than were originally purchased.
1.4Business Value
–Accuracy: By linking returns to original purchase orders, the system prevents errors and ensures that inventory levels are adjusted based on verified historical data.
–Efficiency: Automating the retrieval of store and supplier lists reduces manual data entry and minimizes the risk of selecting incorrect entities.
–Compliance: The structured workflow ensures that all returns are documented and approved according to company policy, providing a clear audit trail for franchise operations.
2.  Logic
2.1Overview

The Franchise Purchase Returns feature allows store users to initiate a return of goods back to the franchisor. This process is designed specifically for "internal" returns, ensuring that items are correctly tracked from the store back to the central supplier. The system guides the user through selecting the store, the supplier, and the specific purchase order associated with the items being returned.

2.2Step-by-Step Flow
1.Initialization: When the page loads, the system automatically populates the "Return From" (Store) and "Return To" (Supplier) dropdowns. The supplier list is restricted to internal franchisor entities only.
2.Selection: The user selects the store and the internal supplier.
3.Order Search: Once a store and supplier are selected, the user can search for a specific purchase order. The search activates after the user types at least three characters.
4.Product Loading: Once a purchase order is selected, the system displays the relevant products associated with that order.
5.Submission: The user completes the return details (such as quantities and notes) and submits the form.
6.Confirmation: Upon successful submission, the return is saved as a "draft" and the user is redirected to a confirmation page.
2.3Key Concepts
–Internal Return: A specific type of return process where goods are sent back to the franchisor rather than an external vendor.
–Draft Workflow State: The initial status of a return record, indicating it has been created but is still in the early stages of processing.
–Searchable Purchase Order: A dynamic field that filters available orders based on the store and supplier selected, ensuring only relevant data is displayed.
–Sender/Receiver Mapping: The system automatically assigns the store as the "sender" and the franchisor as the "receiver" to ensure accurate inventory accounting.
2.4Business Value
–Accuracy: By restricting the supplier list to internal entities and linking returns to specific purchase orders, the system prevents errors in inventory reconciliation.
–Efficiency: The search-as-you-type functionality for purchase orders saves time for store staff by quickly narrowing down the correct transaction.
–Standardization: Automating the "internal" return type and workflow state ensures that all franchise returns follow a consistent process, making it easier for the finance and warehouse teams to track returned stock.
3.  Data
3.1Overview

The Franchise Purchase Return feature allows users to formally initiate the return of inventory items from a specific franchise store back to an internal supplier. This process ensures that all returns are tracked accurately within the Lumi ERP system, linking the returned goods to their original purchase orders and maintaining a clear audit trail of inventory movement.

3.2Step-by-Step Flow
1.Select Origin: The user selects the specific franchise store that is initiating the return from a list of available locations.
2.Select Destination: The user selects the internal supplier receiving the returned goods from a filtered list of internal entities.
3.Enter Return Details: The user provides necessary information, including a reference code, the type of return, the current status of the workflow, and any relevant notes.
4.Identify Items: The user specifies the product and quantity being returned, linking these items to the original purchase order.
5.Finalize Submission: The system saves the return request, ensuring that both the high-level return information (the header) and the specific item details are recorded together as a single, complete transaction.
3.3Key Concepts
–Franchise Purchase Return: A formal record used to track inventory being sent back from a store to an internal supplier.
–Internal Supplier: A business entity within the organization that acts as a source of supply for franchise stores.
–Workflow State: The current stage of the return process (e.g., pending, approved, or completed), which helps manage the lifecycle of the return.
–Reference Code: A unique identifier assigned to the return request to make it easy to search for and track in the system.
–Transaction: A safety mechanism that ensures the return header and the individual items are saved simultaneously; if one part fails, the entire record is not saved, preventing data errors.
3.4Business Value
–Inventory Accuracy: By formalizing the return process, the system ensures that stock levels at both the franchise store and the internal supplier remain accurate and up-to-date.
–Operational Efficiency: Automating the return workflow reduces manual paperwork and minimizes errors associated with tracking returned goods.
–Improved Accountability: Linking returns to specific purchase orders provides clear visibility into why items are being returned and ensures that the correct internal entities are credited or debited accordingly.
