1.1Overview

The Tax Card is a dedicated section within the Service Product edit page designed to manage all tax-related settings for a specific service. It provides a centralized interface where users can select primary and secondary tax types, as well as define specific accounting and reporting codes required for tax compliance.

1.2Step-by-Step Flow
1.Header Identification: The user identifies the section by the "TAX" label and the percent (%) icon located at the top of the card.
2.Primary Tax Selection: The user selects the main tax type (e.g., PPN) from a required dropdown menu.
3.Secondary Tax Selection: The user selects the secondary tax type (e.g., PPh 23) from a second required dropdown menu.
4.Optional Configuration: The user may optionally populate additional fields to ensure accurate financial reporting:

* Tax Product Code: Selects the appropriate e-Faktur code.

* Tax Unit of Measure: Defines the unit associated with the tax calculation.

* Other Tax Account: Selects the specific Chart of Accounts entry for the secondary tax.

* Other Tax Refund Account: Selects the specific Chart of Accounts entry for secondary tax refunds.

5.Validation: The system automatically checks that both the "Tax" and "Other Tax" fields are filled. If these mandatory fields are empty, the form will be flagged as incomplete.
1.3Key Concepts
–Mandatory Fields: The "Tax" and "Other Tax" fields are required; the form cannot be considered complete without these selections.
–Dropdown Selection: All inputs use a standardized selection list, allowing users to either choose from existing data or clear their selection if needed.
–Pre-selection: To improve efficiency, the system automatically loads existing tax settings if they have been previously configured for the service product.
–Real-time Validation: The system monitors the status of the mandatory fields instantly as the user makes changes, ensuring data integrity without requiring a manual "save" to trigger a check.
1.4Business Value
–Compliance: By mandating the selection of primary and secondary taxes, the system ensures that all service products are correctly categorized for tax reporting purposes.
–Efficiency: Pre-loading existing tax data reduces manual data entry and minimizes the risk of human error when editing service products.
–Standardization: Providing specific fields for tax product codes and accounting accounts ensures that financial data is consistent across the entire ERP system, simplifying the reconciliation process for the accounting team.
