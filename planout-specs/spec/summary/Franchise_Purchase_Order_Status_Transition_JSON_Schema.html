1.  Data
1.1Overview

This feature manages the lifecycle of Franchise Purchase Orders within the Lumi ERP system. It ensures that when a store receives an order, the system accurately updates the store's inventory levels and maintains a clear audit trail. The process is designed to be "atomic," meaning that all related updates—such as changing the order status, adjusting stock counts, and logging history—happen together as a single, reliable action. If any part of the process fails, the entire operation is canceled to prevent data errors.

1.2Step-by-Step Flow
1.Verification and Locking: When a "receive order" request is initiated, the system first locks the specific purchase order to ensure no other changes can be made to it simultaneously. It verifies that the order is currently in the "placed" state.
2.Processing Line Items: For every product in the order, the system:

* Updates the specific item record with the received quantity and cost.

* Checks the store's current stock levels.

* Either increases the existing stock count or creates a new stock record if the product is new to that store.

* Records a detailed history entry to track the inventory movement.

3.Finalizing the Order: Once all items are processed, the system updates the order status to "store_received," adds a unique reference code, and saves the final notes.
4.Completion: The transaction is finalized. If any step fails (e.g., the order was already processed), the system rolls back all changes to ensure the inventory remains accurate.
1.3Key Concepts
–Atomic Transaction: A safety mechanism that ensures a group of database changes either all succeed together or all fail together, preventing partial or corrupted data.
–Locking (SELECT ... FOR UPDATE): A method of "reserving" a record so that no other user or process can modify it until the current operation is finished, preventing conflicts.
–Inventory Reconciliation: The process of automatically updating store stock levels based on received purchase orders, ensuring the digital inventory matches physical reality.
–Audit Trail: A history log that tracks every inventory change, providing accountability and visibility into why and when stock levels were adjusted.
1.4Business Value
–Data Integrity: By using atomic transactions and locking, the system prevents common errors like double-counting inventory or processing the same order twice.
–Operational Efficiency: Automating the transition from "placed" to "received" reduces manual data entry and minimizes the risk of human error during the receiving process.
–Accurate Reporting: Because inventory and history logs are updated in real-time as part of the receiving flow, store managers have immediate access to accurate stock levels and reliable audit records for financial and operational oversight.
