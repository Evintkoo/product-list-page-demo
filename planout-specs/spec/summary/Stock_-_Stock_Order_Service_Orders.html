1.  Frontend
1.1Overview

The "Stock Order - Service Orders" feature provides a dedicated view within the Inventory module for tracking stock orders specifically linked to service orders. This interface allows users to monitor the status, financial details, and fulfillment progress of these orders in a clear, organized table format.

1.2Step-by-Step Flow
1.Initial Load: When the page is opened, the system automatically fetches the most recent stock orders associated with service orders and displays them in the table.
2.Filtering: Users can refine the list using the Search Toolbar. By entering criteria such as specific order codes, date ranges, store or warehouse locations, or workflow statuses, the system updates the table to show only the relevant records.
3.Data Display: The table presents key information for each order, including dates, associated store/warehouse, current status, and financial amounts (order vs. received).
4.Navigation: Users can click on a specific Stock Order code to navigate directly to that order's detailed view, or click on a Service Order reference to view the original service request.
1.3Key Concepts
–Stock Order: A formal request for inventory items, in this case, triggered by a service-related requirement.
–Service Order: The original customer or internal request that necessitated the stock order.
–Workflow State: The current progress of the order (e.g., pending, in-progress, completed), represented by a visual status badge.
–Search Toolbar: A set of controls that allows users to filter the list of orders by various parameters like date, location, or status.
–Order vs. Receive Amount: A comparison showing the total value requested versus the value of items actually received, helping to track fulfillment accuracy.
1.4Business Value

This feature centralizes the management of service-related inventory, reducing the time spent searching for order status. By providing clear visibility into both the financial and logistical aspects of these orders, it enables staff to quickly identify pending deliveries, track fulfillment progress, and ensure that service orders are supported by the necessary inventory in a timely manner.

2.  Logic
2.1Overview

The Stock Order Service feature provides a dedicated view for managing inventory requests linked to service orders. It allows users to search, filter, and view a list of stock orders specifically related to service operations. The system automatically pulls this data, formats it for readability, and presents it in a clear table format for easy tracking of order status and financial details.

2.2Step-by-Step Flow
1.Data Retrieval: When the page loads or a user performs a search, the system requests a list of stock orders filtered specifically for "service orders."
2.Filtering: Users can narrow down the list using various criteria, such as specific order codes, date ranges, store or warehouse locations, and current workflow status.
3.Data Mapping: The system takes the raw data from the database and assigns it to the appropriate columns in the table (e.g., mapping "created_at" to the "Date" column).
4.Formatting: The system applies display rules to make the data user-friendly:

* Monetary values (order and receive amounts) are formatted as currency.

* Dates are converted into a readable format.

* Statuses are displayed as visual badges.

5.Rendering: The final table is populated. If an order has not yet been received, the "Received At" field remains blank.
6.Navigation: Users can click on a Stock Order code to view its specific details or click on a Service Order code to navigate to the original service request.
2.3Key Concepts
–Stock Order: A request for inventory items needed to fulfill a specific business requirement.
–Service Order: The originating request that triggered the need for stock; this feature links the two so users can see the relationship between the service and the inventory.
–Workflow State: The current stage of the order (e.g., pending, in-progress, completed), displayed as a status badge for quick identification.
–Reference Path: A direct link that allows users to jump from the stock order list to the original service order document.
2.4Business Value

This feature improves operational efficiency by centralizing service-related inventory data. By providing a clear, searchable, and formatted view of stock orders, staff can quickly verify the status of parts or materials needed for service jobs. This reduces manual lookup time, helps prevent inventory delays, and ensures that financial tracking (order vs. received amounts) is accurate and transparent.

3.  Data
3.1Overview

The Stock Order Service feature provides a dedicated view within the Lumi ERP system to track inventory requests that originate specifically from service orders. This allows staff to easily monitor the lifecycle of stock items—from the initial request through to final receipt—ensuring that parts or materials needed for service tasks are accounted for and managed efficiently.

3.2Step-by-Step Flow
1.Request Data: The system automatically queries the inventory database to retrieve all stock orders specifically tagged as "service orders."
2.Data Processing: The system organizes the raw information into a structured format, ensuring that details like order dates, store locations, and current status are correctly aligned.
3.Display in Table: The processed data is presented in a clear, row-by-row table format.
4.User Interaction: Users can click on specific stock order codes to view order details or click on service order references to navigate directly to the original service request.
5.Status Tracking: The system displays the current progress of the order (e.g., pending, received) and updates the "Received At" date once the inventory has been processed.
3.3Key Concepts
–Stock Order: A formal request for inventory items to be moved or allocated to a specific location.
–Service Order: The originating request that triggered the need for stock, such as a repair or maintenance job.
–Workflow State: The current stage of the order, displayed as a status badge to help users quickly identify if an order is active, delayed, or completed.
–Reference Path: A direct digital link that allows users to jump from the inventory record back to the original service request for context.
3.4Business Value

This feature bridges the gap between service operations and inventory management. By centralizing service-related stock orders, the business gains better visibility into supply chain needs, reduces the time spent manually searching for order statuses, and ensures that service teams have the necessary parts available when they are needed. This leads to improved operational efficiency and more accurate inventory tracking.
