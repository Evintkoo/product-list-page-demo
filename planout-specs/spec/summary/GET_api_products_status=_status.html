1.  LOGIC
1.1Overview

The Product API allows authorized users to retrieve a list of products from the Lumi ERP database. This feature is designed to be flexible, enabling users to search for products based on specific criteria—such as their status (active or inactive), brand, type, or tags—while also supporting pagination to ensure the system remains performant when handling large amounts of data.

1.2Step-by-Step Flow
1.Security Check: The system first verifies that the user is logged in and possesses the necessary permissions to view the product list.
2.Filter Validation: The system checks the search criteria provided in the request to ensure they are formatted correctly and contain valid data types.
3.Reference Verification: If the user is filtering by specific categories like "Brand" or "Product Type," the system confirms that these items actually exist in the database before proceeding.
4.Data Retrieval: The system applies all valid filters (such as name, SKU, or tags) to the database query.
5.Pagination: The system organizes the results into pages based on the requested page number and the number of rows per page.
6.Response: The system returns the filtered list of products to the user, or provides an appropriate error message if the request could not be completed.
1.3Key Concepts
–Filtering: The ability to narrow down the product list using specific attributes like status, SKU, name, brand, or product type.
–Pagination: A method of breaking down a large list of results into smaller, manageable chunks (pages) to improve system speed and user experience.
–Authorization: The security process that ensures only users with the correct access rights can view product information.
–Validation: The process of checking that the information sent in a request is accurate and follows the required format before the system attempts to process it.
1.4Business Value

This feature provides a robust and efficient way for users to manage their inventory data. By allowing precise filtering and pagination, it enables staff to quickly locate specific products without overwhelming the system. Furthermore, the built-in security and validation checks ensure that sensitive product data remains protected and that the system maintains high reliability and data integrity.

2.  DATA
2.1Overview

This feature provides a way to retrieve a list of products from the Lumi ERP system. Users can filter the product list by their current status (active or inactive) and apply additional criteria to narrow down the results. The system also supports pagination, allowing users to request specific "pages" of data to keep the information manageable.

2.2Step-by-Step Flow
1.Request Initiation: The user sends a request to view products, specifying whether they want "active" or "inactive" items.
2.Validation: The system checks if any provided identifiers (such as Brand ID, Type ID, or Tag IDs) actually exist in the database. If an ID is provided that does not exist, the request is rejected.
3.Filtering: The system applies the status filter and any optional search criteria provided by the user, such as partial matches for product names, SKUs, or specific category IDs.
4.Pagination: The system calculates which specific subset of data to return based on the requested page number and the number of rows per page.
5.Data Retrieval: The system gathers the matching records and returns them to the user.
2.3Key Concepts
–Status Filter: A mandatory requirement that ensures the user only sees products that are currently marked as either "active" or "inactive."
–Optional Search Criteria: Flexible filters that allow users to find products by partial names, codes, or specific attributes like brand, type, or tags.
–Pagination: A method of breaking a large list of results into smaller, manageable chunks (pages) to improve performance and readability.
–Reference Validation: A safety check that ensures any specific IDs provided in the search (like a Brand ID) are valid and exist in the system before attempting to search for them.
2.4Business Value

This feature enables efficient product management by allowing staff to quickly locate specific items without having to browse the entire database. By supporting both active and inactive status filtering, it helps teams maintain clean inventory records and easily audit discontinued or archived products. The inclusion of pagination ensures that the system remains fast and responsive, even as the product catalog grows over time.
