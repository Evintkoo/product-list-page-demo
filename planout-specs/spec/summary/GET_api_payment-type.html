1.  Logic
1.1Overview

The "Get Payment Types" feature provides a way for the system to retrieve a list of all payment methods available to a specific company (such as cash, card, or vouchers). This list is used by the payment panel to display the correct options to users during a sale. The feature is designed to be secure, automatically scoping results to the logged-in user's company, and includes tools to help manage large lists of payment types efficiently.

1.2Step-by-Step Flow
1.Request Initiation: The system receives a request to fetch payment types. It automatically identifies the company associated with the logged-in user to ensure data privacy.
2.Parameter Processing: The system checks for any optional filters (such as whether to show only active payment types or specific categories like "card" or "cash") and pagination settings (how many items to show and where to start in the list).
3.Data Retrieval: The system searches the database for all payment types belonging to that company, applying any requested filters.
4.Sorting and Pagination: The results are automatically sorted alphabetically by name. The system then calculates the total number of available items and prepares the specific "page" of results requested.
5.Response: The system returns the list of payment types along with the total count of items found. If the request is invalid or the user is not authorized, the system returns an appropriate error message.
1.3Key Concepts
–Filtering: The ability to narrow down the list of payment types based on their status (active vs. inactive) or their specific category (e.g., cash, card, or voucher).
–Pagination: A method used to break a large list of data into smaller, manageable chunks (pages) to improve performance and readability.
–Scoping: A security measure that ensures users can only see payment types that belong to their own company, preventing access to data from other organizations.
–Metadata: Additional information provided with the list, specifically the "total count," which helps the user interface know how many pages of data are available.
1.4Business Value

This feature ensures that the payment panel is always populated with accurate, relevant, and company-specific payment options. By supporting filtering and pagination, the system remains fast and responsive even as a company grows and adds more payment methods. This creates a seamless and reliable checkout experience for staff, reducing errors and ensuring that only valid, active payment methods are presented during a transaction.

2.  Data
2.1Overview

The `GET /api/payment-types` feature provides a secure way for the system to retrieve a list of payment methods (such as cash, card, or vouchers) configured for a specific company. This list is used by the payment panel to determine which options are available to a customer during a sale. The API automatically identifies the user's company based on their login session, ensuring that businesses only see their own configured payment types.

2.2Step-by-Step Flow
1.Authentication Check: The system verifies the user's session to identify which company is making the request.
2.Parameter Validation: The system checks the request for any pagination settings (limit and offset). If these numbers are negative, the request is rejected.
3.Data Filtering: The system applies optional filters provided by the user, such as whether to show only "active" payment types or to filter by a specific "kind" (e.g., only "card" payments).
4.Sorting: The system organizes the resulting list alphabetically by name.
5.Pagination: The system calculates the total number of available records and retrieves only the specific "page" of results requested.
6.Response: The system returns the filtered, sorted, and paginated list of payment types along with metadata (total count and current page information) to the user.
2.3Key Concepts
–Company Context: The API automatically scopes data to the authenticated user's organization, removing the need for the user to manually specify their company ID.
–Pagination: A method of breaking large lists into smaller, manageable chunks using a "limit" (how many items to show) and an "offset" (where to start in the list).
–Filtering: The ability to narrow down the results based on specific criteria, such as status (active/inactive) or payment category (cash, card, etc.).
–Metadata: Additional information returned with the data, such as the total number of records found, which helps the front-end interface display navigation controls correctly.
2.4Business Value

This feature ensures that the payment interface is always accurate, performant, and secure. By automatically scoping data to the company, it prevents data leakage between different organizations. The inclusion of filtering and pagination ensures that even companies with a large number of payment methods can load the payment panel quickly and navigate through their options efficiently.
