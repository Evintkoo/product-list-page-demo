1.  Frontend
1.1Overview

The Purchase Return feature provides a centralized dashboard for managing inventory returns and claims sent to suppliers. This screen allows users to view a list of all standard purchase returns, filter them by specific criteria (such as status, date range, or supplier), and navigate to detailed records for further action.

1.2Step-by-Step Flow
1.Authentication Check: Upon loading the page, the system verifies the user's login status. If not logged in, the user is redirected to the login page.
2.Initial Data Load: Once authenticated, the system automatically retrieves and displays all standard purchase returns.
3.Filtering: Users can narrow down the list using various criteria, including document number, return type (Return or Claim), date ranges, warehouse, supplier, and workflow status (e.g., Draft, Approved).
4.Applying Search: After setting the desired filters, the user clicks the search button to refresh the list with the relevant records.
5.Sorting: Users can click any column header to sort the data in ascending or descending order.
6.Navigation: Users can click on a specific Document Number to view the full details of that individual return.
7.Pagination: The system displays records in groups of 20, allowing users to navigate through multiple pages of results.
1.3Key Concepts
–Return vs. Claim: Two distinct categories for inventory adjustments; "Returns" typically involve sending physical goods back, while "Claims" may relate to discrepancies or quality issues.
–Workflow State: The current lifecycle stage of a return, which tracks progress from an initial "Draft" through to "Sent," "Approved," or "Cancelled."
–Filter Bar: A set of controls that allows users to isolate specific records without needing to search through the entire database manually.
–Document Number: A unique, system-generated identifier for every return, used as the primary reference for tracking and auditing.
1.4Business Value

This feature streamlines the inventory management process by providing clear visibility into the status of all outgoing returns. By enabling quick filtering and sorting, staff can efficiently track the progress of claims and returns, ensure that supplier interactions are documented, and maintain accurate inventory records. This reduces manual administrative effort and helps prevent errors in the return-to-supplier workflow.

2.  Logic
2.1Overview

The Purchase Return feature provides a centralized view for managing inventory returns to suppliers. It allows users to view, search, and filter purchase return records within the Lumi ERP system. The system ensures that only authorized users can access this information and provides a clean, organized table to track the lifecycle of each return—from creation to final approval.

2.2Step-by-Step Flow
1.Authentication Check: When you navigate to the page, the system automatically verifies your login status. If you are not logged in, you will be redirected to the login screen.
2.Initial Data Load: Once authenticated, the system automatically loads a list of standard purchase returns (excluding fixed assets) to display in the table.
3.Search and Filter: You can use the search controls to narrow down the list. You may filter by document number, return type, warehouse, supplier, or current status.
4.Apply Filters: When you click the search button, the system collects your criteria, ignores any empty fields, and refreshes the table to show only the records that match your specific request.
5.Data Display: The system maps the retrieved information into the table, showing key details such as the document number, dates (created, sent, and approved), warehouse and supplier names, and the current workflow status.
2.3Key Concepts
–Purchase Return: A record representing inventory being sent back to a supplier.
–Workflow State: The current stage of the return process (e.g., pending, sent, or approved), helping you track progress.
–Filter Criteria: Specific fields used to refine the list of returns, ensuring you only see the data relevant to your current task.
–Fixed Asset: A specific category of inventory that is excluded from the default view to keep the list focused on standard operational returns.
2.4Business Value

This feature streamlines inventory management by providing a clear, searchable overview of all supplier returns. By automating the data retrieval and filtering process, it reduces manual effort, minimizes errors in tracking return statuses, and ensures that warehouse and procurement teams have real-time visibility into the movement of goods back to suppliers.

3.  Data
3.1Overview

The Purchase Return feature provides a centralized view of all items being returned to suppliers. This functionality allows your team to track the lifecycle of a return—from the initial creation of the request to its final approval—ensuring that inventory adjustments and supplier communications are transparent and well-documented.

3.2Step-by-Step Flow
1.The system retrieves all purchase return records from the database, automatically sorting them by the most recently created entries first.
2.The system maps the internal database information into a clear, readable format for the user.
3.This information is then presented to the user, including key details such as the document reference number, the type of return, the warehouse involved, the supplier, and the current status of the request.
4.If the system successfully retrieves this data, it is displayed in the interface; if an error occurs, the system provides a notification that the list could not be loaded.
3.3Key Concepts
–Purchase Return: A formal record documenting items sent back to a supplier, typically due to defects, overstock, or incorrect shipments.
–Workflow State: The current stage of the return process, indicating whether the request is pending, sent, or fully approved.
–Reference Code: A unique identifier assigned to each return document to make searching and auditing easier.
–Warehouse Name: The specific storage location from which the returned goods are being dispatched.
3.4Business Value

This feature improves inventory accuracy and supplier accountability. By providing a clear, real-time overview of all returns, your team can quickly identify bottlenecks in the approval process, ensure that returned stock is properly accounted for, and maintain a reliable audit trail for all interactions with suppliers.
