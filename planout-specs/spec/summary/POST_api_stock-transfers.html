1.  Logic
1.1Overview

The Stock Transfer feature allows users to create a formal record of moving inventory between two locations within the Lumi ERP system. This process ensures that inventory movements are tracked accurately, validated for errors, and recorded in a "draft" state for further processing. The system is designed to be robust, preventing duplicate entries and ensuring that all data—from the transfer header to individual product lines—is saved reliably as a single, complete unit.

1.2Step-by-Step Flow
1.Duplicate Prevention: The system checks if a transfer with the same unique request ID has already been processed. If it has, the system returns the existing record instead of creating a duplicate.
2.Validation: The system verifies that the source and destination locations are different and that the list of items to be transferred is valid (e.g., quantities must be greater than zero).
3.Transaction Initiation: The system begins a secure process to save the transfer. If any part of this process fails, the entire operation is canceled to prevent incomplete or corrupted data.
4.Header Creation: A new transfer record is created in "draft" status. If a reference code is not provided, the system automatically generates one.
5.Snapshot and Calculation: For every product in the transfer, the system captures the current stock levels and average costs at that exact moment. It uses these "snapshots" to calculate the value of the transfer, ensuring the data is based on real-time system information rather than manual input.
6.Finalization: The system updates the transfer header with the total calculated value and saves the entire document.
7.Confirmation: Upon success, the system returns the details of the newly created transfer so the user can immediately view the document.
1.3Key Concepts
–Idempotency: A safety mechanism that ensures submitting the same request multiple times does not result in multiple transfers; it simply returns the original result.
–Transactional Processing: A "all-or-nothing" approach to saving data. If one part of the transfer fails, the entire record is discarded to ensure the database remains clean and accurate.
–Snapshotting: The act of recording the exact state of inventory and costs at the moment the transfer is created, providing an audit trail of what the system "saw" when the request was made.
–Draft State: The initial status of a new transfer, allowing for review or adjustments before the movement is finalized.
1.4Business Value
–Data Integrity: By automatically calculating totals and snapshotting stock levels, the system eliminates manual calculation errors and ensures that financial and inventory records are always based on verified system data.
–Operational Reliability: The "all-or-nothing" saving process prevents partial records, ensuring that users never have to deal with incomplete or "broken" transfer documents.
–Efficiency: The system handles administrative tasks—such as generating reference codes and preventing duplicate submissions—automatically, allowing staff to focus on managing inventory rather than managing system errors.
2.  Data
2.1Overview

This feature provides a reliable way to create stock transfer documents within the Lumi ERP system. It allows users to move inventory between locations while ensuring that all data—such as current stock levels, costs, and transfer totals—is captured accurately and consistently at the moment the transfer is created.

2.2Step-by-Step Flow
1.Duplicate Check: The system checks if the request has already been processed. If the same request is sent twice (e.g., due to a double-click), the system returns the original document instead of creating a duplicate.
2.Validation: The system verifies the request details. It ensures that the source and destination locations are different and that the list of items to be transferred is not empty.
3.Data Processing: The system begins a secure "all-or-nothing" operation to ensure data integrity.
4.Snapshotting: For every item in the transfer, the system automatically records the current stock levels at both the source and destination, as well as the current average cost of the product.
5.Calculation: The system calculates the total value of the transfer based on the recorded costs and quantities, rather than relying on values provided by the user.
6.Finalization: The transfer document is saved as a "draft," and the system returns the completed document details so the user can immediately view the record they just created.
2.3Key Concepts
–Idempotency: A safety mechanism that prevents the same action from being performed multiple times, ensuring that resubmitting a form does not create duplicate records.
–Snapshotting: The process of capturing a "frozen" view of data (like current stock levels or costs) at the exact moment the transfer is created, providing an accurate audit trail.
–Transactional Write: A technical safeguard that ensures the entire document—including the header and all individual items—is saved as a single unit. If any part of the process fails, nothing is saved, preventing incomplete or corrupted data.
–Draft State: The initial status of a new transfer, allowing for review before the movement of goods is finalized.
2.4Business Value
–Data Accuracy: By calculating totals and costs on the server side using real-time snapshots, the system eliminates errors caused by manual entry or outdated information.
–Reliability: The "all-or-nothing" saving process prevents partial data entries, ensuring that your inventory records remain clean and trustworthy.
–Efficiency: The system automatically handles reference codes and calculations, reducing the manual workload for users and speeding up the inventory management process.
–Error Prevention: Built-in validations prevent common mistakes, such as transferring items to the same location or submitting empty requests.
