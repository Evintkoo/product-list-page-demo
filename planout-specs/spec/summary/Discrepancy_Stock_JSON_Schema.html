1.  Data
1.1Overview

The "Discrepancy Stock" feature allows users to report and track inventory discrepancies at the store level. This system provides a structured way to document items that do not match expected stock levels, enabling better oversight and resolution of inventory issues. The feature includes both a list view for monitoring existing reports and a creation form for submitting new ones.

1.2Step-by-Step Flow
1.Submission: A user fills out a "Discrepancy Stock" form, selecting the store (entity) and adding one or more product lines, each with a counted quantity and optional notes.
2.Validation & Processing: The system receives the request, validates the data, and automatically assigns system-generated details like the document reference code, the current date, and the initial "draft" status.
3.Storage: The system saves the report header (the store and document info) and the individual product items into the database.
4.Retrieval: When viewing the "Store" tab, the system retrieves a list of these reports. It joins the report data with product and store information to provide a complete view.
5.Display: The system presents the data in a paginated list, allowing users to filter by date, product, document code, or status (e.g., draft, responded, or done).
1.3Key Concepts
–Discrepancy Stock: A formal record of a difference between recorded inventory and actual physical stock.
–Entity: The specific store location where the discrepancy was identified.
–Item-Level Reporting: Each report is broken down by individual product lines, meaning a single report can contain multiple products, each tracked as its own line item.
–Idempotency Token: A unique identifier included with the submission to prevent duplicate reports if a user accidentally clicks "submit" multiple times.
–AASM State: The workflow status of a report, which tracks its lifecycle from an initial "draft" to "responded" and finally "done."
–Pagination: A method of organizing large lists of reports into smaller, manageable pages (using limit and offset) to ensure the application remains fast and responsive.
1.4Business Value
–Improved Inventory Accuracy: By providing a standardized process for reporting discrepancies, the business can identify and address stock issues more quickly.
–Operational Transparency: The system maintains a clear audit trail of who created a report, when it was created, and its current status, ensuring accountability.
–Efficient Workflow: The automated generation of reference codes and status tracking reduces manual administrative work, allowing store staff to focus on resolving the actual inventory issues.
–Better Decision Making: With the ability to filter and search through historical discrepancy data, management can identify recurring stock issues at specific stores or with specific products.
2.  LOGIC
2.1Overview

The Discrepancy Stock feature allows users to record and track inventory differences at specific store locations. When a user identifies a mismatch between physical stock and system records, they can create a "Discrepancy Report." This report acts as a formal document that captures the details of the items involved, the store where the issue occurred, and any relevant notes. The system automatically generates a unique reference code for each report to ensure easy tracking and auditing.

2.2Step-by-Step Flow
1.Entity Selection: The user selects the relevant store from a list of active locations.
2.Product Search: The user searches for products to add to the report using a lookup tool that filters by SKU or product name.
3.Report Creation: The user submits the report, which includes the store ID, the list of products, the counted quantities, and any optional notes.
4.Automatic Numbering: Upon submission, the system automatically generates a unique document reference code (e.g., DISC/STORE-CODE/SEQUENCE) to identify the report.
5.Data Validation & Storage: The system saves the report header and all individual product lines in a single transaction, ensuring that the data is consistent and complete.
6.Review: Users can view a list of all discrepancy reports or drill down into the details of a specific report to see its current status and history.
2.3Key Concepts
–Discrepancy Report: A digital record used to document inventory mismatches at a store.
–Reference Code: A unique, system-generated identifier for each report, formatted to include the store code and a sequential number.
–Idempotency Token: A safety mechanism that prevents the system from creating duplicate reports if a user accidentally clicks the "submit" button multiple times.
–Draft Status: The initial state of a newly created report, indicating it is ready for review or further action.
–Product Lookup: A search tool that helps users quickly find and select the correct items to include in their discrepancy report.
2.4Business Value
–Improved Inventory Accuracy: Provides a structured way to identify and document stock discrepancies, leading to better inventory management.
–Operational Accountability: By tracking who created or updated a report and assigning a unique reference code, the business maintains a clear audit trail for all stock adjustments.
–Efficiency: The automated numbering system and product lookup tool reduce manual data entry errors and speed up the reporting process for store staff.
–Data Integrity: The use of transactional saving ensures that reports are never partially saved, preventing incomplete or corrupted data from entering the system.
