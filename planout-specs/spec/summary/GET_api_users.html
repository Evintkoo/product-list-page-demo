1.  Logic
1.1Overview

This feature provides administrators with a secure way to view a list of all users registered in the Lumi ERP system. To ensure the most relevant information is prioritized, the list is automatically sorted to display the newest users at the top. Access to this information is strictly limited to authorized administrators to maintain data security.

1.2Step-by-Step Flow
1.Identity Verification: The system checks if the person requesting the list is logged in. If they are not, the request is denied.
2.Permission Check: The system verifies that the logged-in user holds an "admin" role. If the user does not have administrative privileges, the request is blocked.
3.Data Retrieval: Once authorized, the system fetches the user directory from the database, automatically organizing the records so that the most recently created accounts appear first.
4.Display: The system presents the requested user information, including their unique ID, email address, role, account creation date, and full name.
1.3Key Concepts
–Authentication: The process of confirming the identity of the user to ensure they are logged into the system.
–Authorization: The process of verifying that the logged-in user has the specific "admin" permissions required to view sensitive user data.
–Descending Order: A sorting method used here to ensure that the "newest" users are always listed at the top of the results.
–User Directory: The collection of account details (such as names and roles) that administrators need to manage the system effectively.
1.4Business Value

This feature empowers administrators to efficiently monitor system growth and manage user accounts. By prioritizing the newest users, administrators can quickly identify and verify recent sign-ups or troubleshoot onboarding issues without having to manually search through the entire database. Furthermore, by enforcing strict role-based access, the feature ensures that sensitive user information remains protected and accessible only to those responsible for system administration.

2.  Data
2.1Overview

This feature provides administrators with a secure way to view a list of all users registered in the Lumi ERP system. To ensure the list is easy to manage, the results are automatically sorted so that the most recently created accounts appear first. The system also includes built-in safeguards to ensure that only authorized administrators can access this sensitive information.

2.2Step-by-Step Flow
1.Authorization Check: When a request is made, the system first verifies that the person making the request holds an "admin" role. If they do not, the request is blocked.
2.Parameter Setup: The system checks for specific display preferences (such as how many users to show at once). If no preferences are provided, it defaults to showing 20 users starting from the most recent.
3.Data Retrieval: The system queries the database to pull the user information, ensuring the list is ordered by the creation date in descending order (newest first).
4.Response Delivery: The system returns the requested list of users along with a summary of the display settings used (the limit and offset) to confirm the data provided.
2.3Key Concepts
–Admin Authorization: A security gate that restricts access to the user list, ensuring only verified administrators can view the data.
–Pagination: A method of breaking a large list of users into smaller, manageable chunks, controlled by "limit" (how many to show) and "offset" (where to start in the list).
–Chronological Sorting: The automatic organization of data based on the time of creation, ensuring the newest users are always at the top of the list.
2.4Business Value

This feature empowers administrators to efficiently oversee the user base within the Lumi ERP. By providing a sorted, paginated view, administrators can quickly identify new account registrations and manage user access without having to manually search through the entire database. The strict authorization layer ensures that sensitive user information remains protected and compliant with internal security policies.
