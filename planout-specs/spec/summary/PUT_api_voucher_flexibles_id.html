1.  Logic
1.1Overview

This feature allows authorized users to update the details of an existing "flexible voucher" within the Lumi ERP system. By providing a specific voucher ID and the updated information (such as the name, description, value, or SKU), users can keep their voucher records accurate and up-to-date.

1.2Step-by-Step Flow
1.Security Check: The system verifies that the user is logged in and possesses the necessary "write" permissions to modify voucher data.
2.Request Processing: The system identifies the specific voucher to be updated using the ID provided in the web address.
3.Validation: The system checks that the information provided in the request is properly formatted and complete.
4.Uniqueness Check: If the user is changing the voucher's SKU, the system ensures that the new SKU is not already being used by another voucher to prevent duplicates.
5.Update: If all checks pass, the system updates the voucher record with the new details and records the time of the update.
6.Confirmation: The system returns the updated voucher information to the user to confirm the changes were successful.
1.3Key Concepts
–Flexible Voucher: A customizable voucher type within the ERP that can be modified to suit changing business needs.
–SKU (Stock Keeping Unit): A unique identifier for the voucher; the system enforces that no two vouchers share the same SKU.
–Authentication: The process of verifying that the person making the request is a recognized user of the system.
–Authorization: The process of ensuring the verified user has the specific "write" permission required to perform updates.
–Validation: A safety check to ensure that the data provided (like names or values) meets the system's required format and rules.
1.4Business Value

This feature provides operational flexibility by allowing administrators to correct or adjust voucher details as business requirements evolve. By enforcing strict validation and uniqueness checks, the system maintains data integrity, ensuring that voucher records remain reliable, organized, and free of conflicting information.

2.  Data
2.1Overview

This feature allows authorized users to update the details of an existing "flexible voucher" within the Lumi ERP system. By providing a unique identifier for the voucher and the updated information, users can modify attributes such as the voucher's name, description, value, and SKU (Stock Keeping Unit). The system includes built-in safeguards to ensure data integrity, such as verifying that the voucher exists before attempting an update and preventing duplicate SKU assignments.

2.2Step-by-Step Flow
1.Authentication and Authorization Check: The system verifies that the user is logged in and possesses the necessary permissions to modify voucher records.
2.Voucher Verification: The system checks if a voucher matching the provided unique identifier exists in the database. If it cannot be found, the request is rejected.
3.Conflict Detection: The system checks the provided SKU against all other existing vouchers. If another voucher is already using that SKU, the update is blocked to prevent data conflicts.
4.Data Validation: The system ensures the provided information meets all required formatting and field rules.
5.Record Update: Once all checks pass, the system updates the voucher record with the new information and records the current date and time as the last modification timestamp.
6.Confirmation: The system returns the updated voucher details to the user to confirm the changes were successful.
2.3Key Concepts
–Flexible Voucher: A specific type of voucher entity within the ERP that contains details like a name, description, monetary value, and a unique SKU.
–SKU (Stock Keeping Unit): A unique identifier used to track specific items; the system enforces that no two vouchers can share the same SKU.
–Unique Identifier (ID): A permanent, system-generated reference used to pinpoint the exact voucher record that needs to be updated.
–Data Integrity: The process of ensuring that updates do not create errors, such as duplicate identifiers or invalid data entries.
2.4Business Value

This feature provides administrative flexibility, allowing the business to adjust voucher details (such as value or descriptions) as marketing strategies or financial requirements evolve. By enforcing strict validation and conflict checks, the system prevents human error and ensures that voucher data remains accurate and reliable for reporting and financial tracking purposes.
