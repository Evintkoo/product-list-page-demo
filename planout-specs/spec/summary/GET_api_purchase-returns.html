1.  Logic
1.1Overview

This feature provides a way for authorized users to retrieve a list of purchase returns within the Lumi ERP system. It is designed to be flexible, allowing users to search through their return records using specific filters, sorting preferences, and pagination to manage large volumes of data efficiently. The system automatically ensures that users only see data belonging to their own company based on their active login session.

1.2Step-by-Step Flow
1.Security Check: The system verifies that the user is logged in and has the necessary permissions to view purchase return records.
2.Parameter Processing: The system collects your search criteria (such as the specific warehouse, return type, or asset category) and your display preferences (such as how many items to show per page and how to sort the list). If no preferences are provided, it defaults to showing the most recently created returns first.
3.Data Retrieval: The system searches the database for records that match your criteria, ensuring the results are restricted to your company’s data.
4.Delivery: The system returns the requested list of purchase returns. If no records match your search, it will return an empty list rather than an error.
1.3Key Concepts
–Pagination: A method of breaking a large list of records into smaller, manageable "pages" to improve performance and readability.
–Filtering: The ability to narrow down the list of returns based on specific criteria, such as whether an item is a fixed asset, the type of return, or the warehouse location.
–Sorting: The ability to organize the list by specific fields (like date) in either ascending or descending order.
–Session-Based Scoping: A security feature that automatically identifies which company the user belongs to, ensuring they can only access their own company's data without needing to manually specify a company ID.
1.4Business Value

This feature empowers staff to quickly audit and manage return history without manual data entry or complex database queries. By providing robust filtering and sorting, users can instantly locate specific return transactions—such as identifying all returns from a particular warehouse or isolating fixed asset returns—which streamlines inventory reconciliation and improves financial reporting accuracy.

2.  Data
2.1Overview

The Purchase Returns feature provides a centralized way to view and track items that have been sent back to vendors. This tool allows your team to retrieve a list of all return transactions, filter them by their current status or specific date ranges, and see the underlying details of what was returned and which original purchase orders were affected.

2.2Step-by-Step Flow
1.Filter and Search: The system receives your request to view returns, applying any filters you have selected, such as the return status (e.g., "Pending" or "Completed") or a specific timeframe.
2.Retrieve Return Records: The system gathers the relevant return records from the database, automatically sorting them so that the most recent returns appear at the top of your list.
3.Fetch Item Details: For the returns found, the system looks up the specific items included in those returns, such as the quantity and price of the products being sent back.
4.Link to Original Orders: The system identifies the original purchase orders associated with these returns and retrieves the order numbers, ensuring you have the necessary context to cross-reference the return with the initial purchase.
5.Consolidate Data: The system combines all this information into a clear, comprehensive view for you to review.
2.3Key Concepts
–Purchase Return: A record of goods sent back to a vendor, including the date of the return, the total value, and the current processing status.
–Return Items: The specific breakdown of products within a return, detailing exactly what was sent back and at what cost.
–Purchase Order Context: The link between a return and the original purchase, allowing you to see the specific order number that triggered the return process.
–Filtering: The ability to narrow down your view by date or status, helping you focus on specific batches of returns rather than searching through the entire history.
2.4Business Value

This feature improves inventory accuracy and financial transparency by providing a clear audit trail of all vendor returns. By linking returns directly to original purchase orders, your team can quickly resolve discrepancies, track vendor performance, and ensure that financial records—such as credits or refunds—are correctly aligned with the physical movement of inventory.
