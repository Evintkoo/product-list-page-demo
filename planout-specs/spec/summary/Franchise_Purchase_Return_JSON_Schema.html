1.  Data
1.1Overview

The Franchise Purchase Return feature allows stores to formally return items to a supplier based on a previous purchase order. This process ensures that returns are tracked accurately, preventing stores from returning more items than they originally received or more than they currently have in stock. The system automatically handles the creation of the return document and validates all quantities against real-time inventory data to maintain accuracy.

1.2Step-by-Step Flow
1.Validation: The system checks the request to ensure the return is valid. It verifies that the purchase order exists, belongs to the correct company, and matches the store and supplier involved.
2.Quantity Verification: The system calculates the maximum returnable quantity for each item by looking at the original order and subtracting any items already returned. It also confirms the store currently has enough stock on hand to fulfill the return.
3.Header Creation: Once validated, the system creates a "Draft" return document. It automatically generates a unique reference code for the document; this cannot be manually overridden by the user.
4.Item Processing: The system records each item being returned, linking it to the original purchase order line. It automatically pulls in necessary details like the original supply price and current stock levels.
5.Finalization: The system returns the complete, newly created document to the user. If any part of this process fails (e.g., a validation error), the entire operation is cancelled to ensure no partial or incorrect data is saved.
1.3Key Concepts
–Source Order: The original purchase order that serves as the basis for the return. The system uses this to track what was originally received.
–Return Cap: A calculated limit that prevents a store from returning more items than were originally received on a specific order line.
–Draft State: The initial status of a new return, indicating it has been created but not yet processed or approved.
–Transaction: A safety mechanism that ensures all steps of the return (validation, header creation, and item recording) happen together. If one step fails, the entire return is discarded to prevent data errors.
–Snapshot Data: Information (such as prices or quantities) captured at the exact moment the return is created, ensuring the record remains accurate even if inventory levels change later.
1.4Business Value
–Prevents Over-Returning: By automatically calculating return caps, the system eliminates the risk of human error or fraud regarding return quantities.
–Data Integrity: Because the system generates document numbers and pulls pricing/stock data directly from the database, it ensures that return records are consistent and reliable for accounting and inventory audits.
–Operational Efficiency: The automated validation process reduces the need for manual checks, allowing staff to process returns quickly while maintaining strict adherence to business rules.
