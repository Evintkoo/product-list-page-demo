1.  Logic
1.1Overview

This feature provides a streamlined way to update the status of a sales delivery within the Lumi ERP system. It allows users to mark a delivery as either "delivered" or "voided." This action is designed to be simple and direct, acting as a final confirmation step to ensure that delivery records accurately reflect their current progress in the supply chain.

1.2Step-by-Step Flow
1.Validation: The system checks that the requested status is either "delivered" or "voided." If an incorrect status is provided, the request is rejected.
2.Security Lock: The system locks the specific delivery record to ensure that no other processes can modify it while the update is in progress.
3.Verification: The system confirms the delivery exists and verifies that it is currently in a "draft" state. If the delivery has already been processed or is missing, the request is rejected.
4.Status Update: The system updates the delivery status to the requested value.
5.Automatic Order Completion: If the status is set to "delivered," the system automatically updates the associated sales order to "completed" and marks it as closed. If the status is "voided," the sales order remains unchanged.
6.Confirmation: The system returns a success message confirming the new status of the delivery.
1.3Key Concepts
–Workflow State: The current stage of a document (e.g., "draft" or "completed"). This ensures that users only perform actions that are appropriate for the current phase of the delivery.
–Database Transaction: A safety mechanism that ensures all related updates (like updating both the delivery and the parent sales order) happen together. If any part of the process fails, the entire action is canceled to prevent data errors.
–Locking: A protective measure that prevents two users from trying to change the same record at the exact same time, which helps maintain data integrity.
1.4Business Value
–Operational Efficiency: Automates the closing of sales orders once a delivery is marked as "delivered," reducing the manual administrative burden on staff.
–Data Accuracy: By restricting status changes to "draft" items only, the system prevents accidental or unauthorized changes to deliveries that have already been finalized.
–Consistency: Ensures that the status of a sales order always stays in sync with its corresponding delivery, providing a reliable view of business operations for reporting and inventory management.
2.  Data
2.1Overview

This feature provides a reliable way to update the status of a sales delivery within the Lumi ERP system. It allows authorized users to mark a delivery as either "delivered" or "voided." The system ensures that these updates are processed safely, preventing conflicting changes and automatically updating the status of the parent sales order when a delivery is successfully completed.

2.2Step-by-Step Flow
1.Request Initiation: The system receives a request to update a specific delivery to a new status ("delivered" or "voided").
2.Validation: The system checks that the requested status is valid and that the delivery record exists.
3.Locking: The system locks the specific delivery record to ensure no other processes can modify it while the update is in progress.
4.State Check: The system verifies that the delivery is currently in a "draft" state. If it is not, the update is rejected to prevent accidental changes to finalized deliveries.
5.Status Update: The delivery status is updated to the new value.
6.Parent Order Sync (Conditional): If the status is set to "delivered," the system automatically checks the parent sales order. It recalculates the order's overall status and determines if the order should be marked as "closed" based on the completion of all associated deliveries.
7.Completion: The system confirms the update is successful and returns the updated delivery information.
2.3Key Concepts
–Workflow State: The current stage of a delivery or order (e.g., "draft," "delivered").
–Transaction: A safety mechanism that ensures all related updates (like updating a delivery and its parent order) happen together successfully or not at all, preventing data inconsistencies.
–Locking: A protective measure that prevents two users from trying to change the same record at the exact same time.
–Draft State: A required starting point for a delivery; the system only allows status changes if the delivery is currently in this initial state.
2.4Business Value
–Data Integrity: By using automated status synchronization, the system ensures that sales orders always accurately reflect the progress of their deliveries without manual intervention.
–Error Prevention: The "draft" state requirement prevents users from accidentally modifying or voiding deliveries that have already been processed.
–Operational Efficiency: Automating the "closed" status for sales orders reduces the administrative burden on staff, ensuring that completed orders are correctly categorized in the system immediately upon delivery.
