1.  Logic
1.1Overview

This feature provides a dedicated way to manage specific "behavioral settings" for individual products within the Mini ERP system. Instead of bundling these settings with general product information, this feature uses a focused set of controls—such as serial number requirements, batch tracking, and consignment status—to dictate how the system handles a specific product during daily operations.

1.2Step-by-Step Flow
1.Retrieving Settings: When you request the settings for a specific product, the system fetches the current status of nine key behavioral flags (e.g., whether the product requires serial numbers or batch tracking).
2.Updating Settings: When you submit changes to these settings, the system first verifies that your company has the necessary permissions to modify these features.
3.Validation: The system performs a series of safety checks to ensure the new settings are compatible with the product's current state. For example, it checks if a product already has existing transactions or stock before allowing you to toggle features like serial number tracking or consignment status.
4.Error Reporting: If any requested changes conflict with the product's history or current configuration, the system will reject the update and provide a list of specific reasons why the change is not allowed.
5.Saving and Syncing: If all validations pass, the system saves the new settings and automatically updates any related data links (such as consignor information) to ensure everything remains in sync.
1.3Key Concepts
–Feature Flags: Specific "on/off" switches that determine how the system treats a product (e.g., "require_serial" forces the system to ask for a serial number during a sale).
–Validation Logic: A safety mechanism that prevents users from changing product settings if that change would break existing data or violate business rules (e.g., you cannot turn on batch tracking if the product doesn't have batch number fields configured).
–Consignment Settings: Specialized flags that manage how products held on behalf of others are tracked, ensuring that consignor details and stock levels are correctly accounted for.
–System Syncing: An automated background process that ensures that when a setting is changed, all related records in the system are updated to match the new configuration.
1.4Business Value

This feature allows businesses to tailor the ERP system to the unique needs of different products without requiring custom development. By providing strict validation, it protects the integrity of your inventory data—preventing users from accidentally enabling settings that would conflict with existing sales history or stock records. This ensures that your operational workflows remain consistent and accurate as your product catalog grows.

2.  Data
2.1Overview

This feature provides a way to retrieve the specific behavioral settings for any given product in the system. These settings act as "feature flags" that determine how the system handles a product—for example, whether it requires a serial number, if it is part of a consignment, or if it is subject to taxes. By accessing this information, the system can ensure that each product behaves according to its unique configuration.

2.2Step-by-Step Flow
1.The system receives a request to view the settings for a specific product.
2.The system searches the database for a saved configuration associated with that product.
3.If a configuration is found, the system returns those specific settings.
4.If no configuration has been set for that product yet, the system automatically provides a default set of settings where all options are turned off (set to "false").
2.3Key Concepts
–Feature Flags: On/off switches that control specific product behaviors, such as tracking batches or enabling multiple pricing tiers.
–Default State: A safety mechanism that ensures the system remains functional even if a product hasn't been explicitly configured yet.
–Product Settings: A collection of rules that define how the ERP system should process a specific item during daily operations.
2.4Business Value

This feature allows for granular control over product management. By centralizing these settings, the business can easily toggle specific requirements (like tax applicability or serial number tracking) on a per-product basis. This flexibility ensures that the ERP system can adapt to different types of inventory—such as consignment goods versus standard retail items—without requiring custom code changes for every new product type.
