1.  Data
1.1Overview

The "Franchise Purchase Order Create" feature allows the system to process and record new purchase orders for franchises. This feature ensures that all order details—such as the source warehouse, destination store, supplier, and specific product quantities—are thoroughly validated before being saved. By using a structured, automated process, the system ensures data integrity and prevents errors like duplicate items or invalid product requests.

1.2Step-by-Step Flow
1.Validation: The system checks the incoming request to ensure the order type (internal or external) is valid and that all referenced entities (Supplier, Warehouse, Store, and Products) exist, are active, and belong to the correct company. It also verifies that product quantities are positive and that no duplicate products are included.
2.Header Creation: Once validated, the system creates the main "Stock Order" record, which acts as the header for the order. This includes generating a unique reference code and setting the initial status to "draft."
3.Item Processing: The system adds the individual products to the order. During this step, it captures "snapshots" of current data, such as the warehouse's average cost and the product's supply price, ensuring these values remain accurate to the time of the order.
4.Total Calculation: The system automatically calculates the total order amount based on the items added.
5.Workflow Initialization: An initial record is created in the workflow history to track the order's lifecycle, starting it in the "draft" state.
6.Confirmation: The system returns the fully created order details to the user, confirming that the entire process was successful.
1.3Key Concepts
–Transaction: A safety mechanism that ensures all steps of the order creation succeed together. If any part of the process fails (e.g., a product is invalid), the entire operation is canceled to prevent incomplete or corrupt data.
–Idempotency Token: A unique identifier (request ID) used to ensure that the same order is not accidentally created twice if a request is sent multiple times.
–Snapshot: A record of data (like product prices or stock levels) taken at the exact moment the order is created, which remains unchanged even if those values are updated in the system later.
–Workflow State: The current status of the order (e.g., "draft"), which helps manage the order's progress through the system.
1.4Business Value
–Data Accuracy: By validating all inputs against existing records (Suppliers, Warehouses, Stores) before saving, the system prevents common data entry errors.
–Operational Efficiency: Automating the calculation of order totals and the creation of workflow history reduces manual work and ensures consistency across all franchise orders.
–Auditability: Every order is linked to a specific user and company, and the workflow history provides a clear, append-only record of the order's status, which is essential for tracking and reporting.
–Reliability: The use of transaction-based processing ensures that the system never ends up in a "half-finished" state, providing peace of mind that every order is either fully recorded or not recorded at all.
