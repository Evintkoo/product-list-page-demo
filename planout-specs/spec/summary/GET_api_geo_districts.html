1.  Logic
1.1Overview

This feature provides a way for the system to retrieve a list of districts based on a selected regency or municipality. It is designed to power "cascading dropdowns," where selecting a higher-level geographic area (the regency) automatically updates the available options in the district dropdown menu.

1.2Step-by-Step Flow
1.Authentication Check: The system verifies that the user is logged in and has an active session. If not, the request is rejected.
2.Validation: The system checks that a valid regency identifier has been provided. If the identifier is missing or formatted incorrectly, the request is rejected.
3.Data Retrieval: The system searches the database for all active districts associated with the provided regency identifier.
4.Sorting and Formatting: The retrieved list of districts is sorted alphabetically by name and formatted into a simple list of IDs and names, which is then sent back to the user.
1.3Key Concepts
–Cascading Dropdown: A user interface pattern where the options in one menu change based on the selection made in a previous menu (e.g., selecting a city updates the list of available districts).
–Regency ID: A unique reference code used to identify a specific regency or municipality, ensuring the system fetches the correct districts for that area.
–Active Status: The system only returns districts that are currently marked as "active," ensuring that users do not see outdated or discontinued locations.
1.4Business Value

This feature improves data accuracy and user experience by automating geographic selections. By ensuring that users only see relevant, active districts for their chosen regency, it reduces manual data entry errors and streamlines the process of filling out forms or setting up location-based configurations within the Lumi ERP system.

2.  Data
2.1Overview

This feature provides a way for the system to retrieve a list of districts to populate dropdown menus. When a user selects a specific regency (or municipality), the system will automatically fetch the relevant districts associated with that area. This ensures that users are only presented with accurate, active, and relevant location options.

2.2Step-by-Step Flow
1.Request Validation: The system receives a request containing a specific regency identifier. It first checks to ensure this identifier is formatted correctly. If the format is invalid, the request is rejected.
2.Data Filtering: The system searches the database for all districts linked to the provided regency. It automatically filters out any districts that are marked as inactive.
3.Sorting: The resulting list of districts is organized alphabetically by name to make it easier for users to find what they need.
4.Data Delivery: The system returns a clean list containing only the necessary information—the unique ID and the name of each district—to be displayed in the dropdown menu.
2.3Key Concepts
–Regency: A regional administrative division; in this context, it acts as the "parent" category used to filter which districts appear in the list.
–Active Status: A safety filter that ensures only currently valid or "live" districts are shown to the user, hiding any that have been retired or disabled.
–Cascading Filter: A design pattern where the options in one dropdown (Districts) are automatically updated based on the selection made in a previous dropdown (Regency).
2.4Business Value

This feature improves data accuracy and user experience by preventing users from selecting outdated or irrelevant locations. By automating the district list based on the selected regency, it reduces manual data entry errors and streamlines the address-selection process within the ERP system.
