1.  Logic
1.1Overview

This feature provides a secure way to retrieve comprehensive details for a specific customer within the Lumi ERP system. By using a unique customer identifier, the system fetches a complete profile, including contact information, store details, tax data, and internal reporting settings. The system is designed to automatically handle different customer types—such as retail, wholesale, or franchise—ensuring the correct information is returned based on the customer's specific classification.

1.2Step-by-Step Flow
1.Request Initiation: A request is made to retrieve a customer's profile using their unique ID.
2.Validation: The system checks that the provided ID is in the correct format and verifies that the person making the request is properly logged in.
3.Data Retrieval: The system searches the database for the customer record matching the provided ID.
4.Profile Assembly: Once found, the system gathers all relevant data, including core information, addresses, tax details, and audit logs.
5.Response:

* If successful, the system returns the full customer profile.

* If the ID is invalid, the user is not logged in, or the customer cannot be found, the system returns a specific error message explaining the issue.

1.3Key Concepts
–Unique Identifier: A specific code assigned to every customer that ensures the system retrieves the correct record.
–Discriminator Flags: Internal markers used to categorize a customer (e.g., Retail, Wholesale, or Franchise) so the system knows how to process their specific business requirements.
–Audit Fields: A record of tracking information that shows when and how a customer profile was created or modified, ensuring data transparency.
–Error Handling: Standardized responses that inform the user if a request failed due to a bad ID, lack of permission, or a system-wide issue.
1.4Business Value

This feature streamlines operations by providing a single, reliable source for customer data. By centralizing information like tax settings, SAP reporting values, and store details, it reduces the time staff spend manually searching for customer records. Furthermore, the built-in security and validation checks ensure that sensitive customer data is only accessed by authorized users, maintaining the integrity and privacy of the ERP system.

2.  Data
2.1Overview

This feature provides a way to retrieve detailed information for a specific customer using their unique ID. Because our system handles different types of business relationships—specifically Retail, Wholesale, and Franchise customers—the system automatically detects the customer's type and presents the data in the format most relevant to that business model.

2.2Step-by-Step Flow
1.Request: The system receives a request for a specific customer using their unique ID.
2.Lookup: The system searches the database for a record matching that ID. If no record is found, it returns a "Not Found" error.
3.Classification: Once the record is retrieved, the system checks internal flags to determine if the customer is a Wholesale, Franchise, or standard Retail customer.
4.Formatting: Based on the classification, the system organizes the customer's data (such as contact info, tax details, and store settings) into the specific format required for that customer type.
5.Response: The system returns the formatted customer details to the user. If any errors occur during this process (such as invalid input or server issues), the system provides the appropriate error notification.
2.3Key Concepts
–Customer ID: A unique identifier used to locate a specific customer record in the database.
–Discriminator Flags: Internal markers (Wholesale, Franchise, or Consignment) used by the system to distinguish between different business types.
–Schema: The specific structure or "template" used to present data; this ensures that a Wholesale customer sees data relevant to their account, while a Retail customer sees their own specific set of information.
–Error Handling: Standardized responses provided by the system when a request cannot be completed, such as when a customer ID does not exist or the user is not authorized.
2.4Business Value

This feature ensures that our API is flexible and accurate. By automatically identifying the customer type and applying the correct data format, we reduce the risk of displaying irrelevant information to users. This creates a cleaner, more reliable experience for our partners and internal teams who rely on this data for reporting, tax compliance, and store management.
